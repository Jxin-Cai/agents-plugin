# 视觉审计原则

本文档定义了视觉审计阶段必须遵循的原则。用这些原则评估界面的视觉可用性。

---

## 1. Nielsen 启发式评估方法

Jakob Nielsen 的启发式评估是最广泛使用的可用性检查方法。核心要点：

### 评估流程（标准作业程序）
- **第一阶段：规划** — 明确评估范围（整个产品 vs 特定流程），准备评估模板和严重程度量表
- **第二阶段：独立评估** — 逐项检查界面是否违反启发式，记录问题位置和描述
- **第三阶段：汇总** — 合并发现，去重，按严重程度排序
- **第四阶段：改进** — 按优先级修复，后续迭代中复验

### 严重程度四级量表
| 等级 | 含义 | 行动建议 |
|------|------|----------|
| 0 | 不是可用性问题 | 无需行动 |
| 1 | 装饰性问题 | 排期低优先级修复 |
| 2 | 轻微可用性问题 | 排入下一迭代修复 |
| 3 | 严重可用性问题 | 高优先级修复 |
| 4 | 可用性灾难 | 上线前必须修复 |

### 十大启发式检查清单

**H1 - 系统状态可见性**
- 是否有加载指示器（骨架屏/Spinner/进度条）？
- 操作成功/失败是否有即时反馈？
- 当前所在位置是否清晰（面包屑/高亮导航）？
- 长时间操作是否有进度提示？

**H2 - 系统与真实世界的匹配**
- 术语是否使用用户语言而非技术术语？
- 图标隐喻是否符合现实世界认知？
- 信息排列顺序是否符合用户的心智模型？
- 日期/货币格式是否符合本地化习惯？

**H3 - 用户控制与自由**
- 是否有明显的"返回""取消""关闭"操作？
- 误操作是否可以撤销（Undo）？
- 多步流程是否支持返回上一步？
- 是否有"紧急出口"避免用户陷入死胡同？

**H4 - 一致性与标准**
- 同类操作在不同页面是否表现一致？
- 是否遵循所在平台（Web/iOS/Android）的惯例？
- 术语和措辞在全站是否统一？
- 视觉样式（颜色、字体、间距）是否一致？

**H5 - 错误预防**
- 危险操作是否有二次确认？
- 输入字段是否有格式约束（如日期选择器替代文本输入）？
- 不可用的操作是否已禁用或隐藏？
- 表单是否在提交前做客户端校验？

**H6 - 识别优于回忆**
- 选项是否可见，而非需要用户记住？
- 是否有上下文提示（Placeholder、Tooltip、Hint）？
- 是否保留用户的历史操作记录？
- 搜索是否提供建议和自动补全？

**H7 - 灵活性与效率**
- 是否为频繁操作提供快捷方式？
- 是否支持批量操作？
- 高级用户是否可以自定义界面/流程？
- 是否支持键盘快捷键？

**H8 - 审美与极简设计**
- 是否每个可见元素都有存在的必要？
- 信息密度是否适当（不拥挤也不空旷）？
- 视觉焦点是否清晰？
- 装饰性元素是否干扰了内容理解？

**H9 - 帮助用户识别、诊断和修复错误**
- 错误信息是否用明确的自然语言而非错误码？
- 是否明确说明了错误原因？
- 是否提供了具体的修复建议？
- 错误信息是否靠近出错的位置？

**H10 - 帮助与文档**
- 是否有针对新用户的引导流程（Onboarding）？
- 空状态是否提供了操作引导？
- 复杂功能是否有内嵌帮助提示？
- 帮助文档是否可搜索且以任务为导向？

## 2. Gestalt 视觉感知原则应用指南

Gestalt（格式塔）原则描述了人类大脑如何组织视觉信息。在界面设计评审中应用这些原则：

### 接近性（Proximity）
人类将物理上靠近的元素视为一组。
- **正确应用**：表单标签紧贴对应输入框（间距 4-8px），不同字段组之间留明显间距（16-24px）
- **常见问题**：标签与上方输入框和下方输入框的距离相等，导致归属模糊
- **检查方法**：遮住标签，仅凭间距能否判断标签属于哪个输入框？

### 相似性（Similarity）
外观相似的元素被视为同类。
- **正确应用**：所有主要操作按钮使用同一视觉样式；所有可点击链接使用同一颜色
- **常见问题**：看起来像按钮的元素不可点击；不同功能的按钮视觉上无法区分
- **检查方法**：纯靠视觉，能否区分哪些元素可交互、哪些不可交互？

### 闭合性（Closure）
大脑会自动补全不完整的形状。
- **正确应用**：卡片不需要四面完整的边框，间距和背景色足以暗示分组
- **常见问题**：过度使用边框和分割线，界面显得繁重
- **检查方法**：去掉所有边框线，仅靠间距和背景色能否维持分组感？

### 连续性（Continuity）
视线倾向于沿平滑的路径移动。
- **正确应用**：列表项对齐、时间线连贯、进度条从左到右
- **常见问题**：布局错乱打断阅读流、重要信息在视线路径之外
- **检查方法**：追踪用户的自然阅读路径（F 型/Z 型），关键信息是否在路径上？

### 图底关系（Figure/Ground）
观者会自动区分前景（figure）和背景（ground）。
- **正确应用**：模态弹窗有遮罩层、卡片有轻微阴影与背景区分
- **常见问题**：弹窗与背景层次不清、多层叠加导致混乱
- **检查方法**：能否一眼判断哪个是当前焦点区域？

### 共同命运（Common Fate）
一起运动的元素被视为关联。
- **正确应用**：展开面板时子内容同步出现、拖拽时关联元素一起移动
- **常见问题**：动画不一致导致元素看起来互相独立
- **检查方法**：状态变化时，关联元素是否同步响应？

### 对称性（Symmetry）
对称的元素被视为统一整体。
- **正确应用**：对称布局传达平衡与稳定、打破对称用于引导注意力
- **常见问题**：无意的不对称（非设计意图）让布局看起来草率
- **检查方法**：不对称之处是有意的设计决策还是疏忽？

## 3. 视觉层次分析框架

视觉层次（Visual Hierarchy）决定了用户看到信息的顺序。分析工具：

### 斜视测试（Squint Test）
半眯眼看界面，模糊细节后：
- 能否识别出最重要的元素？
- 信息的分组是否清晰？
- 视觉重心是否在正确的位置？

### 5 秒测试
快速扫视界面 5 秒后：
- 用户能否说出这个页面是做什么的？
- 用户能否找到最重要的操作入口？
- 用户能否说出页面的主要内容区域？

### 层次工具
用以下手段建立视觉层次：
| 工具 | 强度 | 适用场景 |
|------|------|----------|
| 字号差异 | 强 | 标题 vs 正文 |
| 颜色对比 | 强 | CTA 按钮 vs 普通按钮 |
| 字重差异 | 中 | 重要信息 vs 辅助信息 |
| 间距留白 | 中 | 内容分组 |
| 位置（上方/中央） | 中 | 核心内容放在视觉焦点区域 |
| 透明度/灰度 | 弱 | 弱化次要信息 |

## 4. 无障碍设计基线（WCAG 2.1 AA）

视觉审计必须包含的无障碍基线检查：

### 颜色与对比度
- 正文文本（< 18pt）对比度 >= 4.5:1
- 大字文本（>= 18pt 或 14pt 粗体）对比度 >= 3:1
- 非文本 UI 元素（按钮边框、表单控件）对比度 >= 3:1
- 颜色不是传达信息的唯一手段（如错误提示同时使用颜色 + 图标 + 文字）

### 交互元素
- 触摸目标最小尺寸 44x44px（WCAG 2.5.5）
- 焦点指示器在键盘导航时清晰可见
- 焦点顺序符合视觉阅读顺序
- 悬停/聚焦时显示的内容可关闭、可悬停、可持久（WCAG 1.4.13）

### 文本与排版
- 文本可放大至 200% 不丢失内容或功能
- 行高至少 1.5 倍字号、段间距至少 2 倍字号
- 不使用纯图片文本（除非是 Logo）
