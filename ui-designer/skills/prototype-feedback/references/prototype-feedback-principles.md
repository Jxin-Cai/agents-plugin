# 原型反馈原则

---

## 1. 认知走查法（Cognitive Walkthrough）

模拟新用户首次使用界面的认知过程，在每一步问四个问题：

| # | 问题 | 检查要点 |
|---|------|----------|
| Q1 | 用户是否会尝试正确的操作？ | 目标与界面操作匹配？界面暗示了正确下一步？心智模型与系统一致？ |
| Q2 | 用户是否能发现操作入口？ | 按钮/链接在视线范围内？标签/图标足够直观？未被遮挡或淹没？ |
| Q3 | 用户能否将操作与目标关联？ | 标签文字与任务目标匹配？如"发送邀请"而非"提交" |
| Q4 | 用户能否理解操作后反馈？ | 有即时反馈？反馈告知成功/失败？用户知道下一步？ |

### 阻塞点分类
| 类型 | 说明 | 严重程度 |
|------|------|----------|
| 认知阻塞 | 不知道下一步该做什么 | 高 |
| 发现阻塞 | 找不到操作入口 | 高 |
| 理解阻塞 | 不理解操作标签含义 | 中 |
| 反馈阻塞 | 不确定操作是否成功 | 中 |
| 信心阻塞 | 害怕操作的后果 | 低-中 |

## 2. 任务流分析

### 效率度量
| 维度 | 检查 | 优化方向 |
|------|------|----------|
| 步骤数 | 完成任务需要多少步？ | 减少冗余步骤 |
| 决策点 | 用户需做几次选择？ | Hick 定律：每组 <=5-7 个选项 |
| 信息输入 | 需输入多少信息？ | 自动填充、减少必填项 |
| 页面跳转 | 跨几个页面？ | 尽量单页完成 |

### 关键定律
- **Hick 定律**：选项越多决策越慢。超过 7 个时用分类/搜索/渐进式披露
- **Fitts 定律**：频繁操作按钮放大放近，CTA 在拇指热区，危险操作远离常用操作
- **三次点击**：用户应 <=3 次点击到达目标页。超过则评估导航深度或添加快捷入口

## 3. 信息架构评估

### 组织模式
| 模式 | 适用场景 | 示例 |
|------|----------|------|
| 字母序 | 大量同质内容 | 联系人列表 |
| 时间序 | 事件、活动 | 订单历史 |
| 主题分类 | 有明确类别 | 商品分类 |
| 任务分类 | 以用户行为导向 | 操作菜单 |
| 受众分类 | 不同用户群 | "我是商家/我是买家" |

### 导航与标签
- **全局导航**：始终可见？覆盖所有主功能？
- **本地导航**：当前区域子导航清晰？
- **面包屑**：层级路径可追溯？
- **标签语言**：用户语言而非系统术语？标签互斥且稳定？

## 4. 交互状态完整性

### 五种必须设计的状态
| 状态 | 要求 |
|------|------|
| 空状态 | 说明文字 + 引导操作（禁止空白页或仅"暂无数据"） |
| 加载状态 | 骨架屏优于 Spinner；>3s 需进度指示 |
| 部分数据 | 布局合理不空旷，有引导补充数据的提示 |
| 完整数据 | 分页/虚拟滚动 + 排序/筛选/搜索 |
| 错误状态 | 明确原因 + 修复方式 + 重试/刷新/联系支持 |

### 操作反馈矩阵
| 操作 | 成功 | 失败 | 进行中 |
|------|------|------|--------|
| 创建 | Toast/跳转新项目 | 行内错误 | 按钮 Loading |
| 更新 | Toast"已保存" | 行内错误 | 保存指示器 |
| 删除 | Toast + 撤销选项 | Toast 错误 | 按钮 Loading |
| 提交 | 成功页/确认弹窗 | 行内错误汇总 | 全页 Loading |

## 5. 用户旅程映射

六要素：阶段(Phases) -> 行为(Actions) -> 触点(Touchpoints) -> 情绪(+2 到 -2) -> 痛点 -> 机会

关键时刻：首次印象 / 首次成功 / 首次失败 / 再次回访。重点关注"情绪低谷"和"情绪断崖"——最高优先级改进点。

---

## 6. 渐进式披露

默认简单 / 按需展开 / 上下文触发 / 分步引导(Wizard)。触发条件：选项超 7 个(Miller) / 含新手 / 80%用户只用20%功能 / 信息密度过高
