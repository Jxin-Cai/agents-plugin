# 备份恢复体系

设计完整的备份恢复体系，包含数据库备份、文件系统备份、加密存储、自动化调度和恢复流程，输出可直接使用的备份脚本和恢复手册。

## 加载引用

Read file: `./references/backup-recovery-principles.md`

## 强制执行规则

- 所有交互使用中文
- 输出的 Bash 脚本必须可直接运行，包含错误处理和日志记录
- 所有备份必须加密（GPG 或 AES-256）
- 必须遵循 3-2-1 备份原则
- 恢复手册必须包含具体命令和预期时间

## 前置条件

- 已明确需要备份的数据类型（数据库、文件、配置）
- 已明确数据库类型和版本
- 已明确存储目标（S3、GCS、本地）
- 已明确 RTO（恢复时间目标）和 RPO（恢复点目标）

如信息不完整，使用 `AskUserQuestion` 补充。

## Step 1: 备份策略设计

1. 数据分类和备份频率：
   - **数据库**：每日全量 + 持续 WAL/Binlog 归档
   - **文件系统**：每日增量 + 每周全量
   - **配置文件**：每次变更即备份（Git 管理）
   - **应用日志**：按保留策略轮转存储
2. 保留策略：
   - 每日备份保留 7 天
   - 每周备份保留 4 周
   - 每月备份保留 12 个月
   - 年度备份保留 3 年（按合规要求）
3. 备份窗口规划：
   - 选择业务低峰期（如凌晨 2:00 - 4:00）
   - 错开不同备份任务的时间
4. 输出 `backup-strategy.md`

使用 `AskUserQuestion` 确认备份策略和保留周期。

## Step 2: 加密和存储

1. 加密方案：
   - GPG 非对称加密（推荐，密钥管理灵活）
   - AES-256-CBC 对称加密（简单场景）
2. 密钥管理：
   - 加密密钥与备份分开存储
   - 使用 AWS KMS / HashiCorp Vault 托管密钥
   - 密钥定期轮换
3. 存储方案：
   - 本地存储（快速恢复）
   - S3 / GCS 远程存储（异地灾备）
   - S3 生命周期策略（自动转移至 Glacier）
4. 传输安全：
   - 使用 `aws s3 cp --sse AES256` 加密传输
   - 或使用 TLS 加密通道
5. 输出加密和存储配置

## Step 3: 自动化调度和告警

1. 备份脚本编写：
   - 数据库全量备份脚本（`db-backup.sh`）
   - 文件系统增量备份脚本（`fs-backup.sh`）
   - 配置备份脚本（`config-backup.sh`）
2. 每个脚本包含：
   - 参数验证和环境检查
   - 错误处理（`set -euo pipefail`）
   - 日志记录（时间戳、操作、结果）
   - 备份完整性校验（checksum）
   - 清理过期备份
3. Cron 调度配置：
   - 定时执行备份任务
   - 分离日志输出
4. 告警集成：
   - 备份失败通知（邮件 / Slack）
   - 备份空间不足预警
   - 备份超时告警
5. 输出备份脚本和 crontab 配置

使用 `AskUserQuestion` 确认调度时间和告警渠道。

## Step 4: 恢复流程和测试

1. 恢复手册编写：
   - 完整恢复流程（从零恢复）
   - 部分恢复流程（单库 / 单表恢复）
   - 时间点恢复（PITR）
   - 每步包含具体命令、预期耗时、验证方法
2. 恢复测试计划：
   - 季度全量恢复演练
   - 月度抽样恢复验证
   - 自动化恢复测试脚本
3. 恢复验证清单：
   - 数据完整性校验（行数、checksum）
   - 应用连接测试
   - 业务逻辑验证
4. 输出恢复手册和测试计划

## Step 5: 输出备份恢复文件

将所有文件整理输出至 `backup/` 目录：

```
backup/
├── backup-strategy.md          # 备份策略文档
├── scripts/
│   ├── db-backup.sh            # 数据库备份脚本
│   ├── fs-backup.sh            # 文件系统备份脚本
│   ├── config-backup.sh        # 配置备份脚本
│   └── cleanup-expired.sh      # 过期备份清理脚本
├── crontab.conf                # Cron 调度配置
├── recovery-runbook.md         # 恢复手册
└── recovery-test-plan.md       # 恢复测试计划
```

## 成功指标

- [ ] 备份脚本可直接通过 `bash -n` 语法检查
- [ ] 加密备份可成功解密恢复
- [ ] 恢复手册包含每步的具体命令和预期时间
- [ ] 恢复时间满足 RTO 要求
- [ ] 备份频率满足 RPO 要求
- [ ] 告警通知配置完整

## 失败指标

- 备份未加密
- 所有备份存储在同一位置（违反 3-2-1 原则）
- 恢复手册缺少具体命令
- 脚本缺少错误处理
- 没有恢复测试计划

<IMPORTANT>
备份数据必须加密，密钥必须与备份分开存储。
至少一份备份存储在异地/异区域（3-2-1 原则）。
恢复流程必须经过实际测试，纸上谈兵的恢复计划等于没有。
备份脚本必须包含完整性校验（md5sum / sha256sum）。
永远不要信任未经验证的备份 -- 定期执行恢复测试。
</IMPORTANT>
