# 技术债评估 Playbook

---

## 适用场景
对已有系统进行技术债盘点和还债规划。

---

## 执行步骤

### 1. 技术债盘点
按维度扫描：

| 维度 | 检查项 |
|------|--------|
| 代码质量 | 重复代码、过长函数、圈复杂度过高、违反 SOLID |
| 架构 | 循环依赖、不当耦合、缺失抽象层、过度抽象 |
| 依赖 | 过时依赖、已知漏洞、许可证风险 |
| 基础设施 | 手动部署、缺失监控、无 IaC |
| 测试 | 覆盖率不足、脆弱测试、缺失集成测试 |
| 文档 | 架构文档过期、API 文档缺失、运维 runbook 缺失 |

### 2. 影响评估
对每项技术债评估：
- **业务影响**：High / Medium / Low
- **修复成本**：故事点或人天
- **风险等级**：安全 > 稳定性 > 可维护性 > 性能

### 3. 还债计划
- 按 影响/成本 比排序
- 分配到迭代（建议每个 Sprint 预留 15-20% 容量）
- 设置度量指标跟踪还债进度

---

## 质量门控
- [ ] 盘点覆盖全部 6 个维度
- [ ] 影响评估有具体依据（非猜测）
- [ ] 还债计划有明确优先级和时间线
- [ ] 高风险项有临时缓解措施

---

## 产出
`tech-debt/tech-debt-assessment-{日期}.md`：债务清单 + 影响矩阵 + 还债路线图
