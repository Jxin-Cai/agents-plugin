# 完整架构流程 Playbook

---

## 适用场景
需要从 API → 数据库 → 可扩展性 完整规划的新系统或重大重构。

---

## 执行原则

| 原则 | 说明 |
|------|------|
| 约束优先 | 先收集非功能需求（QPS、SLA、数据量级）再设计 |
| 逐层递进 | API 契约 → 数据模型 → 扩展策略，上层决策影响下层 |
| 决策可追溯 | 每个关键决策记录 context + options + chosen + reason |
| 阶段摘要 | 每阶段产出 ≤20 行摘要写入 `meta/`，供下一阶段参考 |

---

## 质量门控

### API 设计阶段
- [ ] 资源命名一致（复数名词、kebab-case）
- [ ] 错误码体系完整（4xx/5xx 分类）
- [ ] 幂等性标注（POST/PUT/PATCH/DELETE）
- [ ] 版本策略明确

### 数据库建模阶段
- [ ] ER 图覆盖核心实体
- [ ] 索引策略匹配查询模式
- [ ] 数据增长预估（1年/3年）
- [ ] 软删除 vs 硬删除策略

### 可扩展性评审阶段
- [ ] 瓶颈分析有数据支撑（非猜测）
- [ ] 扩展方案有明确触发条件
- [ ] CAP 权衡有业务场景映射
- [ ] 容灾方案覆盖关键故障域

---

## 产出规范

| 阶段 | 产出路径 | 格式 |
|------|---------|------|
| API 设计 | `api/api-design-{日期}.md` | 资源清单 + 端点表 + 错误码表 |
| 数据库建模 | `database/db-model-{日期}.md` | ER 描述 + 索引策略 + DDL 草案 |
| 可扩展性 | `scalability/scalability-review-{日期}.md` | 瓶颈表 + 扩展方案 + 容灾矩阵 |
| 综合摘要 | `meta/architecture-summary-{日期}.md` | 全局架构决策记录 |
