# 实验设计原则

本文档定义了 A/B 测试设计阶段必须遵循的原则。用这些原则检验实验方案的严谨性。

---

## 1. 假设构建

可证伪假设是实验的灵魂。一个好的假设必须满足：

### 结构化假设模板

```
如果我们 [具体的干预/变化]，
那么 [可观测的指标] 将会 [方向] [幅度]，
因为 [因果机制]。
```

### 假设质量检查清单

- **具体性**：能否直接转化为实验变量？"优化体验"不合格，"将加载时间从 3s 降到 1.5s"合格
- **可观测性**：因变量能否被系统自动采集？需要问卷调查的指标慎用
- **可证伪性**：什么样的实验结果可以否定这个假设？
- **因果清晰**：变化到结果之间的因果链条是否合理？中间有多少跳？
- **预期幅度**：MDE（最小可检测效应）是否基于业务判断而非凭空猜测？

### 常见假设陷阱

| 陷阱 | 示例 | 修正 |
|------|------|------|
| 过于模糊 | "新设计会更好" | "新结账流程将使完成率从 65% 提升到 70%" |
| 不可证伪 | "用户可能会喜欢" | 改为可量化的行为指标 |
| 多因果混淆 | "改了颜色和文案会提升转化" | 拆成两个独立实验，或使用因子设计 |
| MDE 不合理 | "期望提升 50%" | 参考行业基准和历史实验数据 |

## 2. 变量控制

### 单一变量原则

实验的核心原则：一次只改一个东西。如果同时改了按钮颜色和文案，你无法知道是哪个变化带来了效果。

例外情况：
- **因子设计**：需要测试变量间的交互效应时，可以同时测试多个变量，但需要更大的样本量
- **多臂老虎机**（Multi-Armed Bandit）：探索阶段允许多个变体，但目标不同于经典 A/B 测试

### 变量分类

| 类型 | 定义 | 注意事项 |
|------|------|---------|
| 自变量 | 你主动改变的变量（实验干预） | 必须精确定义变化内容 |
| 因变量 | 你观测的结果变量（实验指标） | 必须可量化、可自动采集 |
| 控制变量 | 需要保持不变的干扰因素 | 通过随机化和分层来控制 |
| 混淆变量 | 同时影响自变量和因变量的变量 | 必须识别并通过设计消除 |

### 混淆变量识别

问自己三个问题：
1. 有没有什么因素会同时影响分组和结果？
2. 实验期间有没有其他变化同时发生？
3. 实验组和对照组除了干预之外，还有其他区别吗？

## 3. 随机分组

### 随机化的目的

确保实验组和控制组在所有已知和未知的维度上都是可比的。分组的唯一差异应该是实验干预本身。

### 分组方案选择

**简单随机分组（Simple Randomization）**
- 每个用户以固定概率被分配到各组
- 适用于样本量大、用户独立的场景
- 可能出现组间不均衡（小样本时尤其明显）

**分层随机化（Stratified Randomization）**
- 先按关键维度分层（如新/老用户），再在每层内随机分配
- 确保关键维度上的组间均衡
- 适用于已知某些维度对指标影响很大的场景

**集群随机化（Cluster Randomization）**
- 以集群（如城市、公司、社交圈）为单位分配
- 适用于存在网络效应、社交传播的场景
- 有效样本量是集群数而非用户数，需要更大样本

**交叉设计（Crossover Design）**
- 同一用户先后体验两种版本
- 适用于持续性干预、效果可逆的场景
- 必须考虑顺序效应和携带效应

### SRM 检查（Sample Ratio Mismatch）

实验开始后，第一件事是检查实际分组比例是否符合预期：
- 如果预期 50/50，实际为 52/48，需要调查原因
- SRM 可能说明随机化代码有 bug，或某些用户群体被系统性排除
- 发现 SRM 的实验结果不可信，必须先解决分组问题

## 4. 样本量计算

### 核心公式参数

| 参数 | 符号 | 说明 | 影响 |
|------|------|------|------|
| 显著性水平 | alpha | 允许的一类错误概率 | alpha 越小，需要样本量越大 |
| 检验力 | 1 - beta | 检测到真实效果的概率 | 检验力越高，需要样本量越大 |
| 最小可检测效应 | MDE/delta | 业务上有意义的最小变化 | MDE 越小，需要样本量越大 |
| 基线值 | p0 / mu0 | 当前指标水平 | 影响方差估计 |
| 方差 | sigma^2 | 指标波动程度 | 方差越大，需要样本量越大 |

### 比例型指标（如转化率）

```
每组样本量 n = (Z_alpha/2 + Z_beta)^2 * [p1(1-p1) + p2(1-p2)] / (p1 - p2)^2
```

其中 p1 为基线转化率，p2 为期望转化率。

### 连续型指标（如 ARPU、停留时长）

```
每组样本量 n = (Z_alpha/2 + Z_beta)^2 * 2 * sigma^2 / delta^2
```

其中 delta 为期望的绝对差异，sigma 为标准差。

### 方差缩减技术

当样本量需求过大时，可以使用方差缩减技术减少所需样本量：

- **CUPED**（Controlled-experiment Using Pre-Experiment Data）：利用实验前的用户行为数据作为协变量，降低 20-50% 的方差
- **分层分析**：在分层变量内进行分析，减少组间方差
- **差分法**（Difference-in-Differences）：比较实验前后的变化差异而非绝对值

## 5. 实验时长

### 最短时长要求

- **统计要求**：累积足够的样本量
- **业务周期要求**：至少覆盖一个完整周（7 天），消除星期效应
- **用户行为要求**：对于低频行为（如月度续费），需要覆盖一个完整的行为周期

### 时长估算公式

```
实验天数 = ceil(每组所需样本量 * 组数 / 日均符合条件的流量)
```

向上取整到完整周（7 的倍数）。

### 不宜运行实验的时间窗口

- 重大节假日（如双十一、春节）——用户行为异常
- 系统大版本发布前后——技术变量失控
- 竞品重大变动期——外部干扰
- 季节性波动窗口——除非季节性本身是研究对象

## 6. 预注册

### 为什么需要预注册

预注册是在实验开始前记录假设、分析计划和决策标准。目的是防止：
- **p-hacking**：尝试多种分析方法直到找到显著结果
- **HARKing**（Hypothesizing After Results are Known）：看到结果后编造假设
- **选择性报告**：只报告支持假设的指标

### 预注册文档应包含

1. **假设声明**：结构化的可证伪假设
2. **主要指标**：事前确定的核心评判指标（最多 1-2 个）
3. **分析方法**：频率学派/贝叶斯/序贯，具体的统计检验方法
4. **决策规则**：什么条件下推全/回滚/继续观察
5. **分群分析计划**：事前确定要分析的用户分群
6. **多重比较校正**：如果有多个变体或指标，使用什么校正方法
