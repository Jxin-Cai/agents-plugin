## Step 1: 数据质量检查

在进行任何统计分析之前，先做数据质量检查：

### SRM 检查（Sample Ratio Mismatch）

- "实验组和控制组的实际样本量各是多少？"
- "预期分配比例是多少？（如 50/50）"
- 计算卡方检验判断分组比例是否异常
- **如果 SRM 存在**：必须暂停分析，先排查原因（随机化 bug、数据丢失、用户退出偏差）

### 数据完整性检查

| 检查项 | 确认 |
|--------|------|
| 实验运行时长是否达到预设要求？ | ✅/❌ |
| 是否覆盖了完整的业务周期（至少 1 周）？ | ✅/❌ |
| 是否有数据缺失或异常波动？ | ✅/❌ |
| 是否有外部事件干扰（促销、故障、竞品变动）？ | ✅/❌ |
| 各指标的数据是否完整采集？ | ✅/❌ |

**⏸️ 向用户报告数据质量检查结果。如果有问题，讨论是否可以继续分析。等待用户确认。**

## Step 2: 护栏指标检查

**先看护栏，再看核心。** 如果护栏指标恶化，核心指标再好也需要审慎决策。

对每个护栏指标：
- 报告实验组和控制组的数值
- 判断是否有统计显著的恶化
- 如果恶化幅度超过预设阈值，**立即向用户预警**

护栏检查结果分三档：
- 🟢 安全：所有护栏指标无显著恶化
- 🟡 需关注：某护栏指标有轻微恶化，但未超阈值
- 🔴 警告：护栏指标显著恶化，需要认真评估是否推全

**⏸️ 等待用户确认是否继续分析核心指标。**

## Step 3: 核心指标统计检验

引导用户选择分析方法（或使用预注册中指定的方法）：

### 频率学派分析

报告以下信息：
- **样本量**：各组实际样本量
- **点估计**：各组指标值及差异
- **效果量**：相对提升（Relative Lift）和绝对提升（Absolute Lift）
- **置信区间**：95% CI（或预设水平）
- **p 值**：双尾检验结果
- **检验力**：实际达到的检验力（是否满足预设的 80%）

### 贝叶斯分析

报告以下信息：
- **后验概率**：实验组优于控制组的概率
- **可信区间**：95% 可信区间
- **预期损失**：如果选错方案的预期损失
- **Bayes Factor**：支持实验假设 vs 零假设的证据强度

### 结果解读模板

```markdown
### [指标名称]

| | 控制组 | 实验组 | 差异 |
|--|--------|--------|------|
| 样本量 | [N1] | [N2] | - |
| 指标值 | [V1] | [V2] | [V2-V1] |
| 相对提升 | - | - | [+X.X%] |
| 95% CI | - | - | [下限, 上限] |
| p 值 | - | - | [p] |
| 结论 | | | [显著/不显著] |
```

**⏸️ 向用户展示核心指标分析结果。等待用户确认。**

## Step 4: 辅助指标分析

对辅助指标进行相同的统计分析，用于：
- 解释核心指标的变化原因
- 发现潜在的分群差异
- 识别非预期的效应

**关键追问**：
- "核心指标和辅助指标的变化方向是否一致？"
- "有没有辅助指标的变化超出预期？"
- "需要做哪些分群分析？（新/老用户、不同地区、不同设备）"

如果有多重比较校正需求，应用预注册中指定的校正方法。

## Step 5: 分群分析（如需要）

基于预注册的分群计划或发现的异常信号，进行分群分析：

- 按用户类型（新/老用户）
- 按设备类型（iOS/Android/Web）
- 按地区（一线/二线/三四线城市）
- 按用户活跃度（高活/低活）

**辛普森悖论检查**：总体趋势是否与分群趋势一致？如果不一致，需要深入分析。

**注意**：事后的分群分析仅供参考和假设生成，不能用于做推全决策。

## Step 6: 决策建议

基于全部分析结果，引导用户做出决策：

### 决策矩阵

| 核心指标 | 护栏指标 | 建议 |
|---------|---------|------|
| 显著提升 | 安全 | **推全**——效果明确且无副作用 |
| 显著提升 | 有恶化 | **权衡**——量化得失，评估长期影响 |
| 不显著 | 安全 | **不推全**——没有证据支持变化有效 |
| 不显著 | 有恶化 | **回滚**——没有收益且有副作用 |
| 显著恶化 | — | **回滚**——变化产生了负面效果 |

### 非结论性结果的处理

如果结果不显著，引导用户区分：
- **检验力不足**：样本量不够大，可能错过了真实效果 → 建议延长实验或增加流量
- **效果确实不存在**：检验力充足但效果接近零 → 接受零假设，记录学习
- **效果量太小**：统计显著但业务无意义 → 不推全，但记录为知识

### 下一步行动

引导用户明确：
- 如果推全：推全时间表、全量上线的监测计划
- 如果回滚：回滚执行方案、替代方案探索
- 如果继续实验：调整方案、延长时长、新假设
- 无论结果如何：记录到知识库，作为未来实验的参考

**⏸️ 等待用户确认决策。**

## Step 7: 保存产出

将分析结果保存到 `{实验目录}/results/analysis-{日期}.md`，包含：
- 数据质量检查报告
- 护栏指标检查结果
- 核心指标统计检验结果（包含效果量和置信区间）
- 辅助指标分析结果
- 分群分析结果（如有）
- 决策建议和下一步行动

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：实验 "{实验名}" 分析完成。核心指标 [结果摘要]。护栏指标 [状态]。建议：[推全/回滚/继续观察]。

- **归档实验记录（推荐）** — 将完整的实验记录归档到知识库
- **调整分析** — 如果需要补充分群分析或更换统计方法
- **回到实验设计** — 如果需要基于本次结果设计迭代实验

## 完成标准

| 维度 | 合格条件 |
|------|---------|
| 数据质量 | SRM 检查和完整性检查在统计分析之前完成 |
| 检查顺序 | 护栏指标先于核心指标检查 |
| 统计报告 | 同时报告 p 值、效果量和置信区间 |
| 不显著处理 | 区分"检验力不足"和"效果不存在" |
| 分群标注 | 事前/事后分群分析有明确标注 |
| 决策建议 | 基于完整证据链（统计 + 业务上下文） |
| 知识记录 | 无论结果正负都记录学习和下一步 |
| 用户确认 | 每步分析经用户确认，菜单后等待输入 |

<IMPORTANT>
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
护栏指标必须在核心指标之前检查，发现护栏显著恶化时必须先向用户预警，不可直接报告核心指标结果。
统计结论必须同时报告 p 值、效果量（相对提升 + 绝对提升）和置信区间三项，缺任何一项不可作为有效结论。
结果不显著时必须区分"检验力不足"和"效果不存在"，禁止笼统地说"没有显著差异"。
事后分群分析必须明确标注为"探索性分析，仅供假设生成"，不可用于推全决策。
</IMPORTANT>
