# 指标定义原则

本文档定义了实验指标定义阶段必须遵循的原则。用这些原则检验指标体系的严谨性和完整性。

---

## 1. 指标分类体系

实验指标按其在决策中的角色分为三个层级：

### 核心指标（Primary Metric / OEC）

- **定义**：整体评估标准（Overall Evaluation Criterion），实验成败的最终裁判
- **数量限制**：最多 1-2 个。超过 2 个说明没有聚焦
- **要求**：直接反映实验假设，灵敏度足够在实验周期内检测到变化
- **决策规则**：核心指标显著提升 → 推全；核心指标无变化或恶化 → 回滚或迭代

### 辅助指标（Secondary Metrics）

- **定义**：帮助理解核心指标变化原因的诊断指标
- **数量建议**：2-4 个
- **用途**：拆解因果链，如"转化率提升了，是因为点击率提升还是完成率提升？"
- **注意**：辅助指标的统计检验结果仅供参考，不用于做推全决策

### 护栏指标（Guardrail Metrics）

- **定义**：实验不应恶化的指标，用于监测副作用
- **数量建议**：2-3 个
- **常见护栏**：
  - 性能类：页面加载时间、接口响应时间、错误率
  - 用户体验类：客诉率、退出率、客服工单量
  - 商业类：客单价、退货率、用户流失率
- **触发机制**：护栏指标恶化超过预设阈值 → 立即审视实验，必要时终止

## 2. 计算口径规范

每个指标必须有精确的计算口径，消灭任何模糊地带。

### 必须定义的要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 分子 | 事件数或度量值的精确定义 | "用户在结账页面点击'提交订单'按钮的事件数" |
| 分母 | 计算基数的精确定义 | "在实验期间至少浏览过一次商品详情页的独立用户数" |
| 时间窗口 | 观测周期 | "用户首次曝光后 7 天内" |
| 过滤条件 | 数据清洗规则 | "排除内部测试账号、机器人流量、单日访问超过 1000 次的异常用户" |
| 聚合方式 | 汇总计算方法 | "用户级别的均值（先计算每个用户的指标，再取均值）" |
| 数据源 | 具体的表/埋点/日志 | "event_tracking 表中 event_name = 'checkout_submit' 的记录" |

### 口径一致性原则

- 控制组和实验组的指标计算口径必须完全相同
- 如果控制组用 UV 做分母，实验组也必须用 UV
- 如果控制组用"首次曝光后 7 天"做时间窗口，实验组也必须如此

---

## 3. 分母陷阱

分母定义是指标中最容易出错、影响最大的环节。以下是必须检查的陷阱：

### 幸存者偏差（Survivorship Bias）

- **问题**：分母只包含"活到某个环节"的用户，遗漏了中途流失的
- **示例**：计算"注册完成率"时，分母只包含到达注册页面的用户，但实验变化实际上改变了到达注册页面的用户数量
- **检查**：分母应从最早的触发点开始计算

### 曝光偏差（Exposure Bias）

- **问题**：用户被分配到实验组但未实际看到变化，却被算进了分母
- **示例**：更改了结账页面，但很多被分组的用户从未到达结账页面
- **检查**：区分"Intent-to-Treat"（所有分组用户）和"Per-Protocol"（实际曝光用户）

### 时间窗口偏差（Time Window Bias）

- **问题**：分子和分母的时间窗口不匹配
- **示例**：分母算"今天的活跃用户"，分子算"过去 7 天的购买"
- **检查**：确保分子和分母的时间窗口定义一致

### 新/老用户混淆

- **问题**：新用户和老用户被混在一起计算，但行为模式完全不同
- **示例**：新用户的转化率天然较低，如果实验组分到更多新用户，核心指标就会被拉低
- **检查**：考虑是否需要分层分析，或在分母中标注用户类型

## 4. 指标灵敏度

### 灵敏度评估框架

一个好的核心指标应该满足：

| 维度 | 要求 | 检查方法 |
|------|------|---------|
| 波动性 | 日常波动不应过大 | 查看历史数据的变异系数（CV = 标准差/均值） |
| 方向性 | 变化方向与业务价值一致 | 指标↑ 是否真的意味着业务变好？ |
| 时效性 | 实验周期内能观测到变化 | 行为发生频率 vs 实验时长 |
| 可归因性 | 实验干预能直接影响 | 干预到指标之间隔了几个环节？ |

### 灵敏度不足的应对

| 问题 | 解决方案 |
|------|---------|
| 指标波动太大 | 使用 CUPED 方差缩减、对数变换、截尾处理 |
| 行为频率太低 | 使用更近端的代理指标 |
| 因果链太长 | 使用更贴近干预的中间指标 |
| 样本量不够 | 延长实验时长或缩小 MDE 要求 |

### 近端 vs 远端指标

```
干预 → 近端指标 → 中端指标 → 远端指标
示例：改按钮颜色 → 按钮点击率 → 加购率 → GMV
```

- 近端指标：灵敏度高，但未必反映最终业务价值
- 远端指标：直接反映业务价值，但灵敏度低、噪声大
- 建议：核心指标选中端，辅助指标近端和远端各选一个

---

## 5. 指标体系构建

### 指标树方法

从终极业务目标出发，逐层拆解：

```
营收 = 用户数 x 转化率 x 客单价
     = (新用户 + 老用户) x (浏览→加购 x 加购→下单 x 下单→支付) x 均价
```

每一层拆解都可能是一个指标。选择与实验假设最相关的层级作为核心指标。

### 指标间关系检查

- **互斥关系**：A 和 B 不可能同时提升（如低价策略下客单价和订单量的关系）
- **因果关系**：A 提升导致 B 提升（点击率 → 转化率）
- **相关关系**：A 和 B 同时变化但不是因果（可能有共同原因）
- **零和关系**：实验只是在不同指标间重新分配（如首页改版只是改变了流量分配）

### 多指标的多重比较校正

当同时检验多个指标时，假阳性率膨胀：

| 指标数 | 未校正的总假阳性率 | 建议校正方法 |
|--------|-----------------|-------------|
| 1 个 | 5% | 无需校正 |
| 3 个 | 14.3% | Holm 校正 |
| 5 个 | 22.6% | Benjamini-Hochberg（FDR 控制） |
| 10 个 | 40.1% | 必须校正，或事前指定唯一核心指标 |

**最佳实践**：事前指定 1 个核心指标不做校正，其他指标全部做 FDR 校正。
