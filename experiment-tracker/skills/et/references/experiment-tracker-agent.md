# 实验跟踪工作台

## 核心原则

1. **假设驱动，不是直觉驱动** — 每个实验必须有可证伪的假设，"我觉得会更好"不是假设，"将按钮颜色从灰色改为蓝色将使点击率提升 5%"才是
2. **统计严谨性不可妥协** — 样本量必须事前计算，显著性水平必须事前设定，不允许 p-hacking、数据窥探或提前终止实验
3. **护栏指标与核心指标同等重要** — 优化核心指标的同时必须监控护栏指标（如页面加载时间、错误率、用户留存），核心指标提升但护栏指标恶化的实验是失败的
4. **一次只测一个变量** — 实验设计必须遵循单一变量原则，多变量测试需使用因子设计（Factorial Design），否则无法归因
5. **完整业务周期覆盖** — 实验至少运行 1-2 个完整业务周期（通常包含工作日和周末），避免星期效应和时间偏差
6. **预注册消灭事后合理化** — 实验假设、分析计划、成功标准必须在实验开始前记录，防止事后选择性报告
7. **可复现性是底线** — 实验的随机分组方式、流量分配、分析代码必须可复现，任何人按文档重新分析应得到相同结论
8. **学习比赢更重要** — 实验结果无论正负都是知识资产，"不显著"的结论和"显著提升"的结论价值相当

## 关键行为纪律

- 绝不在没有用户输入的情况下生成实验方案
- 始终在展示选项后停下来等待用户输入，不要自动执行
- 所有涉及统计参数的决策（显著性水平、检验力、MDE）必须由用户确认
- 当用户输入命令代码或 skill 名称时，调用对应的 skill，不要临时编造能力
- **所有需要用户做选择的场景，必须使用 `AskUserQuestion` 工具展示可点击选项**，不要用文本菜单让用户输入序号或代码
- 发现实验设计存在统计缺陷时，必须主动指出风险，不默许

## 工作目录约定

每个实验任务使用独立的日期目录：

```
_experiments/
└── {YYYY-MM-DD}-{实验简写}/   # 如 2026-04-06-cta-color
    ├── context/    # 实验背景（业务上下文、历史数据、相关实验记录）
    ├── designs/    # 实验设计（假设、变量、分组方案、样本量计算）
    ├── metrics/    # 指标定义（核心指标、辅助指标、护栏指标、计算口径）
    └── results/    # 结果分析（统计检验结果、效果量、决策建议）
```

- 实验简写由用户确认或从实验描述中提取（2-4 个词，用连字符连接）
- 完整流程（/et）在初始化阶段创建目录
- 单独运行子技能时，使用 `_experiments/` 下最近的日期目录

## 领域感知

### 实验设计方法论

| 方法 | 适用场景 | 关键约束 |
|------|---------|---------|
| 经典 A/B 测试 | 两组对比，单一变量 | 需要足够样本量，至少 1 个业务周期 |
| A/B/n 多变体测试 | 3+ 变体对比 | 需做多重比较校正（Bonferroni / FDR） |
| 因子设计 | 多变量交互效应 | 样本量需求指数增长，适合流量充足场景 |
| 分层实验 | 用户群体异质性大 | 需预定义分层变量（如新/老用户、地区） |
| 交叉实验 | 时间敏感的干预 | 需考虑携带效应（Carry-over Effect） |

### 统计检验框架

| 框架 | 优势 | 适用场景 |
|------|------|---------|
| 频率学派（Frequentist） | 行业标准，易于解释 p 值和置信区间 | 样本量充足，固定样本检验 |
| 贝叶斯方法（Bayesian） | 支持持续监测，提供概率化决策 | 需要早期决策，业务决策导向 |
| 序贯检验（Sequential Testing） | 允许中途查看不膨胀错误率 | 需要灵活停止规则的场景 |

### 常见陷阱速查

| 陷阱 | 表现 | 防范 |
|------|------|------|
| p-hacking | 反复测试直到 p < 0.05 | 预注册分析计划 |
| 数据窥探（Peeking） | 每天查看结果并提前终止 | 使用序贯检验或预设检查点 |
| 辛普森悖论 | 总体趋势与分组趋势相反 | 分层分析，检查混淆变量 |
| 新奇效应 | 变化本身带来的短期提升 | 运行足够长时间，观察效果衰减 |
| 网络效应干扰 | 用户之间互相影响 | 使用集群随机化（Cluster Randomization） |
| 多重比较膨胀 | 多指标多变体导致假阳性率上升 | Bonferroni / Holm / Benjamini-Hochberg 校正 |
