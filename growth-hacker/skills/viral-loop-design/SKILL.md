# 病毒循环设计

引导式病毒循环设计流程：从网络效应潜力分析到推荐机制设计、病毒系数计算、方案输出。

## 强制执行规则

1. **必须**先分析产品的网络效应潜力，再设计推荐机制
2. **病毒系数**必须有计算过程，不能凭感觉估算
3. **推荐机制**必须考虑双边激励和反欺诈
4. **输出文件**保存到 `viral/` 子目录
5. 全程使用**中文**与用户交互

## 前置条件

- 已有产品基本信息
- 用户能提供当前推荐相关数据（如有）

## Step 1: 分析产品的网络效应潜力

**目标**：评估产品是否具备病毒传播的基因。

分析维度：
1. **网络效应类型**：直接 / 间接 / 数据 / 无网络效应
2. **产品传播性评估**：多人场景？可分享产出？核心价值一句话说清？口碑时刻？
3. **当前传播数据**（如有）：K-factor、NPS、主动分享频率

输出格式：

```markdown
## 网络效应潜力评估

| 维度 | 评估结果 | 说明 |
|------|---------|------|
| 网络效应类型 | {直接/间接/数据/无} | {一句话理由} |
| 多人使用场景 | {有/无} | {具体场景} |
| 可分享产出 | {有/无} | {产出类型} |
| 口碑时刻 | {有/无} | {触发场景} |
| 传播性评分 | {1-10} | {综合评估} |
| 推荐模式建议 | {邀请奖励/内容共享/协作价值/社交证明} | {选择理由} |
```

## Step 2: 设计推荐机制

**目标**：设计适合产品的病毒循环机制。

根据 Step 1 的分析结果，设计推荐方案：

1. **激励模式选择**
   - 单边激励（仅推荐人获益）
   - 双边激励（推荐人 + 被推荐人双方获益）
   - 无激励（产品价值本身驱动分享）

2. **推荐流程设计**
   - 触发时机：用户在什么时刻最可能推荐？
   - 推荐方式：链接/邀请码/二维码/社交分享
   - 落地体验：被推荐人的首次体验优化
   - 奖励发放：即时/延迟/阶梯式

3. **反欺诈机制**
   - 防刷单策略
   - 奖励上限设置
   - 质量验证（被推荐人需完成激活行为）

## Step 3: 计算病毒系数（K-factor）

**目标**：量化评估推荐机制的预期效果。

计算框架：

```
K = i × c

i = 每个用户发出的平均邀请数
c = 每个邀请的转化率（收到邀请 → 完成注册/激活）
```

细化计算：

```
i = 推荐参与率 × 每个参与者平均邀请数
c = 邀请到达率 × 邀请打开率 × 落地页转化率 × 激活率
```

需要估算的参数：
- 推荐参与率（有推荐行为的用户占比）
- 人均邀请数
- 邀请到达率（成功送达）
- 邀请转化率

输出：K-factor 计算表 + 敏感度分析

## Step 4: 输出病毒循环设计方案

**目标**：生成完整的病毒循环设计文档。

输出到 `viral/viral-loop-design.md`，包含：
- 网络效应分析结论
- 推荐机制设计（完整流程图）
- K-factor 计算与敏感度分析
- 分阶段实施计划（MVP → 迭代 → 优化）
- 关键指标追踪看板
- 反欺诈策略

---

## 成功指标

- 完成网络效应类型分析和传播性评估
- 推荐机制包含完整的触发→推荐→落地→奖励流程
- K-factor 有详细的计算过程和敏感度分析
- 设计方案有分阶段实施计划

## 失败指标

- 跳过网络效应分析直接设计推荐机制
- K-factor 没有计算过程（纯拍脑袋）
- 推荐机制缺少反欺诈考虑
- 方案不可执行（缺少实施步骤）

---

**IMPORTANT**: 绝不跳过网络效应分析。病毒系数必须有计算过程。推荐机制必须考虑双边激励和反欺诈。对于没有天然网络效应的产品，诚实告知并设计适合的轻量传播策略，不强行套用病毒模型。
