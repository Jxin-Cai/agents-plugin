# 情感分析原则

> 确保情感判断准确、分析维度完整、结论可追溯。

---

## 1. 多维情感分类

每条反馈必须标注以下四个维度：

| 维度 | 选项 | 说明 |
|------|------|------|
| 情感极性 | 正面 / 负面 / 中性 / 混合 | 混合指同一条反馈含正负面情感 |
| 情感强度 | 5(强烈) / 4(较强) / 3(中等) / 2(较弱) / 1(微弱) | 5=极端表达，1=需从上下文推断 |
| 情感指向 | 功能 / 性能 / 界面 / 服务 / 价格等 | 必须具体到对象，"不满意"不是有效标注 |
| 判断置信度 | 高 / 中 / 低 | 低置信度标记"待人工复核" |

**处理规则：**
- 混合情感需拆分多个指向分别标注
- 反讽和隐喻需结合上下文和标点符号判断（如"真是太'好用'了"= 负面）
- 中文用户倾向含蓄表达——对"还行""一般""凑合用"保持负面警觉

---

## 2. NPS/CSAT/CES 评分框架

量化评分与文本情感必须交叉验证，二者矛盾时需特别关注。

| 框架 | 公式 | 基准 | 关键动作 |
|------|------|------|---------|
| NPS | 推荐者%(9-10) - 贬损者%(0-6) | >50优秀, 30-50良好, <0危险 | 分析推荐者/贬损者文本，关注7-8分被动者转化机会 |
| CSAT | (4+5分) / 总数 x 100% | >80%优秀, 65-80%良好 | 对比不同触点CSAT，揭示体验断点 |
| CES | 用户完成任务费力度 | 低费力=高留存 | 关注"麻烦""复杂""找不到""步骤太多"等信号词 |

**交叉验证规则：**
- NPS 高分 + 文本负面 → 惯性打高分，需关注文本隐忧
- NPS 低分 + 文本正面 → 对产品满意但对品牌/价格不满
- CSAT 各触点差异大 → 用户旅程存在体验断点

---

## 3. 主题聚类方法

**聚类流程：** 开放编码（逐条标注关键词）→ 轴心编码（相似关键词归类）→ 选择编码（合并精炼为 5-8 个核心主题）→ 主题命名（具体可操作）

**聚类原则：**
- **互斥性**：一条反馈只归入一个主题
- **穷尽性**：所有反馈都能归入某个主题（"其他"不超过 10%）
- **粒度适中**：5-8 个最佳（<5 过笼统，>10 过碎片）
- **可操作性**：主题命名指向可改进方向（"页面加载超3秒" > "性能差"）

**Kano 模型辅助分类：**

| 类型 | 定义 | 示例 |
|------|------|------|
| 基本需求 | 没有会不满，有了不特别满意 | 登录能正常使用 |
| 期望需求 | 满足程度越高越满意 | 加载速度越快越好 |
| 兴奋需求 | 未期望但提供后惊喜 | 智能推荐恰好想要 |
| 反向需求 | 有了反而不满 | 强制弹窗教程 |

---

## 4. 趋势分析与反陷阱

**时间序列分析：** 追踪各主题的反馈量和情感极性随时间变化，标注关键事件节点（版本发布、营销活动、竞品动态），区分趋势（持续性）和波动（一次性），关注突增/突降/渐升/渐降四种模式。

**常见陷阱：**

| 陷阱 | 描述 | 应对 |
|------|------|------|
| 反讽误判 | "真是太'好用'了"被判正面 | 结合上下文和标点符号 |
| 文化差异 | 中文含蓄表达，负面被低估 | 对"还行""一般"保持警觉 |
| 幸存者偏差 | 只有不满用户发声 | 对比沉默多数的行为数据 |
| 锚定效应 | 第一印象主导后续判断 | 逐条独立标注 |
| 频率幻觉 | 同一用户多渠道重复 | 去重后再统计 |
| 表达强度偏差 | 极端少数掩盖温和多数 | 同时关注频次和强度 |
