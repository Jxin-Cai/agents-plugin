# 洞察决策框架

> 从洞察到决策的转化框架：机会识别、决策分层、常见陷阱。

---

## 1. 机会解决方案树

使用 Teresa Torres 的 Opportunity Solution Tree 框架：

```
期望成果（要改善的指标，如"NPS 从 30 提升到 50"）
├── 机会 1（改进机会）→ 方案 A / 方案 B
├── 机会 2 → 方案 C / 方案 D
└── 机会 3 → 方案 E
```

**规则：**
- 期望成果从分析目的出发，明确要改善的指标
- 每个机会至少 2 个方案，避免锁定第一个想到的方案
- 每个方案标注核心假设和最小验证实验

---

## 2. 决策建议分层

| 层级 | 受众 | 内容 | 时间 |
|------|------|------|------|
| 执行摘要 | 高管 | 3句话概括核心发现和建议 | 30秒看完 |
| 立即行动项 | 执行团队 | 速赢项，明确负责人和预期 | 本周启动 |
| 短期规划项 | 产品经理 | 战略项目，需评估排期 | 1-3个月 |
| 持续监控项 | 数据团队 | 需持续跟踪的指标趋势 | 持续 |
| 开放问题 | 研究团队 | 需进一步调研的未解问题 | 按需 |

**建议质量标准：** 可分配（谁来做）+ 可衡量（怎么知道成功）+ 有时间预期（多久见效）。避免"提升用户体验"等无法执行的万金油建议。

---

## 3. 反洞察陷阱

| 陷阱 | 描述 | 应对 |
|------|------|------|
| 确认偏误 | 只关注支持预设结论的数据 | 主动寻找反面证据 |
| 频率偏误 | 高频 = 高优先级 | 同时考虑影响深度和用户价值 |
| 近因偏误 | 过度关注最近的反馈 | 区分趋势和波动 |
| 生存者偏差 | 只分析活跃用户 | 关注沉默用户和流失用户 |
| 过度拟合 | 少量数据提取过多结论 | 标明样本量和置信度 |
| 伪相关 | 相关性当因果性 | 标明是假设，需验证 |
