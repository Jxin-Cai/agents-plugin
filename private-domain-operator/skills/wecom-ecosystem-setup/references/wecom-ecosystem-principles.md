# 企微生态搭建原则

本文档定义了企微生态搭建阶段必须遵循的原则和最佳实践。用这些原则检验配置方案的完整性和合理性。

---

## 1. 企微组织架构最佳实践

### 团队架构设计

企微私域团队的组织架构应根据业务规模分级设计：

**初创期（好友<1万）**
```
私域负责人（1人）
├── 运营专员（1-2人）：内容+社群+活动
└── 客服（1人）：咨询+售后
```

**成长期（好友1-10万）**
```
私域负责人（1人）
├── 内容组（2-3人）：内容策划+素材制作
├── 运营组（2-3人）：社群运营+活动策划
├── 销售组（2-5人）：1对1成交+客户跟进
└── 数据专员（1人）：数据分析+报表
```

**成熟期（好友>10万）**
```
私域总监（1人）
├── 内容中心（5+人）
├── 社群运营（5+人）
├── 销售团队（10+人）
├── SCRM/技术（2-3人）
├── 数据分析（2-3人）
└── 合规/品控（1-2人）
```

### 员工号人设设计

| 人设类型 | 适用场景 | 头像风格 | 朋友圈风格 |
|---------|---------|---------|-----------|
| 品牌顾问 | 高客单价、专业服务 | 职业照 | 专业知识+案例分享 |
| 福利官 | 促销导向、高频消费 | 品牌IP形象 | 福利预告+限时活动 |
| 专属客服 | 售后服务、客户维护 | 亲和力真人照 | 使用技巧+用户反馈 |
| 创始人IP | 品牌故事、信任背书 | 创始人真人照 | 品牌理念+幕后故事 |
| 专家KOC | 知识付费、咨询类 | 专业形象照 | 行业洞察+干货分享 |

### 员工号管理规范

- 每个员工号好友上限建议控制在 5000 以内（企微上限 2 万，但管理效率在 5000 时最优）
- 朋友圈发布频率：每天 1-3 条，避免刷屏
- 朋友圈内容比例：价值内容 60% + 产品种草 25% + 促销信息 15%
- 名片信息完整：头像+昵称+签名+电话+地址

## 2. 渠道活码类型和配置

### 活码类型详解

**员工活码（个人码）**
- 支持多个员工轮流接待，自动均分流量
- 可设置添加上限，达到上限自动切换下一个员工
- 适用于：1对1 场景（高客单、需求咨询、售后）

**群活码**
- 支持多个群轮流承接，单群满员自动切换
- 群满员阈值建议设为 180 人（200 人上限留 buffer）
- 适用于：批量引流场景（活动引流、直播引流）

**渠道活码（带参数）**
- 每个渠道生成独立活码，自动追踪来源
- 支持关联自动标签和欢迎语
- 适用于：多渠道引流归因

### 各渠道活码配置指南

**包裹卡**
```yaml
渠道: 包裹卡
活码类型: 员工活码
承接员工: 福利官人设
欢迎语: |
  Hi~ 我是{品牌}的专属福利官{名字}
  感谢你购买{产品}，给你准备了一份老客专属福利
  回复「1」领取 →
自动标签:
  - 来源:包裹卡
  - 消费:已购客户
设计要点:
  - 卡片尺寸：名片大小（90x54mm）或明信片大小
  - 必须有明确的利益点（不是"扫码加好友"，而是"扫码领XX元红包"）
  - 二维码大小不小于 2cm x 2cm
  - 加好友转化率基准：3-8%
```

**直播间**
```yaml
渠道: 直播间
活码类型: 群活码
承接群: 直播福利群
欢迎语: |
  欢迎进入{品牌}直播福利群！
  直播专属优惠将在群内发放 →
  群内还有不定期的秒杀和抽奖活动
自动标签:
  - 来源:直播
  - 偏好:直播购物
设计要点:
  - 直播间口播+贴片引导
  - 限时限量制造紧迫感
  - 加群转化率基准：5-15%
```

**门店**
```yaml
渠道: 门店
活码类型: 员工活码
承接员工: 对应门店员工
欢迎语: |
  你好呀~ 我是{门店名}的{名字}
  以后有任何问题都可以找我
  先送你一张会员专属券 →
自动标签:
  - 来源:门店
  - 来源:门店_{门店编号}
设计要点:
  - 收银台立牌/桌贴
  - 结合买单优惠引导扫码
  - 加好友转化率基准：15-30%
```

**短信召回**
```yaml
渠道: 短信
活码类型: 员工活码
承接员工: 专属客服
欢迎语: |
  终于等到你回来啦 {昵称}~
  好久不见，给你准备了一份回归礼
  回复「领取」即可获得 →
自动标签:
  - 来源:短信召回
  - 生命周期:沉睡回流
设计要点:
  - 短信内嵌短链+活码落地页
  - 强调"专属""老客"等身份认同
  - 加好友转化率基准：1-3%
```

## 3. 客户标签体系设计方法论

### 四维标签框架

标签体系是私域精细化运营的核心基础设施。设计不好的标签体系比没有标签更糟糕——它会产生错误的运营决策。

#### 维度一：来源标签（Where）

追踪用户从哪里来，用于渠道 ROI 分析。

| 一级标签 | 二级标签示例 | 打标方式 |
|---------|------------|---------|
| 渠道来源 | 包裹卡/直播/门店/广告/自然/老带新 | 渠道活码自动 |
| 首次触点 | 具体活动名/页面名/员工号 | 渠道活码自动 |
| 首次时间 | 加好友日期 | 系统自动 |

#### 维度二：消费标签（What）

追踪用户买了什么、花了多少，用于消费分层和选品推荐。

| 一级标签 | 二级标签示例 | 打标方式 |
|---------|------------|---------|
| 消费层级 | 未购/首购/复购/高价值 | 订单数据同步 |
| 客单价区间 | 0/1-99/100-299/300+ | 订单数据同步 |
| 品类偏好 | 具体品类名（如护肤/彩妆/身体护理） | 订单数据同步 |
| RFM 评分 | R(最近)/F(频率)/M(金额)组合 | 定期计算更新 |

#### 维度三：生命周期标签（When）

追踪用户处于哪个阶段，用于差异化触达策略。

| 一级标签 | 定义 | 打标方式 |
|---------|------|---------|
| 新客 | 加好友 0-7 天 | 时间自动计算 |
| 成长期 | 加好友 7-30 天 | 时间自动计算 |
| 成熟期 | 加好友 30-90 天且有购买 | 时间+订单联合判断 |
| 沉睡期 | 90 天内无互动无购买 | 行为数据自动检测 |
| 流失 | 删除好友/180天无任何行为 | 系统检测 |

#### 维度四：偏好标签（How）

追踪用户的行为习惯和偏好，用于内容推荐和触达时机。

| 一级标签 | 二级标签示例 | 打标方式 |
|---------|------------|---------|
| 内容偏好 | 种草型/促销型/知识型/互动型 | 点击行为分析 |
| 互动水平 | 高互动/中互动/低互动/潜水 | 消息回复率计算 |
| 活跃时段 | 早间(7-9)/午间(12-14)/晚间(20-22) | 互动时间统计 |
| 社群活跃 | 核心成员/活跃成员/潜水成员/僵尸 | 群内行为统计 |

### 标签管理原则

1. **少即是多**：初期标签不超过 30 个，避免标签泛滥导致无法管理
2. **自动优先**：能自动打标的绝不手动，手动标签误差大且不可持续
3. **定期清洗**：每月检查标签覆盖率和准确率，清理无效标签
4. **权限分级**：核心标签（如消费层级）只允许系统打标，不允许手动修改

## 4. SCRM 工具对比

### 主流工具详细对比

**微伴助手**
- 定位：轻量级全功能 SCRM
- 核心优势：免费版功能够用、上手快、生态完善
- 核心功能：渠道活码、自动标签、群 SOP、客户画像、数据看板
- 适合：初创期团队（好友<3万）、预算有限（免费-1万/年）
- 短板：高级自动化和定制化能力一般

**尘锋 SCRM**
- 定位：销售驱动型 SCRM
- 核心优势：销售漏斗管理强、跟进提醒完善、销售话术库
- 核心功能：线索分配、销售跟进、智能话术、会话质检、业绩报表
- 适合：有销售团队的品牌（好友3-30万）、预算1-5万/年
- 短板：社群运营功能相对薄弱

**微盛**
- 定位：社群管理专家
- 核心优势：群运营能力强、群 SOP 自动化、群活码管理
- 核心功能：社群雷达、群 SOP、群活码、群数据分析、自动入群
- 适合：社群密集型业务（社群>50个）、预算5k-3万/年
- 短板：1对1 私聊和销售管理较弱

**句子互动**
- 定位：技术驱动型 SCRM
- 核心优势：自动化流程强、API 开放、可深度定制
- 核心功能：RPA 自动化、智能路由、API 对接、自定义工作流
- 适合：有技术团队的品牌、需要深度定制、预算定制报价
- 短板：上手成本高，需要技术支持

### 选型决策树

```
Q1: 预算 < 1万/年？
├── 是 → 微伴助手（免费版 or 基础版）
└── 否 → Q2

Q2: 核心需求是销售跟进还是社群运营？
├── 销售跟进 → 尘锋 SCRM
├── 社群运营 → 微盛
└── 两者都要 → Q3

Q3: 有技术团队支持？
├── 是 → 句子互动（定制化）
└── 否 → 尘锋（综合能力更均衡）
```

## 5. 会话存档合规要求

### 法律依据

- 《个人信息保护法》(PIPL) 2021年11月1日施行
- 《网络安全法》
- 企业微信官方会话存档接口规范

### 合规要点

1. **告知义务**：必须明确告知用户会话内容会被存档，并获得同意
2. **同意获取**：
   - 内部员工：劳动合同/员工手册中明确
   - 外部客户：加好友时弹出存档提醒，客户需点击同意
3. **数据安全**：
   - 会话数据加密存储
   - 访问权限严格控制（仅合规/质检人员可查看）
   - 数据保存期限不超过必要期限
4. **使用限制**：
   - 仅用于合规审计和服务质量管理
   - 不得用于非法目的或超范围使用
   - 员工离职后及时处理相关数据

### 企微会话存档配置步骤

1. 管理员在企微后台开通会话存档功能
2. 配置存档范围（哪些员工的会话需要存档）
3. 设置外部联系人提醒文案（合规告知）
4. 对接 SCRM 系统的会话存档 API
5. 配置数据加密密钥和访问权限

## 6. 离职继承和在职转移配置

### 离职继承

当员工离职时，其企微好友和群聊需要平稳转移：

**配置要点：**
- 在企微后台设置离职继承规则
- 指定继承人（优先同部门同角色员工）
- 自定义继承通知文案（告知客户换人了，不要用默认文案）
- 继承后 24 小时内由新员工主动打招呼

**继承通知文案模板：**
```
你好，我是{品牌}的{新员工名}
之前服务你的{旧员工名}已调岗，后续由我来为你服务
你之前的所有权益和记录都完整保留
有任何问题随时找我 😊
```

### 在职转移

当客户需要更换服务人员时（如升级为 VIP 专属客服）：

**配置要点：**
- 需要原员工和新员工双方确认
- 客户会收到系统通知
- 转移后聊天记录不会丢失（但会话存档需重新授权）
- 标签和备注信息完整转移

### 关键风险防范

- 员工离职前批量导出客户信息 → 设置数据导出权限
- 员工带走客户 → 合同约定竞业禁止+客户归属权
- 继承后客户大量流失 → 提前做好过渡，继承前后密切关注删除率
