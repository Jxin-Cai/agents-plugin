# 用户生命周期原则

本文档定义了用户生命周期管理必须遵循的原则和实战方法论。用这些原则检验生命周期方案的精准性和可执行性。

---

## 1. 各阶段关键行为指标

### 阶段划分与核心指标

**新客阶段（0-7天）**

| 指标 | 定义 | 基准 | 优秀 |
|------|------|------|------|
| 首日互动率 | 加好友24h内有消息互动 | >40% | >60% |
| 7天首购率 | 7天内完成首次购买 | >15% | >20% |
| 7天留存率 | 7天后未删除好友 | >75% | >85% |
| 欢迎语回复率 | 收到欢迎语后回复的比例 | >25% | >40% |
| 社群入群率 | 被邀请后实际入群比例 | >50% | >70% |

**成长阶段（7-30天）**

| 指标 | 定义 | 基准 | 优秀 |
|------|------|------|------|
| 二次购买率 | 首购后30天内再次购买 | >10% | >15% |
| 社群活跃率 | 7天内有互动行为 | >30% | >40% |
| 消息打开率 | 私聊消息的打开比例 | >35% | >50% |
| 标签完善率 | 核心标签（4维度）覆盖比例 | >60% | >80% |
| 朋友圈互动率 | 对品牌朋友圈点赞/评论 | >5% | >10% |

**成熟阶段（30-90天）**

| 指标 | 定义 | 基准 | 优秀 |
|------|------|------|------|
| 复购频率 | 月均购买次数 | >1次/月 | >2次/月 |
| 客单价趋势 | 客单价环比变化 | 持平 | 上升>10% |
| 交叉购买率 | 购买过2+品类的比例 | >20% | >30% |
| NPS得分 | 净推荐值 | >30 | >50 |
| 推荐转化 | 推荐好友成功加入私域 | >3% | >5% |

**沉睡阶段（90+天）**

| 指标 | 定义 | 基准 | 优秀 |
|------|------|------|------|
| 唤醒率 | 沉睡用户被成功激活的比例 | >8% | >15% |
| 唤醒后复购率 | 被唤醒用户30天内购买 | >10% | >20% |
| 流失率 | 最终删除好友/180天无行为 | <15%/月 | <8%/月 |

## 2. 自动化触达时机和内容设计

### 触达的黄金原则

1. **有理由再触达** — 每次触达必须有明确的理由（时间节点/行为触发/价值传递），不能为了触达而触达
2. **频率控制** — 同一用户每天最多被触达2次（私聊1次+社群/朋友圈1次），一周不超过5次私聊
3. **时段选择** — 最佳触达时段按优先级：20:00-21:30 > 12:00-13:00 > 10:00-11:00，避免早于8:00和晚于22:00
4. **内容递进** — 触达内容应随关系深度递进：关怀→价值→引导→促成，不要跳跃

### 行为触发式自动化规则

**新客阶段触发规则**

### 内容模板设计原则

| 场景 | 语气 | 长度 | 关键要素 |
|------|------|------|---------|
| 欢迎语 | 热情亲切 | 50-100字 | 自我介绍+价值承诺+行动引导 |
| 关怀跟进 | 真诚关心 | 30-60字 | 提问式开头+不推销 |
| 产品推荐 | 专业种草 | 80-150字 | 场景痛点+产品方案+社会证明 |
| 优惠触发 | 紧迫直接 | 40-80字 | 专属感+限时限量+行动按钮 |
| 唤醒话术 | 温暖+稀缺 | 60-100字 | 关怀开头+专属福利+低门槛 |

## 3. 沉睡唤醒策略（30/45/60/90天分级）

### 唤醒的核心逻辑

沉睡唤醒不是骚扰用户，而是「最后的好意」。策略的核心是：**力度递增、频率递减、尊重选择**。

### 30天级唤醒（轻度沉睡）

**触达方式：** 朋友圈精准可见

**策略：** 不主动打扰，通过朋友圈内容自然触达

```
内容方向：
- 用户可能感兴趣的新品/新活动
- 与用户标签匹配的种草内容
- 限时优惠信息（设置为仅该用户可见）

不要做：
- 直接私聊推销
- 群发消息
```

### 45天级唤醒（中度沉睡）

**触达方式：** 1对1 私聊

**策略：** 真诚关怀为主，附带回归福利

```
话术模板：
"Hi {昵称}，好久不联系了～
最近怎么样呀？有什么我能帮到你的吗？
对了，给你留了一份老朋友专属福利 →
{福利详情}
不感兴趣也没关系，随时找我聊天 😊"

福利设计：
- 无门槛优惠券（5-10元，降低回归门槛）
- 限时72小时有效
```

### 60天级唤醒（重度沉睡）

**触达方式：** 私聊 + 短信双触达

**策略：** 加大力度，制造稀缺性

```
私聊话术：
"{昵称}，我发现你好久没来看看了
给你准备了一个超值回归礼包，全场通用 →
仅限48小时，过期就没有啦
{礼包详情}"

短信模板（控制在70字内）：
"【{品牌}】{昵称}你好，好久不见！
专属回归礼：满{X}减{Y}，仅48h有效
领取→ {短链}"

福利设计：
- 大额满减券（满100减30/满200减60）
- 限时48小时
- 短信+私聊双触达
```

### 90天级唤醒（极度沉睡/最后触达）

**触达方式：** 私聊（最后一次）

**策略：** 真诚告别，给用户体面

```
话术模板：
"{昵称}，这是我最后一次打扰你了
如果你不需要了，完全理解 ☺️
走之前给你留了一份告别礼：{福利详情}
以后想回来的话，随时加我就好～"

福利设计：
- 力度最大的优惠（可以是亏本引流品）
- 有效期7天（给足时间考虑）
- 这是最后一次，之后不再主动触达
```

### 唤醒后处理

- 唤醒成功 → 重新进入对应阶段，更新生命周期标签
- 唤醒失败（4次都无响应） → 标记为「沉默好友」，只通过朋友圈被动触达，不再主动打扰
- 用户主动回应"不需要了" → 礼貌告别，标记为「主动拒绝」，永不再触达

## 4. 流失预警模型特征

### 特征工程

构建流失预警模型需要关注以下特征维度：

**行为特征（权重最高）**

| 特征 | 计算方式 | 预警阈值 |
|------|---------|---------|
| 30天消息打开量 | 最近30天打开私聊消息的次数 | <3次 |
| 消息打开率变化 | (本月打开率-上月打开率)/上月打开率 | 下降>50% |
| 社群互动频率变化 | (本周互动-上周互动)/上周互动 | 下降>60% |
| 朋友圈互动频率 | 最近30天对品牌朋友圈的点赞/评论 | 从有到无 |
| 小程序访问频率 | 最近30天访问小程序/商城的次数 | <1次 |

**交易特征（权重高）**

| 特征 | 计算方式 | 预警阈值 |
|------|---------|---------|
| 最近购买距今天数 | today - last_purchase_date | >产品使用周期*2 |
| 购买频率变化 | (近3月频率-前3月频率)/前3月频率 | 下降>50% |
| 客单价变化 | (近3月客单价-前3月客单价)/前3月客单价 | 下降>30% |
| 优惠券使用率 | 近30天发放的优惠券使用比例 | 从使用到不使用 |

**服务特征（权重中）**

| 特征 | 计算方式 | 预警阈值 |
|------|---------|---------|
| 未解决投诉 | 30天内有投诉且未关闭的数量 | >0 |
| 差评/退货 | 最近60天内差评或退货次数 | >1次 |
| 客服响应满意度 | 最近一次客服评价 | <3分（5分制） |

### 评分卡模型

```python
# 简化版流失预警评分卡
def calculate_churn_risk_score(user):
    score = 0
    
    # 行为特征（满分40分）
    if user.msg_open_count_30d < 3:
        score += 15
    if user.msg_open_rate_change < -0.5:
        score += 10
    if user.community_interaction_change < -0.6:
        score += 10
    if user.moments_interaction_30d == 0 and user.moments_interaction_60d > 0:
        score += 5
    
    # 交易特征（满分40分）
    if user.days_since_last_purchase > user.product_cycle * 2:
        score += 20
    if user.purchase_frequency_change < -0.5:
        score += 10
    if user.avg_order_value_change < -0.3:
        score += 5
    if user.coupon_usage_rate_30d == 0 and user.coupon_usage_rate_60d > 0:
        score += 5
    
    # 服务特征（满分20分）
    if user.open_complaints > 0:
        score += 15
    if user.negative_reviews_60d > 1:
        score += 5
    
    return score

# 预警等级
# 0-30: 正常（绿色）
# 31-50: 关注（黄色预警）→ 自动推送关怀内容
# 51-70: 危险（橙色预警）→ 客服1对1跟进
# 71-100: 极度危险（红色预警）→ 运营经理亲自处理
```

## 5. 手动干预触发条件

并非所有场景都适合自动化，以下情况需要人工介入：

### 必须手动干预的场景

| 场景 | 触发条件 | 干预人 | 干预动作 |
|------|---------|--------|---------|
| 大额客户沉睡 | 累计消费>5000元 + 30天无互动 | 运营经理 | 电话回访+专属方案 |
| 投诉升级 | 投诉未解决>48h 或 二次投诉 | 客服主管 | 优先处理+补偿方案 |
| KOC流失预警 | 超级用户群成员30天互动下降>50% | 私域负责人 | 1对1深度沟通 |
| 批量流失 | 同一渠道/社群短时间内删除好友>5% | 运营团队 | 排查原因+紧急调整 |
| 竞品挖角 | 用户提及正在使用竞品 | 运营专员 | 差异化价值沟通 |

### 手动干预的执行原则

1. **24小时响应** — 触发手动干预后，必须在24小时内执行
2. **先听后说** — 不要上来就给方案，先了解用户真实原因
3. **有权决策** — 干预人需要有一定的优惠/补偿决策权限
4. **记录闭环** — 干预过程和结果必须记录，用于优化自动化规则
5. **复盘迭代** — 每月复盘手动干预案例，将可标准化的场景转为自动化
