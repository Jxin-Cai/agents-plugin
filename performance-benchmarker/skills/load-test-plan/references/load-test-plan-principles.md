# 负载测试计划原则

基于 Google SRE、Brendan Gregg 方法论、ISTQB 性能测试指南。

---

## 1. 五阶段递进测试模型

| 阶段 | 目的 | 负载 | 关注指标 | 产出 |
|------|------|------|---------|------|
| Baseline | 建立正常负载基线 | 日常 50%-100% | P50/P95/P99、吞吐量、资源利用率 | 基线报告 |
| Load | 验证峰值下 SLO 达标 | 预期峰值 100% | SLO 达标率、错误率、资源趋势 | SLO 达标评估 |
| Stress | 找性能拐点和崩溃点 | 峰值 → 崩溃 | 拐点、降级行为、错误类型 | 容量上限 |
| Spike | 验证突发流量应对 | 瞬间跳至峰值 200%-500% | 扩缩容响应、排队行为、熔断触发 | 弹性评估 |
| Soak | 发现内存泄漏/资源耗尽 | 70%-80% 持续 4-24h | 内存趋势、连接池泄漏、GC 变化 | 稳定性评估 |

## 2. 工作负载建模

- **开放模型**：新用户固定速率到达，不受响应影响——适用公网 API
- **闭合模型**：固定并发数，等响应后发下一请求——适用内部系统
- 模型选错导致测试结果偏差 30%-300%
- 场景权重：从生产日志提取 Top 10 API 比例，区分读写（典型 80:20）
- 包含关联操作链（登录→浏览→加购→下单→支付）和后台任务影响
- 测试数据：脱敏生产数据或等价合成数据，量级与生产一致，预热缓存后测试

## 3. SLI/SLO/SLA 体系

**SLI 选择**：

| 类别 | SLI | 测量方式 |
|------|-----|---------|
| 可用性 | 成功请求占比 | (总请求 - 5xx) / 总请求 |
| 延迟 | 响应时间百分位 | P50/P95/P99 |
| 吞吐量 | RPS | 固定窗口内请求计数 |
| 错误率 | 业务错误占比 | 业务错误 / 总请求 |
| 饱和度 | 资源利用率 | CPU/内存/连接池使用率 |

**SLO 格式**：`[SLI] [目标值] [时间窗口] [测量条件]`
- 示例：API P99 < 200ms，30 天滚动，排除维护时段
- 错误预算：99.9% = 每月允许 43 分钟不可用

**SLA**：对外承诺，阈值宽于 SLO（SLO=99.95% → SLA=99.9%），含违约后果

## 4. 测试环境管控

- 硬件与生产同规格或等比缩放（标注比例），中间件版本完全一致
- 网络拓扑模拟真实延迟和带宽，数据量级与生产同量级
- 测试环境与生产完全隔离，外部依赖 Mock/Stub（标注行为差异）

## 5. 工具选型

| 工具 | 适用场景 | 脚本语言 | 分布式 |
|------|---------|---------|--------|
| k6 | API/微服务 | JavaScript | 原生 |
| Gatling | 高并发/CI-CD | Scala/Java | 原生 |
| JMeter | 多协议/GUI | XML/Groovy | 原生 |
| Locust | Python 生态 | Python | 原生 |
| Artillery | Serverless/Node | YAML/JS | 云原生 |
| wrk/wrk2 | HTTP 快速验证 | Lua | 单机 |

选型：优先团队已有经验 → CI/CD 集成能力 → 分布式生成能力

## 6. 结果分析

- **延迟分布**：看百分位不看均值（P50 正常但 P99 飙升 = 长尾问题）
- **吞吐量曲线**：随并发是否线性？拐点在哪？
- **错误率**：分类——超时 vs 拒绝 vs 业务错误
- **资源关联**：性能指标与 CPU/内存/磁盘/网络做时间轴对齐

**异常模式**：线性恶化=资源争用 | 阶梯跳变=阈值触发 | 周期波动=GC/定时任务 | 渐进退化=泄漏
