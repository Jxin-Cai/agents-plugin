# 综合审查报告模板

> 用于 full-review workflow 完成后合并各阶段产出

## 报告结构

```
# 综合代码审查报告

## 审查概况
| 项目 | 内容 |
|------|------|
| 审查目标 | {目标描述} |
| 审查日期 | {日期} |
| 技术栈 | {语言/框架} |
| 代码规模 | {文件数} 文件 / {行数} 行 |
| Workflow | {执行的 workflow} |

## 风险总览
| 类别 | Blocker/Critical | High/Major | Medium/Minor | Low |
|------|-------------------|------------|-------------|-----|
| 安全 | {n} | {n} | {n} | {n} |
| 质量 | {n} | {n} | {n} | - |
| 重构 | {n} | {n} | {n} | - |

## 安全审查摘要
{从 security-report 提取关键发现，每项一行}

## 质量审计摘要
{六维度评级表 + 关键问题}

## 重构建议摘要
{优先级分布 + 立即做列表}

## 行动建议
1. 紧急（阻断发布）：{Critical/Blocker 问题}
2. 本迭代必须解决：{High/Major 问题}
3. 近期规划：{Medium 问题 + 重构计划}
```

## 填充规则

1. 从各阶段报告文件中提取数据，不重新分析代码
2. 风险总览数字必须与各阶段报告一致
3. 摘要部分只取关键发现（每类最多 5 项）
4. 行动建议按紧急程度排序，附文件路径方便定位
5. 报告保存到 `{工作目录}/review-summary-{日期}.md`
