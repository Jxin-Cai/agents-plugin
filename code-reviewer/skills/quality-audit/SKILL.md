# 质量审计

以架构师视角从六个维度全面评估代码健康度。不只找问题，更帮助开发者理解什么是好代码。

用户传入的参数：`$ARGUMENTS`

---

## Step 0: 前置条件

1. 确定工作目录：检查 `_code-review/` 下最近的日期目录，若无则创建
2. 存在 `meta/review-state.md` 时 Read 并确认当前阶段
3. Read `context/scope.md`（如存在）获取审查范围
4. 加载已有安全审查产出（如存在 `security/` 目录）
5. 确定目标代码并加载，优先加载核心业务文件

---

## Step 1: 代码概览与结构分析

Read `references/quality-audit-principles.md`

快速浏览目标代码，建立整体画像：

1. 规模统计：文件数、总行数、平均文件行数
2. 结构分析：模块划分、层次结构、入口点
3. 技术栈识别：语言、框架、设计模式
4. 依赖关系：主要内部/外部依赖

用 `AskUserQuestion` 展示概览，确认审计重点。

---

## Step 2: 六维度质量评估

按 `references/quality-audit-principles.md` 的六维度模型逐项评估：

| 维度 | 核心关注 |
|------|---------|
| 可靠性 | 错误处理、空值安全、边界条件、资源管理 |
| 可维护性 | 命名质量、函数长度、注释质量、代码组织 |
| 复杂度 | 圈复杂度 >10、嵌套 >3 层、过度抽象 |
| 重复度 | 克隆代码 >6 行、结构重复模式 |
| 耦合与内聚 | 循环依赖、职责单一性、模块间依赖 |
| 可测试性 | 测试覆盖、可测试设计、依赖注入 |

每个维度给出 A-E 评级和具体度量数值。每完成 2 个维度后展示中间结果。

---

## Step 3: 代码坏味道识别

对照 `references/quality-audit-principles.md` 坏味道速查表，记录每个发现：

| 字段 | 要求 |
|------|------|
| 坏味道类型 | 具体名称（如"上帝类""长函数"） |
| 位置 | 文件路径 + 行号范围 |
| 度量数值 | 具体数字（如"函数 72 行""圈复杂度 18"） |
| 严重程度 | Blocker / Major / Minor |
| 影响 | 导致什么具体问题 |

---

## Step 4: 生成质量报告

保存结构化报告到 `{工作目录}/quality/quality-report-{日期}.md`。

更新 `meta/review-state.md`（质量审计阶段 = done）。

报告包含：六维度评级总览 + 综合评级 + 问题清单(Blocker/Major/Minor) + 改进路线图(短期/中期/长期)。

---

## Step 5: 门控确认

使用 `AskUserQuestion` 展示：

> 综合评级 [{等级}]。Blocker [a] 个，Major [b] 个，Minor [c] 个。最需关注：[{维度}]。

选项：进入重构建议 / 深入某个维度 / 对比行业标准 / 结束审查

---

<IMPORTANT>
## 质量硬门控

- 绝不在没有阅读代码的情况下给出质量评估
- 每个问题必须给出具体度量数值，禁止模糊描述（如"比较复杂"）
- 六维度必须全部评估完成，不得遗漏
- 综合评级取各维度最低等级，任一维度 D/E 时综合评级不得高于 C
- 不到用户确认，不进入下一步
- 不确定时声明不确定，禁止猜测指标数值
</IMPORTANT>
