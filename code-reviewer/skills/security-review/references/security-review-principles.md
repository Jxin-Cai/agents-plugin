# 安全审查原则

> 基于 OWASP Top 10（2021）、OWASP Code Review Guide v2.0、Google 安全工程实践

---

## 1. OWASP Top 10 检查框架

每次审查必须覆盖全部 10 个类别，不适用的标注 N/A 并说明原因。

| 类别 | 关键检查项 |
|------|-----------|
| **A01: 访问控制失效** | 水平/垂直越权、API 权限校验（勿仅依赖前端）、最小权限默认拒绝、CORS 配置、路径穿越 |
| **A02: 加密失败** | 敏感数据明文传输/存储、过时算法(MD5/SHA1/DES)、硬编码密钥、TLS/HTTPS 强制、安全随机源 |
| **A03: 注入** | SQL 参数化查询/ORM、OS 命令注入、SSTI 模板注入、LDAP/XPath/NoSQL 注入、输入验证与转义 |
| **A04: 不安全设计** | 威胁建模、业务逻辑漏洞(竞态/重放)、速率限制、纵深防御 |
| **A05: 安全配置错误** | 默认凭据/调试端口暴露、错误信息泄露内部细节、HTTP 安全头(CSP/HSTS)、无用功能禁用 |
| **A06: 脆弱组件** | 已知 CVE 漏洞、不再维护的库、版本固定(lock file)、自动依赖扫描 |
| **A07: 认证失败** | 密码策略/MFA、会话令牌安全、登录频率限制、令牌过期/刷新 |
| **A08: 完整性失败** | CI/CD 完整性校验、反序列化类型白名单、自动更新签名验证 |
| **A09: 日志监控失败** | 安全事件记录、日志上下文充分性、日志脱敏、异常告警机制 |
| **A10: SSRF** | 用户可控 URL/IP、出站请求白名单、内网地址/元数据端点过滤 |

## 2. 风险等级分类

| 等级 | 定义 | 处置要求 |
|------|------|---------|
| **Critical** | 可被远程利用，导致数据泄露或系统沦陷 | 必须立即修复，阻断发布 |
| **High** | 可被利用但需要一定条件 | 必须在本次迭代内修复 |
| **Medium** | 存在风险但利用难度较高 | 近期修复，记录为技术债 |
| **Low** | 最佳实践偏离，不构成直接风险 | 建议改进，不阻断发布 |

## 3. 安全检查清单

每次审查必须覆盖（不适用时标注 N/A）：

- [ ] 输入验证：所有外部输入是否经过验证？
- [ ] 输出编码：输出到浏览器/日志/其他系统时是否正确编码？
- [ ] 认证：身份验证机制是否健全？
- [ ] 授权：访问控制是否正确实施？
- [ ] 会话管理：会话是否安全管理？
- [ ] 加密：敏感数据是否正确加密？
- [ ] 错误处理：错误是否安全处理（不泄露信息）？
- [ ] 日志：安全事件是否被正确记录？
- [ ] 依赖：第三方组件是否安全？
- [ ] 配置：安全配置是否正确？

## 4. 语言/框架特定关注点

| 技术栈 | 特定关注点 |
|--------|-----------|
| Java/Spring | SpEL 注入、反序列化、Actuator 暴露、JDBC 参数化 |
| Python/Django | ORM 绕过、Pickle 反序列化、DEBUG 模式、CSRF 令牌 |
| Node.js/Express | 原型污染、正则 DoS、不安全 eval、依赖链攻击 |
| Go | 整数溢出、goroutine 泄露、不安全 crypto/rand |
| React/Vue | dangerouslySetInnerHTML/v-html、XSS、敏感数据渲染 |
| SQL | 动态拼接、权限过大的数据库用户、未加密连接 |
