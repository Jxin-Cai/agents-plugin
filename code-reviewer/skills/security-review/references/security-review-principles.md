# 安全审查原则

本文档定义了安全审查阶段必须遵循的原则。基于 OWASP Top 10（2021）、OWASP Code Review Guide v2.0 和 Google 安全工程实践。

---

## 1. OWASP Top 10 逐项检查框架

每次安全审查必须覆盖 OWASP Top 10 的全部类别，按风险从高到低排序：

### A01: 访问控制失效（Broken Access Control）
- 是否存在越权访问？（水平越权：用户 A 访问用户 B 的数据；垂直越权：普通用户执行管理员操作）
- API 接口是否有权限校验？是否仅依赖前端控制？
- 是否遵循最小权限原则？默认拒绝，显式授权
- CORS 配置是否过于宽松？
- 目录遍历和路径穿越是否被防护？

### A02: 加密失败（Cryptographic Failures）
- 敏感数据（密码、密钥、PII）是否以明文传输或存储？
- 是否使用了过时的加密算法（MD5、SHA1、DES）？
- 密钥是否硬编码在代码中？
- TLS 配置是否正确？是否强制 HTTPS？
- 随机数生成是否使用安全随机源？

### A03: 注入（Injection）
- SQL 查询是否使用参数化查询或 ORM？
- 是否存在 OS 命令注入风险？
- 模板引擎是否有 SSTI（服务端模板注入）风险？
- LDAP、XPath、NoSQL 注入是否被考虑？
- 所有外部输入是否经过验证和转义？

### A04: 不安全设计（Insecure Design）
- 是否有威胁建模？关键业务流程是否考虑了滥用场景？
- 是否存在业务逻辑漏洞（如竞态条件导致的超卖、重放攻击）？
- 关键操作是否有速率限制？
- 是否遵循纵深防御原则（不依赖单一安全控制）？

### A05: 安全配置错误（Security Misconfiguration）
- 是否暴露了默认凭据、调试端口、管理界面？
- 错误信息是否泄露了内部实现细节（堆栈跟踪、SQL 语句）？
- HTTP 安全头是否正确配置（CSP、X-Frame-Options、HSTS）？
- 不必要的功能、端口、服务是否已禁用？

### A06: 脆弱和过时的组件（Vulnerable & Outdated Components）
- 依赖是否有已知 CVE 漏洞？
- 是否使用了不再维护的库？
- 依赖版本是否固定（lock file）？
- 是否有自动依赖扫描机制？

### A07: 身份认证和会话管理失败（Identification & Authentication Failures）
- 密码策略是否合理？是否支持 MFA？
- 会话令牌是否安全生成、安全存储？
- 登录失败是否有频率限制？是否泄露用户存在信息？
- 令牌过期和刷新机制是否正确？

### A08: 软件和数据完整性失败（Software & Data Integrity Failures）
- CI/CD 流水线是否有完整性校验？
- 反序列化输入是否可信？是否有类型白名单？
- 自动更新是否验证签名？

### A09: 安全日志和监控失败（Security Logging & Monitoring Failures）
- 关键安全事件（登录、权限变更、数据访问）是否被记录？
- 日志是否包含足够的上下文信息用于调查？
- 日志是否泄露了敏感数据（密码、令牌、PII）？
- 是否有告警机制用于检测异常行为？

### A10: 服务端请求伪造（SSRF）
- 是否有用户可控的 URL 或 IP 地址被服务端请求？
- 出站请求是否有白名单限制？
- 内网地址和元数据端点是否被过滤？

## 2. 风险等级分类

审查发现的每个安全问题必须标注风险等级：

| 等级 | 定义 | 处置要求 |
|------|------|---------|
| **Critical** | 可被远程利用，导致数据泄露或系统沦陷 | 必须立即修复，阻断发布 |
| **High** | 可被利用但需要一定条件 | 必须在本次迭代内修复 |
| **Medium** | 存在风险但利用难度较高 | 应在近期修复，记录为技术债 |
| **Low** | 最佳实践偏离，不构成直接风险 | 建议改进，不阻断发布 |

## 3. 安全审查检查清单

每次安全审查必须覆盖以下检查项（即使某些项不适用也需显式标注 N/A）：

- [ ] 输入验证：所有外部输入是否经过验证？
- [ ] 输出编码：输出到浏览器/日志/其他系统时是否正确编码？
- [ ] 认证：身份验证机制是否健全？
- [ ] 授权：访问控制是否正确实施？
- [ ] 会话管理：会话是否安全管理？
- [ ] 加密：敏感数据是否正确加密？
- [ ] 错误处理：错误是否安全处理（不泄露信息）？
- [ ] 日志：安全事件是否被正确记录？
- [ ] 依赖：第三方组件是否安全？
- [ ] 配置：安全配置是否正确？

## 4. 语言/框架特定关注点

根据检测到的技术栈，额外关注：

| 技术栈 | 特定关注点 |
|--------|-----------|
| Java/Spring | SpEL 注入、反序列化、Actuator 暴露、JDBC 参数化 |
| Python/Django | ORM 绕过、Pickle 反序列化、DEBUG 模式、CSRF 令牌 |
| Node.js/Express | 原型污染、正则 DoS、不安全的 eval、依赖链攻击 |
| Go | 整数溢出、goroutine 泄露、不安全的 crypto/rand |
| React/Vue | dangerouslySetInnerHTML/v-html、XSS、敏感数据渲染 |
| SQL | 动态拼接、权限过大的数据库用户、未加密连接 |
