# 系统知识图谱（System Map）

`.e2e-tests/system-map.md` 是跨任务累积的**系统架构加速缓存**。存在时加速扫描和分析决策；缺失时 fallback 到正常扫描——不阻塞任何流程。

## 维护规则

1. **scan-context 回写**：每次扫描完成后，将新发现的服务、调用链、源码映射追加到 system-map。已有条目只更新 `最后验证` 日期，不覆盖。与已有条目冲突时，在变更日志中记录差异
2. **test-runner 回写**：Playwright 探索（路径 C）发现的 API 调用链、实际端点和认证方式，是对 system-map 的**实测验证**。回写时标注 `最后验证` 日期
3. **impact-analysis 读取**：变更影响分析时，读取"源码路径 → 服务/功能映射"和"调用链索引"，推导受影响的测试
4. **人工修正优先**：用户手动修改 system-map 的内容优先级高于自动回写
5. **过期条目可清理**：服务下线/改名时标注 `deprecated`。`deprecated` 超过 180 天的条目可在重建时清除
6. **可从零重建**：当 system-map 内容严重过时或格式不兼容时，可删除整文件从空模板重建。下次 scan-context 执行时会重新填充
7. **缺失不阻塞**：任何读取 system-map 的流程（impact-analysis、scan-context、test-runner、run-suite），如果文件不存在，应 fallback 到直接代码扫描或跳过知识加速步骤，不得报错或阻塞
