## Step 1: 服务依赖链路梳理

引导用户梳理待监控服务的完整依赖链路：

1. **服务基本信息**：
   - 服务名称、部署方式（K8s / VM / Serverless）
   - 技术栈（语言、框架）
   - 流量规模（QPS 量级）

2. **依赖清单**：

| 依赖 | 类型 | 重要性 | 不可用时的影响 |
|------|------|--------|--------------|
| [名称] | 数据库/缓存/服务/队列 | 核心/可降级 | [具体影响描述] |

3. **已有监控现状**：
   - 已经有哪些健康检查？
   - 已经有哪些告警？
   - 有没有过因监控缺失导致的故障？

**如果已有集成测试计划产出：**
- 从中提取服务依赖关系
- 向用户确认是否完整

**⏸️ 等待用户确认后继续。**

## Step 2: 健康检查端点设计

引导用户设计分级健康检查端点：

### 对每个检查级别追问：

| 级别 | 追问 | 目标 |
|------|------|------|
| Liveness | "服务进程存活需要检查什么？有没有可能假死？" | 确定存活检查内容 |
| Readiness | "服务准备好接受流量需要满足什么条件？" | 确定就绪检查范围 |
| Startup | "服务冷启动需要多长时间？有哪些初始化步骤？" | 确定启动检查和超时 |
| Detail | "运维排查问题时需要看到哪些信息？" | 确定详细状态内容 |

### 对每个依赖的检查方式追问：

| 追问 | 目标 |
|------|------|
| "这个依赖检查应该用什么方式？（连接检查/查询/写入）" | 确定检查方法 |
| "检查超时设置多少合理？" | 确定超时阈值 |
| "这个依赖失败时，服务应该标记为不健康还是降级？" | 确定失败影响 |
| "需要连续失败几次才判定为不健康？" | 确定容忍策略 |

**每设计完一个端点，向用户展示响应示例，确认后再继续。**

## Step 3: SLI/SLO 定义

引导用户定义关键服务指标和目标：

### 3.1 识别关键 SLI

对服务的每一类接口追问：

| 追问 | 目标 |
|------|------|
| "这个接口用户最关心的是速度还是准确性？" | 确定首要 SLI |
| "可接受的最大延迟是多少？P50/P95/P99 分别呢？" | 确定延迟目标 |
| "可接受的错误率是多少？" | 确定可用性目标 |
| "业务角度，每月允许多少分钟不可用？" | 确定 SLO 级别 |

### 3.2 SLO 制定

```markdown
### 核心接口 SLO

| 接口 | 可用性 | P50 延迟 | P95 延迟 | P99 延迟 | 错误预算/月 |
|------|--------|---------|---------|---------|-----------|
| [接口A] | 99.9% | <100ms | <500ms | <1s | 43 分钟 |
| [接口B] | 99.5% | <200ms | <1s | <3s | 3.6 小时 |
```

**⏸️ 向用户展示 SLO 方案，等待确认。**

## Step 4: 告警规则设计

基于 SLI/SLO，引导用户设计告警规则：

### 对每个 SLI 追问：

| 追问 | 目标 |
|------|------|
| "什么情况下需要立即通知值班人员？" | 确定 P0/P1 告警条件 |
| "什么情况下只需要发到 IM 群？" | 确定 P2 告警条件 |
| "要检查多久才能确定不是瞬时抖动？" | 确定持续时间窗口 |
| "谁应该收到告警？值班人 / 团队 / 经理？" | 确定通知对象 |
| "收到告警后第一步该做什么？" | 关联 Runbook |

### 告警规则模板

```markdown
### 告警：[服务名]-[指标]-[级别]

**触发条件：** [指标] [操作符] [阈值] 持续 [时长]
**告警级别：** P0 / P1 / P2 / P3
**通知渠道：** [电话 / 短信 / IM / 邮件]
**通知对象：** [值班人 / 团队 / 经理]
**抑制规则：** [更高级别告警触发时抑制]
**自动恢复检测：** [恢复条件]
**Runbook：**
  1. [第一步排查操作]
  2. [第二步排查操作]
  3. [升级条件]
```

**每设计完一组告警规则，向用户展示，确认后继续。**

## Step 5: 合成监控方案

引导用户设计主动探测方案：

| 追问 | 目标 |
|------|------|
| "部署后最关键的 3-5 个接口是什么？" | 确定可用性探测列表 |
| "核心业务流程可以自动化执行吗？" | 确定功能验证场景 |
| "用户主要分布在哪些地域？" | 确定多地域探测点 |
| "探测失败后应该做什么？" | 确定故障响应流程 |

向用户展示合成监控方案，确认后继续。

## Step 6: 保存产出

将健康检查方案保存到 `{工作目录}/health/health-check-{日期}.md`，包含：
- 服务依赖链路图
- 分级健康检查端点设计（含响应示例）
- SLI/SLO 定义
- 告警规则（含 Runbook）
- 合成监控方案
- 监控工具部署建议
