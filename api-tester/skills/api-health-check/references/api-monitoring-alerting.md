# API 监控与告警原则

## 1. 告警策略

### 告警分级

| 级别 | 触发条件 | 通知方式 | 响应时间 |
|------|---------|---------|---------|
| P0-Critical | 服务完全不可用 / 数据丢失 | 电话+短信+IM | 立即 |
| P1-High | 核心功能受损 / SLO 即将突破 | IM+邮件 | 15min |
| P2-Medium | 非核心异常 / 性能退化 | IM | 1h |
| P3-Low | 预警信号 / 趋势异常 | 邮件/Dashboard | 工作时间 |

### 设计原则

- **可操作**：收到告警有明确排查步骤，绑定 Runbook
- **防疲劳**：使用聚合和抑制，不逐请求告警
- **多窗口**：结合短窗口（5min）和长窗口（1h）判断
- **自动恢复**：触发后检测是否恢复，发送恢复通知

### 告警规则模板

每条规则包含：告警名称（服务-指标-级别）、触发条件（指标+阈值+持续时长）、通知渠道、抑制规则、Runbook 链接。

## 2. 合成监控（Synthetic Monitoring）

主动持续从外部探测可用性和性能——不等用户报告，提前发现问题。

| 场景 | 频率 | 内容 |
|------|------|------|
| 可用性探测 | 1min | 关键接口 HTTP 200 |
| 功能验证 | 5min | 核心业务流程端到端 |
| 性能基准 | 15min | 响应时间是否在 SLO 内 |
| SSL 证书 | 每天 | 证书过期时间 |
| DNS 解析 | 5min | 域名解析是否正常 |

**多地域探测**：从用户主要分布地域 + 服务部署地域发起；地域间结果不一致标记为地域性问题。

## 3. 可观测性三支柱

| 支柱 | 方法论 | 关键实践 | 推荐工具 |
|------|--------|---------|---------|
| Metrics | RED（Rate/Errors/Duration）+ USE（资源级） | 请求速率、错误率、延迟分位数 | Prometheus + Grafana |
| Logs | 结构化日志 | JSON 含 traceId/spanId；ERROR=需介入，WARN=关注，INFO=业务事件 | ELK / Loki |
| Traces | 分布式追踪 | 覆盖服务间调用，标注关键 Span | Jaeger / OpenTelemetry |
