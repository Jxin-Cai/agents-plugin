# 集成测试计划原则

## 1. 集成测试分层

| 层级 | 范围 | 方式 | 速度 |
|------|------|------|------|
| 窄集成 | 单服务 + 直接依赖（DB/缓存/队列） | 真实依赖（Testcontainers），Mock 外部服务 | 秒级，CI 常跑 |
| 宽集成 | 多服务协作完成业务流程 | Docker Compose / K8s 测试环境 | 分钟级，发布前跑 |
| E2E 契约验证 | 完整业务流程跨多服务 | 类生产环境，关注关键路径 | 较慢，发布前/定时 |

## 2. 测试数据管理

**黄金法则**：数据自给自足 + 测试后清理 + 测试间隔离

| 策略 | 适用场景 | 隔离方式 |
|------|---------|---------|
| 工厂模式 | 单元/窄集成 | 独立 Schema 或 Testcontainers |
| Fixture/Seed | 宽集成 | 唯一租户 ID |
| Snapshot | 性能基准 | 独立数据库实例 |
| 动态生成 | 契约测试 | 事务内运行，结束回滚 |

## 3. Mock 与真实服务决策

| 场景 | Mock | 真实服务 |
|------|------|---------|
| 外部第三方（支付/短信） | 必须 Mock | 不可控 |
| 内部其他服务 | 契约测试时 | 集成测试时 |
| 数据库/缓存/队列 | 契约测试时 | Testcontainers |

**Mock 工具**：WireMock（REST）/ MockServer（HTTPS 代理）/ Prism（OpenAPI）/ Testcontainers（中间件）

**准确性保证**：Mock 行为与契约一致 → 契约变更时同步更新 → 定期用真实服务验证

## 4. 测试用例设计

### 覆盖分类

| 类型 | 说明 |
|------|------|
| 正向流程 | 核心业务路径（下单 → 支付 → 发货） |
| 异常流程 | 服务不可用、超时、错误码 |
| 降级策略 | 依赖不可用时的降级行为 |
| 边界条件 | 空数据/超大数据/并发/竞争 |
| 数据一致性 | 跨服务操作后最终一致 |

### 用例模板

每个用例必须包含：用例名称、前置条件、触发操作、验证点（响应 + 数据库 + 事件 + 副作用）、清理操作。

## 5. CI/CD 集成

| 阶段 | 内容 | 速度 | 失败策略 |
|------|------|------|---------|
| 代码提交 | 单元 + 契约（消费者端） | <2min | 阻断流水线 |
| 构建后 | 窄集成（Testcontainers） | <5min | 阻断流水线 |
| 发布前 | 契约验证 + can-i-deploy | - | 阻断部署 |
| 测试环境 | 宽集成测试 | <15min | 阻断发布 |
| 部署后 | 冒烟 + 健康检查 | - | 触发回滚 |

## 6. 环境管理

| 环境 | 数据 | 外部依赖 |
|------|------|---------|
| 本地/CI | Testcontainers | Mock |
| 集成测试 | 种子数据 | 沙箱/Mock |
| 预发布 | 脱敏生产数据 | 沙箱 |

**一致性保证**：IaC（Terraform/Helm）+ 容器化 + 配置与代码版本绑定
