# 知识库建设

设计和构建客户自助知识库，包括文章结构、分类体系、文章模板和交互式故障排除流程，让客户能自助解决 60%+ 的常见问题。

## 强制执行规则

1. **知识库文章必须从客户视角出发**——标题是客户会搜索的问题，不是内部术语
2. **每篇文章必须有明确的"下一步"**——要么问题解决，要么引导联系支持
3. **分类体系必须扁平直觉**——最多三级，用户 3 次点击内找到答案
4. **所有文章使用中文撰写**
5. **输出可直接用于内容管理系统的 Markdown 模板**

## Step 1: 知识库文章结构设计

Read `context/business-context.md` 提取产品名称和核心功能。按以下五层递进结构（问题描述→常见原因→分步解决→高级排错→联系支持）设计标准化文章模板，Write 输出到 `kb/article-structure.md`：

### 标准文章结构

```markdown
# {问题标题 — 客户会搜索的自然语言}

> 适用于：{适用产品/版本/场景}
> 最后更新：{日期}

## 问题描述
简明描述客户会遇到的具体症状和表现。

## 常见原因
按概率从高到低列出可能的原因。

## 解决步骤
### 方法一：{最常见的解决方案}
1. 步骤一（附截图/示例）
2. 步骤二
3. 验证：如何确认问题已解决

### 方法二：{备选方案}
...

## 高级排错
如果以上方法未解决，尝试以下步骤：
...

## 仍需帮助？
如果问题依然存在，请 [联系我们的支持团队]，并提供以下信息：
- {需要收集的信息清单}
```

输出文件：`kb/article-structure.md`

## Step 2: 常见问题分类体系

Read `kb/article-structure.md`（Step 1 产出）确认文章结构。若 `tickets/routing-rules.yaml` 存在则 Read 获取工单分类维度。按"互斥/穷尽/均衡/扁平（最多三级）"四原则设计分类框架，Write 输出到 `kb/category-taxonomy.yaml`：

### 推荐分类框架

```
一级分类（按问题性质）
├── 入门指南          # 新用户上手
│   ├── 注册与登录
│   ├── 初始设置
│   └── 快速开始
├── 功能使用          # 产品功能相关
│   ├── {核心功能 A}
│   ├── {核心功能 B}
│   └── {核心功能 C}
├── 账号与安全        # 账号管理
│   ├── 密码与安全
│   ├── 账号设置
│   └── 权限管理
├── 计费与订阅        # 付款相关
│   ├── 套餐与定价
│   ├── 支付问题
│   └── 发票与退款
├── 故障排除          # 技术问题
│   ├── 常见错误
│   ├── 性能问题
│   └── 兼容性
└── 最佳实践          # 进阶使用
    ├── 效率技巧
    ├── 集成指南
    └── 数据管理
```

根据具体产品调整分类，输出文件：`kb/category-taxonomy.yaml`

## Step 3: 文章模板生成

Read `kb/article-structure.md` 和 `kb/category-taxonomy.yaml`（前两步产出）。为三种典型问题类型分别生成详细模板（含标准化标题、必填字段、步骤模板、截图占位符、SEO 关键词、关联文章），Write 输出到 `kb/templates/` 目录：

### 模板 A：技术故障排除
适用于：系统错误、功能异常、性能问题

### 模板 B：账号管理操作
适用于：密码重置、设置变更、权限调整

### 模板 C：计费问题处理
适用于：付款失败、退款申请、套餐变更

每个模板包含：
- 标准化标题格式
- 必填信息字段
- 步骤模板（含截图占位符）
- SEO 关键词建议
- 关联文章推荐

输出文件：`kb/templates/` 目录下分别输出

## Step 4: 交互式故障排除流程

Read `kb/category-taxonomy.yaml` 提取 Top 3 高频复杂问题分类。为每个高频问题设计决策树式排除流程（是/否分支→子分支→解决/升级），Write 输出到 `kb/troubleshooting-flows.yaml`：

```
用户报告问题
  ├── 是否能登录？
  │   ├── 否 → 登录故障排除分支
  │   └── 是 → 继续
  │       ├── 哪个功能出问题？
  │       │   ├── 功能 A → A 排除分支
  │       │   ├── 功能 B → B 排除分支
  │       │   └── 其他 → 通用排除
  │       └── 是否有错误提示？
  │           ├── 是 → 按错误码查找
  │           └── 否 → 症状描述匹配
  └── 问题已解决？
      ├── 是 → 反馈"有帮助"
      └── 否 → 引导联系支持
```

输出文件：`kb/troubleshooting-flows.yaml`

## Step 5: 自助资源优化

Read `kb/article-structure.md` 和 `kb/category-taxonomy.yaml` 获取知识库整体结构。针对搜索优化（同义词映射、热门置顶、无结果引导）、文章推荐（上下文帮助、智能推荐）、效果评估（有用率、跳出率、工单转化率）三个维度制定策略，Write 输出到 `kb/optimization-strategy.md`：

1. **搜索优化**
   - 关键词同义词映射
   - 热门搜索置顶
   - 搜索无结果引导

2. **文章推荐**
   - 产品内嵌上下文帮助
   - 相关文章智能推荐
   - 基于用户行为的个性化推荐

3. **效果评估**
   - 文章有用/无用投票
   - 阅读后工单创建率
   - 搜索→阅读→解决转化漏斗

输出文件：`kb/optimization-strategy.md`

## 成功指标

- [ ] 文章结构标准化，新文章可在 30 分钟内按模板完成
- [ ] 分类体系覆盖 90%+ 高频问题
- [ ] 故障排除流程覆盖 Top 3 复杂问题

## 失败指标

- 文章标题使用内部术语而非客户语言
- 分类层级超过三级
- 没有效果评估机制

---

**IMPORTANT**: 知识库的核心价值是"让客户不需要联系我们就能解决问题"。每篇文章写完后问自己：如果我是一个焦急的用户，在凌晨 2 点看到这篇文章，能独立解决问题吗？
