# 知识库建设原则与参考

## 文章结构最佳实践

### 五层递进结构

优秀的知识库文章遵循"从简单到复杂"的递进逻辑：

1. **问题描述** — 让用户确认"这就是我遇到的问题"
2. **常见原因** — 帮用户理解"为什么会这样"
3. **分步解决** — 引导用户"一步步解决"
4. **高级排错** — 覆盖"如果上面的方法不管用"
5. **联系支持** — 兜底"我们来帮你"

### 写作原则

- **标题即问题**：用客户会搜索的自然语言，不用内部术语
  - 好：`无法登录账号怎么办？`
  - 差：`Authentication Error Resolution Guide`
- **一篇一问**：每篇文章只解决一个问题，不要试图把所有情况塞进一篇
- **步骤可执行**：每一步都足够具体，用户不需要猜"然后呢"
- **截图必备**：关键操作步骤必须有截图或 GIF
- **时效标注**：标明适用版本和最后更新日期

## 分类体系设计方法

### 卡片分类法（Card Sorting）

1. 收集所有客户问题（从工单、搜索日志、FAQ 列表）
2. 写在卡片上，邀请 5-8 个用户分组
3. 用户按自己理解分组并命名
4. 分析共同模式，形成分类结构

### 分类原则

- **互斥**：一个问题只属于一个分类
- **穷尽**：所有问题都能找到归属
- **均衡**：每个分类下 5-15 篇文章（太少合并，太多拆分）
- **扁平**：最多三级，首选两级

### 导航设计

```
首页
├── 搜索栏（最显眼的位置）
├── 热门问题 Top 10
├── 按分类浏览
│   ├── 图标 + 分类名 + 文章数
│   └── 每个分类显示 Top 3 文章
└── 最近更新的文章
```

## 搜索优化和标签策略

### 同义词映射

```yaml
synonyms:
  - group: [登录, 登陆, 登入, sign in, login, 进入]
  - group: [密码, 口令, password, 验证码]
  - group: [付款, 支付, 付费, 充值, payment]
  - group: [退款, 退费, 退钱, refund]
  - group: [bug, 故障, 错误, 出错, 崩溃, 闪退]
```

### 标签策略

每篇文章标注以下标签维度：
- **问题类型**：故障、操作、咨询、建议
- **产品模块**：对应产品功能模块
- **用户类型**：新用户、老用户、管理员
- **难度等级**：初级、中级、高级
- **平台**：Web、iOS、Android、API

### 搜索无结果优化

当搜索无结果时，依次展示：
1. 拼写建议："您是否在找 {修正词}？"
2. 相关分类推荐："以下分类可能有帮助"
3. 热门文章："其他用户常看的文章"
4. 联系支持："没找到答案？联系我们"

## 文章效果评估

### 核心指标

| 指标 | 计算方法 | 健康值 |
|------|----------|--------|
| 有用投票率 | 点击"有用" / 总阅读量 | > 70% |
| 跳出率 | 阅读 < 10s 的比例 | < 30% |
| 搜索→阅读转化率 | 搜索后点击文章 / 搜索次数 | > 50% |
| 阅读后工单创建率 | 阅读后仍创建工单 / 总阅读量 | < 15% |
| 文章覆盖率 | 有对应文章的工单类型 / 总工单类型 | > 90% |

### 文章健康度评分

```
文章健康度 = 有用投票率 × 0.3
           + (1 - 跳出率) × 0.2
           + (1 - 阅读后工单率) × 0.3
           + 时效性得分 × 0.2

时效性得分：
  更新 < 30 天 = 1.0
  更新 30-90 天 = 0.7
  更新 > 90 天 = 0.3
```

## 持续改进流程

### 月度评审流程

1. **数据收集**（每月 1 日）
   - 导出文章阅读量、投票数据、搜索日志
   - 统计新增工单中的"知识库未覆盖"问题

2. **问题识别**（每月 5 日前）
   - 低分文章列表（健康度 < 0.5）
   - 高阅读+低有用率文章（内容待改进）
   - 零阅读文章（标题/标签待优化或下线）
   - 搜索无结果 Top 20 关键词

3. **改进行动**（每月 10 日前）
   - 低分文章：重写或拆分
   - 无结果搜索：补充新文章或同义词
   - 过时文章：更新或标记归档
   - 新增高频问题：创建新文章

4. **效果追踪**（下月评审时）
   - 改进前后指标对比
   - 知识库整体覆盖率变化
   - 自助解决率趋势

### 知识库与工单联动

```
工单关闭 → 检查是否有对应知识库文章
  ├── 有 → 检查文章是否需要更新
  │   ├── 需要 → 创建文章更新任务
  │   └── 不需要 → 完成
  └── 无 → 评估是否值得创建文章
      ├── 高频问题（月出现 > 5 次） → 创建文章任务
      └── 低频问题 → 记录到潜在文章清单
```
