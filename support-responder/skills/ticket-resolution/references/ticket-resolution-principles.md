# 工单处理原则与参考

## 全渠道 SLA 基准

| 渠道 | 首次响应 | 解决时间 | 说明 |
|------|----------|----------|------|
| 在线聊天 | < 1 分钟 | < 15 分钟 | 用户期待即时响应 |
| 应用内消息 | < 5 分钟 | < 30 分钟 | 上下文丰富，解决更快 |
| 电话 | < 30 秒 | 当次通话 | 一次性解决最理想 |
| 社交媒体 | < 30 分钟 | < 2 小时 | 公开可见，影响品牌 |
| 邮件 | < 2 小时 | < 24 小时 | 容忍度最高 |

## 分层支持能力矩阵

| 能力维度 | T1 基础 | T2 技术 | T3 专家 |
|----------|---------|---------|---------|
| 产品功能 | 高 | 高 | 中 |
| 技术排查 | 低 | 高 | 高 |
| 系统操作 | 只读 | 读写 | 全权限 |
| 代码能力 | 无 | 日志分析 | 代码修复 |
| 客户沟通 | 高 | 中 | 低 |
| 响应速度 | 最快 | 中等 | 较慢 |
| 处理容量 | 高(批量) | 中 | 低(专注) |

## 工单状态流转

```
新建 → 已分配 → 处理中 → 已解决 → 已关闭
                  ↕ 等待客户/等待内部    ↕ 重新打开→处理中
```

自动化规则：
- 已解决 72h 无回复 → 自动关闭
- 等待客户 24h → 发送提醒
- SLA 剩余 20% → 通知负责人
- 客服离线 → 重分配

## 优先级判定（影响面 x 紧急度）

| | 影响面大 | 影响面小 |
|---|---------|---------|
| **紧急度高** | P0 紧急 | P1 高 |
| **紧急度低** | P2 中 | P3 低 |

- 影响面大：所有用户/核心功能不可用/数据安全
- 紧急度高：业务中断/有时限/VIP

## 升级触发条件

**自动升级**：SLA剩余<20% / 客户第3次表达不满 / 处理时间超同类2倍 / 关键词(投诉/退款/律师/媒体)

**手动升级**：超出能力范围 / 需跨部门协作 / 客户要求上级 / 安全合规问题

## 沟通模板要点

| 场景 | 关键要素 |
|------|----------|
| 首次响应 | 称呼+确认收到+复述问题+致歉+预估时间 |
| 升级通知 | 说明原因+介绍专家+已同步信息+无需重复 |
| 解决确认 | 复述问题+说明方案+请求确认+开放后续 |
| 满意度调查 | 1-5星评分+开放建议+感谢 |
