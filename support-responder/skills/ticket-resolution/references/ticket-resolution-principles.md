# 工单处理原则与参考

## 全渠道 SLA 标准

不同渠道因用户期待不同，SLA 基准也应差异化：

| 渠道 | 首次响应 | 解决时间 | 说明 |
|------|----------|----------|------|
| 在线聊天 | < 1 分钟 | < 15 分钟 | 用户期待即时响应 |
| 应用内消息 | < 5 分钟 | < 30 分钟 | 上下文丰富，解决更快 |
| 电话 | < 30 秒（接听） | 当次通话 | 一次性解决最理想 |
| 社交媒体 | < 30 分钟 | < 2 小时 | 公开可见，影响品牌 |
| 邮件 | < 2 小时 | < 24 小时 | 容忍度最高，但也不能拖 |

## 分层支持能力矩阵

| 能力维度 | T1 基础 | T2 技术 | T3 专家 |
|----------|---------|---------|---------|
| 产品功能 | ★★★ | ★★★ | ★★ |
| 技术排查 | ★ | ★★★ | ★★★ |
| 系统操作 | 只读 | 读写 | 全权限 |
| 代码能力 | — | 日志分析 | 代码修复 |
| 客户沟通 | ★★★ | ★★ | ★ |
| 响应速度 | 最快 | 中等 | 较慢 |
| 处理容量 | 高（批量） | 中 | 低（专注） |

## 工单生命周期管理

### 状态流转

```
新建(New)
  → 已分配(Assigned)
    → 处理中(In Progress)
      → 等待客户(Waiting on Customer)
        → 处理中(In Progress)
      → 等待内部(Waiting on Internal)
        → 处理中(In Progress)
      → 已解决(Resolved)
        → 已关闭(Closed)
        → 重新打开(Reopened) → 处理中
```

### 自动化规则

- **自动关闭**：已解决状态 72h 无客户回复 → 自动关闭
- **自动提醒**：等待客户 24h 无回复 → 发送提醒
- **自动升级**：SLA 剩余 20% 时间 → 通知负责人
- **自动重分配**：客服离线/请假 → 工单重分配到可用人员

## 优先级判定框架

使用 **影响面 × 紧急度** 二维矩阵：

```
紧急度 ↑
  高  │ P1（高）    P0（紧急）
      │
  低  │ P3（低）    P2（中）
      └──────────────────→ 影响面
         小            大
```

### 影响面判定

- **大**：影响所有用户 / 核心功能不可用 / 数据安全风险
- **小**：影响单个用户 / 非核心功能 / 界面问题

### 紧急度判定

- **高**：用户业务中断 / 有时间限制 / VIP 客户
- **低**：有 workaround / 非营业时间 / 功能建议

---

## 升级触发条件

### 自动升级

1. SLA 即将违规（剩余时间 < 20%）
2. 客户在同一工单中第 3 次表达不满
3. 工单处理时间超过同类型平均值 2 倍
4. 关键词触发（"投诉"、"退款"、"律师"、"媒体"）

### 手动升级

1. 客服判断超出自身能力范围
2. 需要其他部门协作
3. 客户明确要求与上级沟通
4. 涉及安全或合规问题

## 客户沟通模板

### 首次响应

```
您好 {客户姓名}，

感谢您联系我们！我是 {客服姓名}，已收到您反馈的问题。

我理解 {问题简述} 给您带来了不便，非常抱歉。

我正在为您排查，预计在 {预估时间} 内给您回复。如果期间有任何补充信息，请随时告知。

{客服姓名}
```

### 升级通知

```
{客户姓名} 您好，

为了更好地解决您的问题，我已将您的情况转交给我们的 {高级技术 / 专家} 团队。
{专家姓名} 将在 {时间} 内与您联系。

您之前提供的所有信息已同步，无需重复描述。
感谢您的耐心等待。
```

### 解决确认

```
{客户姓名} 您好，

关于您反馈的 {问题简述}，我们已通过 {解决方案} 进行了处理。

请您确认问题是否已经解决？如果还有任何疑问，请随时联系我们。

祝好！
{客服姓名}
```

### 满意度调查

```
{客户姓名} 您好，

您的问题已关闭。为了持续改进我们的服务，恳请您花 30 秒完成以下评价：

⭐ 本次服务满意度（1-5 星）
💬 您有什么建议想告诉我们？

您的反馈对我们非常重要，感谢！
```
