# 合规审计评估

对目标业务执行系统性合规审计，识别适用法规框架，逐项检查数据处理活动的合规性，输出差距分析和整改路线图。

> **免责声明**：本审计报告仅供参考，不构成正式法律意见。最终合规判定请咨询持证专业律师。

## 加载引用

```
@references/compliance-audit-principles.md
```

## 强制执行规则

1. 每项合规检查必须引用具体法规条款
2. 不确定的合规判定标记为"需法律顾问确认"
3. 风险评级必须基于影响分析，不得主观臆断
4. 输出报告必须包含免责声明
5. 所有产物保存到 `audits/` 目录

## 前置条件

- 已收集业务类型、运营地域、行业信息
- 已确定适用的法规框架

---

## Step 1: 确定适用法规框架

根据业务背景确定适用法规：

| 条件 | 适用法规 |
|------|---------|
| 处理欧盟居民数据 | GDPR |
| 处理加州居民数据 | CCPA/CPRA |
| 处理中国居民数据 | PIPL（个保法） |
| 涉及健康数据（美国） | HIPAA |
| 处理支付卡数据 | PCI-DSS |
| 上市公司（美国） | SOX |

输出适用法规清单及适用原因。

**AskUserQuestion**: "根据您的业务情况，以下法规框架适用：[{法规列表}]。请确认是否准确？是否有遗漏的法规要求？"

---

## Step 2: 数据处理活动清单

梳理所有数据处理活动，形成清单：

- **数据收集**：收集哪些类型的个人数据？通过什么渠道？
- **数据存储**：存储在哪里？存储期限？加密措施？
- **数据处理**：处理目的？法律基础？是否有自动化决策？
- **数据传输**：是否跨境传输？传输目的地？传输机制？
- **数据删除**：删除策略？用户请求删除的响应机制？

将清单保存到 `audits/data-processing-inventory.md`

---

## Step 3: 逐项合规检查

针对每个适用法规，按以下维度逐项检查：

### GDPR 检查项（如适用）
- [ ] 法律基础是否明确（Art. 6）
- [ ] 数据分类是否完成（普通数据 vs 特殊类别数据 Art. 9）
- [ ] 信息告知义务是否满足（Art. 13, 14）
- [ ] 数据主体权利机制是否建立（Art. 15-22）
- [ ] 数据处理者协议是否签署（Art. 28）
- [ ] 数据保护影响评估是否执行（Art. 35）
- [ ] 数据泄露响应计划是否建立（Art. 33, 34）
- [ ] 隐私设计是否融入系统（Art. 25）
- [ ] DPO 是否指定（Art. 37，如需要）

### CCPA 检查项（如适用）
- [ ] 消费者知情权是否保障（Sec. 1798.100）
- [ ] 删除权是否实现（Sec. 1798.105）
- [ ] 拒绝出售权是否提供（Sec. 1798.120）
- [ ] "Do Not Sell My Personal Information" 链接是否存在（Sec. 1798.135）

### PIPL 检查项（如适用）
- [ ] 处理合法基础是否具备（Art. 13）
- [ ] 告知义务是否满足（Art. 17）
- [ ] 个人权利保障机制是否建立（Art. 44-49）
- [ ] 跨境传输合规机制是否建立（Art. 38-39）
- [ ] 个人信息保护影响评估是否执行（Art. 55）

对每个检查项标注状态：合规 / 部分合规 / 不合规 / 不适用

---

## Step 4: 差距分析和风险评级

对不合规和部分合规项进行差距分析：

- **差距描述**：当前状态 vs 法规要求
- **风险评级**：高 / 中 / 低（参考 references 中的风险评级标准）
- **影响分析**：违规可能导致的后果（罚款金额、业务影响、声誉损失）
- **整改建议**：具体的整改措施

---

## Step 5: 生成合规评估报告

输出完整的合规评估报告，包含：

1. **执行摘要**：总体合规得分（满分100）、关键发现
2. **适用法规框架**
3. **数据处理活动清单**
4. **逐项检查结果**
5. **差距分析和风险评级**
6. **整改路线图**（按优先级排序，含时间建议）

保存到 `audits/compliance-assessment-report.md`

---

## Step 6: 输出 GDPR 合规配置（如适用）

生成 YAML 格式的 GDPR 合规配置：

```yaml
gdpr_compliance:
  data_controller:
    name: "{公司名称}"
    contact: "{联系方式}"
    dpo: "{DPO 联系方式}"
  legal_bases:
    - purpose: "{处理目的}"
      basis: "{法律基础}"
      article: "Art. 6(1)(x)"
  data_subjects_rights:
    access: true
    rectification: true
    erasure: true
    portability: true
    restriction: true
    objection: true
  data_retention:
    - category: "{数据类别}"
      period: "{保留期限}"
      justification: "{保留理由}"
  breach_notification:
    authority_deadline_hours: 72
    subject_notification: "without undue delay"
```

保存到 `audits/gdpr-compliance-config.yaml`

---

## 成功指标

- 所有适用法规的检查项均已评估
- 合规评分计算完成
- 差距分析覆盖所有不合规项
- 整改路线图按优先级排序并包含时间建议
- 用户已确认报告内容

## 失败指标

- 遗漏适用法规的检查项
- 风险评级缺少影响分析支撑
- 整改建议过于笼统无法执行
