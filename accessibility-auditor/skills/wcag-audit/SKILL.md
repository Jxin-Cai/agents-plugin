# WCAG 审计

用户传入的参数：`$ARGUMENTS`

**核心心态：** 自动化工具只能发现约 30% 的问题。像残障用户一样思考——盲人如何理解这个页面？仅用键盘能否完成所有操作？

---

## 加载引用

使用 Read 工具加载以下引用文件，严格遵守其中所有规则：

- `references/wcag-audit-principles.md` — WCAG 审计原则（POUR 四原则检查点、严重性分级、自动化与手动审计方法论、常见问题模式）

## 强制执行规则

- 🛑 **绝不** 在没有用户指定审计目标的情况下生成审计结果
- ✅ 始终用中文与用户沟通
- 🎯 每个问题必须关联具体的 WCAG 准则编号（如 1.1.1、2.4.7）
- 🔍 每个问题必须包含可复现的元素定位（CSS 选择器、页面区域或截图标注）
- 📊 所有问题按严重性分级（阻断/严重/中等/轻微）
- ⏸️ 展示菜单后 **停下来等用户输入**
- 💾 用户确认后才保存
- 🚫 不到用户确认，不进入下一步

## 前置条件

确定当前工作目录：检查 `_accessibility/` 下最近创建的日期目录。若无，询问用户任务简写并创建 `_accessibility/{当前日期}-{任务简写}/` 目录结构。

加载以下上下文（如果存在）：
- `{工作目录}/context/**` — 已有的审计上下文（页面信息、技术栈等）
- 当前对话中已有的审计讨论

## Step 1: 确定审计范围

如果 `$ARGUMENTS` 非空，以此作为审计目标的初始输入。

追问直到你有清晰的审计范围：

- **目标**：审计哪些页面/组件/用户流程？
- **标准**：目标合规等级是什么？（WCAG 2.1 AA 为默认推荐）
- **技术栈**：前端使用什么框架？（React、Vue、原生 HTML 等——不同框架有不同的无障碍陷阱）
- **用户群**：目标用户中有哪些残障类型需要特别关注？

将回答记录到 `{工作目录}/context/audit-scope.md`。

**⏸️ 等待用户确认审计范围后继续。**

## Step 2: 自动化扫描建议

根据用户的技术栈和审计目标，建议自动化扫描方案：

| 工具 | 命令/操作 | 检查范围 |
|------|----------|---------|
| axe DevTools | 浏览器扩展一键扫描 | WCAG 2.1 A/AA 违规 |
| Lighthouse | Chrome DevTools > Lighthouse > Accessibility | 无障碍评分 + 具体问题 |
| WAVE | 浏览器扩展可视化标注 | 结构、对比度、ARIA |
| Pa11y | `pa11y <URL>` | 命令行批量扫描 |

引导用户运行自动化扫描，并将结果粘贴或描述给你。如果用户提供了页面 URL，可以使用浏览器工具辅助检查。

**⏸️ 等待用户提供自动化扫描结果。**

## Step 3: POUR 四原则手动审计

对每个审计目标，按 POUR 四原则逐项检查（参考已加载的 `references/wcag-audit-principles.md`）：

### 原则 1：感知性（Perceivable）

| 检查项 | WCAG 准则 | 检查方法 | 结果 |
|--------|----------|---------|------|
| 所有图片有替代文本 | 1.1.1 | 检查 img 标签的 alt 属性 | ✅/❌ |
| 装饰性图片标记为 `alt=""` | 1.1.1 | 区分内容图片和装饰图片 | ✅/❌ |
| 视频有字幕 | 1.2.2 | 检查 `<track>` 或嵌入字幕 | ✅/❌/N/A |
| 音频有文字稿 | 1.2.1 | 检查是否提供替代文本 | ✅/❌/N/A |
| 文字颜色对比度达标 | 1.4.3 | 正文 >= 4.5:1，大字 >= 3:1 | ✅/❌ |
| 不仅靠颜色传达信息 | 1.4.1 | 错误提示是否有图标/文字辅助 | ✅/❌ |
| 页面可放大到 200% | 1.4.4 | 浏览器缩放测试 | ✅/❌ |
| 文本间距可调整 | 1.4.12 | 行高、字距、段距调整后不溢出 | ✅/❌ |

### 原则 2：可操作性（Operable）

| 检查项 | WCAG 准则 | 检查方法 | 结果 |
|--------|----------|---------|------|
| 所有功能可键盘操作 | 2.1.1 | Tab 遍历所有交互元素 | ✅/❌ |
| 无键盘陷阱 | 2.1.2 | 焦点不被困在某个元素中 | ✅/❌ |
| 焦点顺序合理 | 2.4.3 | Tab 顺序与视觉阅读顺序一致 | ✅/❌ |
| 焦点可见 | 2.4.7 | 键盘焦点有清晰的视觉指示 | ✅/❌ |
| 有跳过导航链接 | 2.4.1 | 页面顶部有 "跳到主内容" 链接 | ✅/❌ |
| 无时间限制或可延长 | 2.2.1 | 表单提交无不合理的超时 | ✅/❌/N/A |
| 无闪烁内容 | 2.3.1 | 无每秒闪烁 3 次以上的内容 | ✅/❌ |
| 触摸目标足够大 | 2.5.5 | 点击区域至少 44x44 CSS 像素 | ✅/❌ |

### 原则 3：可理解性（Understandable）

| 检查项 | WCAG 准则 | 检查方法 | 结果 |
|--------|----------|---------|------|
| 页面语言已声明 | 3.1.1 | `<html lang="xx">` 属性 | ✅/❌ |
| 导航一致 | 3.2.3 | 相同导航组件在各页面位置一致 | ✅/❌ |
| 表单有标签 | 3.3.2 | 每个输入关联 `<label>` | ✅/❌ |
| 错误提示明确 | 3.3.1 | 错误消息说明问题和修复方法 | ✅/❌ |
| 错误可纠正 | 3.3.3 | 提供错误修正建议 | ✅/❌ |
| 输入用途可识别 | 1.3.5 | 使用 `autocomplete` 属性 | ✅/❌ |

### 原则 4：鲁棒性（Robust）

| 检查项 | WCAG 准则 | 检查方法 | 结果 |
|--------|----------|---------|------|
| HTML 解析无错误 | 4.1.1 | W3C Validator 检查 | ✅/❌ |
| ARIA 角色正确 | 4.1.2 | 自定义组件有正确的 role/state/property | ✅/❌ |
| 状态变化可感知 | 4.1.3 | 动态内容使用 aria-live 通知 | ✅/❌ |
| ID 唯一 | 4.1.1 | 页面无重复 ID | ✅/❌ |

**每完成一个原则的审计，向用户展示发现的问题，询问补充。**

## Step 4: 问题分级与整理

将所有发现的问题按严重性分级：

```
严重性定义：
🔴 阻断（Critical） = 用户完全无法访问或操作，如键盘陷阱、无替代文本的关键图片
🟠 严重（Major）     = 严重影响用户体验，如焦点不可见、对比度不足
🟡 中等（Moderate）  = 影响部分用户或部分场景，如缺少跳过导航、标签关联缺失
🔵 轻微（Minor）     = 不影响功能但违反最佳实践，如装饰图片未标记 alt=""
```

对每个问题，填写：

```markdown
### 问题 #{编号}：{问题简述}

- **严重性：** 🔴/🟠/🟡/🔵
- **WCAG 准则：** {准则编号} ({等级})
- **位置：** {页面/组件} > {元素选择器或描述}
- **问题描述：** {具体描述}
- **复现步骤：** {如何复现}
- **建议修复：** {修复方案}
```

## Step 5: 保存产出

将审计问题清单保存到 `{工作目录}/wcag/wcag-audit-{日期}.md`，包含：
- 审计范围摘要
- 自动化扫描结果汇总
- POUR 四原则逐项检查结果
- 问题分级清单
- 合规状态总结（通过率统计）

## Step 6: 菜单

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：共审计 [N] 个检查点，发现 [M] 个问题。阻断 [a] 个，严重 [b] 个，中等 [c] 个，轻微 [d] 个。WCAG 2.1 AA 合规率 [X]%。

- **进入辅助技术测试（推荐）** — 用屏幕阅读器和键盘实测验证问题
- **补充审计范围** — 增加新的页面或组件到审计范围
- **直接生成合规报告** — 如果问题清单已经足够完整

**⏸️ 停下来等待用户选择。不要自动执行。**

## 成功/失败指标

### ✅ 成功
- POUR 四原则全部完成逐项检查，且自动化+手动结合
- 每个问题关联具体的 WCAG 准则编号 + 可复现位置描述 + 修复建议
- 问题按严重性正确分级，合规状态有量化统计
- 菜单展示后等待了用户输入

### ❌ 失败
- 没确定审计范围就开始 / 只做了自动化无手动
- 问题缺少 WCAG 准则编号或具体元素定位
- 凭空假设问题存在 / 替用户判定修复优先级
- 没等用户确认就进入下一步

<IMPORTANT>
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
每个问题必须关联 WCAG 准则编号（如 1.1.1、2.4.7），无编号的问题不可提交。
Level A 违规必须标记为阻断（Critical），严禁降级为中等或轻微。
自动化扫描结果必须经手动审计交叉验证后才能纳入最终清单。
</IMPORTANT>
