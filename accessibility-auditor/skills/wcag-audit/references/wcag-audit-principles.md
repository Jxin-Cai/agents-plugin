# WCAG 审计原则

## 1. POUR 四原则检查体系

| 原则 | 核心要求 | 关键检查点 |
|------|---------|-----------|
| 感知性 (P) | 用户能感知所有信息，不依赖单一感官 | 1.1.1 文本替代 / 1.2.x 时基媒体替代 / 1.3.x 语义结构+标题层次 / 1.4.x 对比度(正文4.5:1,大字3:1)+不仅靠颜色+可缩放 |
| 可操作性 (O) | 所有组件和导航可操作 | 2.1.x 键盘可达+无陷阱 / 2.2.x 可暂停延长时限 / 2.3.x 无3次/秒闪烁 / 2.4.x 跳过导航+焦点顺序+焦点可见 / 2.5.x 触摸目标+多输入方式 |
| 可理解性 (U) | 用户能理解信息和操作 | 3.1.x 语言声明 / 3.2.x 导航一致+可预测 / 3.3.x 错误识别+标签说明+纠正建议 |
| 鲁棒性 (R) | 内容可被辅助技术可靠解析 | 4.1.x HTML无错误+name/role/value+aria-live / ARIA第一规则：能用原生HTML就不用ARIA |

## 2. 严重性分级

| 等级 | 含义 | 示例 | 修复时限 |
|------|------|------|---------|
| 阻断 | 用户完全无法感知/操作/理解 | 键盘陷阱、关键图片无alt、按钮对SR不可见 | 立即 |
| 严重 | 严重降低体验但有替代 | 焦点不可见、对比度<3:1、错误提示不明确 | 下一版本 |
| 中等 | 部分用户/场景受影响 | 缺跳过导航、标签关联缺失但有占位提示 | 计划内 |
| 轻微 | 不影响功能但违反最佳实践 | 装饰图片未标alt=""、HTML轻微错误 | 择机 |

## 3. 自动化与手动审计方法论

**自动化能检出（约30%）：** 缺alt、对比度不足、缺表单标签、重复ID、缺lang、ARIA语法错误

**必须手动（约70%）：** alt是否准确描述内容、焦点顺序是否合理、键盘操作是否顺畅、SR朗读是否有意义、错误提示是否真正帮助用户、动态内容是否被AT感知、自定义组件交互是否符合预期

**流程：** 自动化先行(axe/Lighthouse) -> 手动POUR逐项补充 -> 交叉验证消除误报 -> 场景覆盖所有关键用户流

## 4. 常见问题模式 Top 10

1. 图片无替代文本 2. 颜色对比度不足 3. 表单缺标签 4. 键盘不可访问(自定义组件) 5. 焦点管理缺失(SPA路由/模态框) 6. ARIA滥用(错误role/缺必需属性) 7. 动态内容无通知(Toast) 8. 标题层次混乱(跳级) 9. 链接文本不明确("点击这里") 10. 触摸目标太小(<44px)

| 框架 | 常见陷阱 |
|------|---------|
| React | 自定义组件未转发ref致焦点失败、onClick用在div而非button |
| Vue | v-if切换后焦点丢失、缺aria-live的动态区域 |
| Angular | 路由切换无焦点管理、mat-组件ARIA覆盖不当 |
| 原生HTML | div替代button、table用于布局、缺语义标签 |

## 5. WCAG 2.2 新增准则

| 准则 | 等级 | 要点 |
|------|------|------|
| 2.4.11 焦点不被遮挡(最小) | AA | 焦点元素不能被完全遮挡 |
| 2.5.7 拖放替代 | AA | 拖放必须有非拖放替代 |
| 2.5.8 目标尺寸(最小) | AA | 至少24x24 CSS像素 |
| 3.2.6 一致的帮助 | A | 帮助机制位置一致 |
| 3.3.7 冗余输入 | A | 不要求重复输入相同信息 |
| 3.3.8 无障碍认证 | AA | 认证不依赖认知功能测试 |
