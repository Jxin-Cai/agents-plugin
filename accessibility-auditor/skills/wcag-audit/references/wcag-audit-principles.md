# WCAG 审计原则

本文档定义了 WCAG 审计阶段必须遵循的原则。用这些原则确保审计的完整性和专业性。

---

## 1. POUR 四原则检查体系

WCAG 2.1 围绕四大核心原则组织，审计必须按此框架系统推进：

### 感知性（Perceivable）
用户必须能感知到所有信息和界面组件。不能仅依赖单一感官通道。

关键检查点：
- **文本替代（1.1.1）**：非文本内容必须有等效文本替代。图片、图标、图表、验证码均需处理
- **时基媒体替代（1.2.x）**：视频需字幕和音频描述，音频需文字稿
- **适应性（1.3.x）**：信息的结构和关系可通过编程方式确定（语义 HTML、正确的标题层次）
- **可区分性（1.4.x）**：前景和背景可区分——颜色对比度（正文 4.5:1，大字 3:1）、不仅靠颜色传达信息、文本可缩放

### 可操作性（Operable）
所有界面组件和导航必须可操作。不能要求用户执行无法完成的交互。

关键检查点：
- **键盘可访问（2.1.x）**：所有功能可通过键盘操作，无键盘陷阱
- **充足时间（2.2.x）**：用户有足够时间阅读和操作，可暂停/调整/延长时限
- **癫痫和物理反应（2.3.x）**：无每秒闪烁超过 3 次的内容
- **可导航（2.4.x）**：跳过导航、页面标题、焦点顺序、链接目的、焦点可见
- **输入方式（2.5.x）**：触摸目标尺寸足够、支持多种输入方式

### 可理解性（Understandable）
用户必须能理解信息和界面操作方式。

关键检查点：
- **可读性（3.1.x）**：页面语言声明、专业术语解释
- **可预测性（3.2.x）**：导航一致、组件行为可预测、焦点不引起意外变化
- **输入辅助（3.3.x）**：错误识别和描述、标签和说明、错误预防和纠正建议

### 鲁棒性（Robust）
内容必须足够健壮，能被各种用户代理（包括辅助技术）可靠地解析。

关键检查点：
- **兼容性（4.1.x）**：HTML 解析无错误、组件有名称/角色/值、状态消息可被辅助技术感知
- **ARIA 使用规范**：不滥用 ARIA（第一规则：能用原生 HTML 就不用 ARIA）、role/state/property 正确配对

## 2. 严重性分级标准

问题严重性按用户影响程度分四级，指导修复优先顺序：

### 🔴 阻断（Critical）
- 用户完全无法感知、操作或理解某个功能
- 键盘陷阱导致用户困在页面某处
- 关键操作按钮对屏幕阅读器完全不可见
- 表单无法提交因为无法到达提交按钮
- **修复时限：** 立即

### 🟠 严重（Major）
- 严重降低用户体验但有替代方式
- 焦点指示器不可见，键盘用户难以定位当前位置
- 颜色对比度严重不足（比率 < 3:1）
- 错误提示不明确，用户反复试错
- **修复时限：** 下一个版本

### 🟡 中等（Moderate）
- 部分用户或部分场景受影响
- 缺少跳过导航链接
- 表单标签关联缺失但有占位文本暗示
- 非关键图片缺少替代文本
- **修复时限：** 计划内修复

### 🔵 轻微（Minor）
- 不影响功能使用但违反最佳实践
- 装饰性图片未标记 `alt=""`
- HTML 验证有轻微错误但不影响解析
- 页面语言未声明但内容单一语言
- **修复时限：** 择机修复

## 3. 自动化与手动审计方法论

### 自动化工具的价值与局限

自动化工具能高效检出的问题类型：
- 缺少 alt 属性的图片
- 颜色对比度不足
- 缺少表单标签
- 重复 ID
- 缺少页面语言声明
- ARIA 属性语法错误

**自动化无法检出的问题类型（必须手动审计）：**
- alt 文本是否准确描述了图片内容
- 焦点顺序是否符合逻辑
- 键盘操作是否顺畅
- 屏幕阅读器的朗读是否有意义
- 错误提示是否真正帮助用户理解问题
- 动态内容更新是否被辅助技术感知
- 自定义组件的交互模式是否符合用户预期

### 推荐审计流程

1. **自动化先行**：用 axe/Lighthouse 快速扫描，建立问题基线
2. **手动补充**：逐页面按 POUR 四原则手动检查
3. **交叉验证**：自动化发现的问题用手动方式确认（消除误报）
4. **场景覆盖**：确保覆盖所有关键用户流程，不只是单页面

## 4. 常见无障碍问题模式

### 高频问题 Top 10

1. **图片无替代文本** — 最常见的问题，影响所有使用屏幕阅读器的用户
2. **颜色对比度不足** — 影响低视力用户和特定环境（如户外强光）下的所有用户
3. **表单缺少标签** — 占位文本消失后屏幕阅读器用户无法知道字段用途
4. **键盘不可访问** — 自定义组件（下拉菜单、模态框、标签页）未实现键盘支持
5. **焦点管理缺失** — SPA 路由切换后焦点丢失，模态框打开后焦点未移入
6. **ARIA 滥用** — 使用了错误的 role 或遗漏了必需的 aria-* 属性
7. **动态内容无通知** — Toast/Snackbar 出现时屏幕阅读器不知道
8. **标题层次混乱** — 跳级使用标题（H1 直接到 H3）破坏文档结构
9. **链接文本不明确** — "点击这里"、"了解更多" 脱离上下文后无意义
10. **触摸目标太小** — 移动端按钮/链接的点击区域不足 44x44px

### 框架特定陷阱

| 框架 | 常见陷阱 |
|------|---------|
| React | 自定义组件未转发 ref 导致焦点管理失败、`onClick` 用在 `<div>` 上而非 `<button>` |
| Vue | `v-if` 切换内容后焦点丢失、缺少 `aria-live` 的动态区域 |
| Angular | 路由切换无焦点管理、`mat-` 组件的 ARIA 属性覆盖不当 |
| 原生 HTML | `<div>` 替代 `<button>`、`<table>` 用于布局、缺少语义化标签 |

## 5. WCAG 2.2 新增准则速查

WCAG 2.2（2023 年发布）新增以下准则，现代审计应纳入检查范围：

| 准则 | 等级 | 要点 |
|------|------|------|
| 2.4.11 焦点不被遮挡（最小） | AA | 获得焦点的元素不能被其他内容完全遮挡 |
| 2.4.12 焦点不被遮挡（增强） | AAA | 获得焦点的元素必须完全可见 |
| 2.4.13 焦点外观 | AAA | 焦点指示器有足够的面积和对比度 |
| 2.5.7 拖放替代 | AA | 拖放操作必须有非拖放的替代方式 |
| 2.5.8 目标尺寸（最小） | AA | 目标尺寸至少 24x24 CSS 像素 |
| 3.2.6 一致的帮助 | A | 帮助机制在多页面中位置一致 |
| 3.3.7 冗余输入 | A | 同一流程中不要求用户重复输入相同信息 |
| 3.3.8 无障碍认证 | AA | 认证过程不依赖认知功能测试 |
| 3.3.9 无障碍认证（增强） | AAA | 认证过程完全不依赖认知功能测试 |
