# 辅助技术测试原则

## 1. 屏幕阅读器测试方法

**核心理念：** 屏幕阅读器将视觉界面线性化为语音/盲文。视觉布局的空间关系消失，用户只能感知焦点位置内容，上下文切换无提示则用户迷失。

### 操作速查

| 操作 | VoiceOver (macOS) | NVDA (Windows) |
|------|-------------------|----------------|
| 开启/关闭 | Cmd+F5 | Ctrl+Alt+N |
| 朗读当前项 | VO+A (VO=Ctrl+Option) | -- |
| 下一项 | VO+右箭头 | 下箭头 |
| 激活 | VO+Space | Enter |
| 标题导航 | VO+Cmd+H | H |
| 链接导航 | -- | K |
| 表单控件 | VO+Cmd+J | Enter(进入)/Esc(退出) |
| 路标导航 | VO+Cmd+L | D |
| 元素列表 | -- | NVDA+F7 |

### 关键测试维度

1. **信息获取** — 能否获取所有关键信息？
2. **任务完成** — 能否完成核心业务流程？
3. **效率** — 是否需过多步骤完成简单任务？
4. **错误恢复** — 出错时知道哪错了、如何修？
5. **方向感** — 任何时刻知道自己在哪？

## 2. 键盘导航测试

| 按键 | 功能 | 检查点 |
|------|------|--------|
| Tab / Shift+Tab | 前进/后退焦点 | 顺序逻辑、无遗漏、可回退 |
| Enter / Space | 激活按钮/链接/复选框 | 行为与鼠标一致 |
| Esc | 关闭弹窗/下拉 | 焦点回到触发元素 |
| Arrow Keys | 菜单/单选/标签切换 | 组内导航流畅 |
| Home / End | 首/末项 | 长列表支持 |

### 焦点管理规则

- **模态框打开** → 焦点移入，Tab循环限制在框内；**关闭** → 焦点返回触发元素
- **SPA路由切换** → 焦点移到新内容主区域或页面标题
- **动态加载完成** → 焦点移到新内容或保持在触发元素
- **删除操作** → 焦点移到合理的下一项

### 常见键盘陷阱

富文本编辑器Tab被缩进占用、iframe捕获焦点、自定义下拉只响应鼠标、日期选择器无键盘操作、拖放无键盘替代

## 3. 视觉辅助测试

| 测试项 | WCAG准则 | 检查要点 |
|--------|---------|---------|
| 放大200% | 1.4.4 | 无截断/重叠、无水平滚动、文字可读、交互可操作 |
| 重排320px | 1.4.10(AA) | 等效400%桌面缩放，单维度滚动 |
| 正文对比度 | 1.4.3(AA) | >=4.5:1 |
| 大文本对比度 | 1.4.3(AA) | >=3:1 (18pt或14pt粗体) |
| UI组件/图形 | 1.4.11(AA) | >=3:1 (边框、图标) |
| 焦点指示器 | -- | 高对比度下仍可见，>=3:1 |
| 文本间距 | 1.4.12 | 行高1.5/字距0.12em/词距0.16em/段距2em，无溢出重叠 |
| 高对比度模式 | -- | 文本可读、边界可见、信息不仅靠颜色 |

## 4. AT 兼容性矩阵

| 层级 | 组合 | 说明 |
|------|------|------|
| Tier 1(必测) | NVDA+Firefox(Win) / VoiceOver+Safari(macOS/iOS) / 键盘(跨平台) | 覆盖率最高 |
| Tier 2(推荐) | JAWS+Chrome(Win) / TalkBack+Chrome(Android) / 放大200% | 企业+移动+低视力 |
| Tier 3(可选) | 高对比度(Win) / Narrator+Edge / 语音控制 | 补充覆盖 |

**已知差异：** aria-label朗读优先级不同 / role="application"改变JAWS键盘行为 / aria-live延迟不一致 / SVG无障碍支持差异大

## 5. 任务流测试法

**设计原则：** 从用户目标出发 -> 覆盖关键路径 -> 包含错误路径 -> 每流3-10步 -> 记录每步操作/期望/实际

| 评分 | 含义 |
|------|------|
| 通过 | 独立、高效完成任务 |
| 困难 | 可完成但需额外努力或困惑 |
| 阻断 | 无法完成任务 |
