# 辅助技术测试

用户传入的参数：`$ARGUMENTS`

**核心心态：** 合规不等于可用。一个页面可以通过所有 WCAG 检查点但仍然让屏幕阅读器用户抓狂。目标是验证真实的端到端用户体验。

## 加载引用

使用 Read 工具加载以下引用文件，严格遵守其中所有规则：

- `references/assistive-tech-test-principles.md` — 辅助技术测试原则（屏幕阅读器测试方法、键盘导航测试、放大镜测试、AT 兼容性矩阵、任务流测试法）

## 强制执行规则

- 🛑 **绝不** 在没有用户指定测试目标的情况下生成测试结果
- ✅ 始终用中文与用户沟通
- 🎯 每个问题必须基于实际操作步骤中发现
- 🔄 测试必须覆盖完整的用户任务流，不只是孤立页面元素
- 📱 标注测试时使用的 AT 工具 + 浏览器 + 操作系统组合
- ⏸️ 展示菜单后 **停下来等用户输入**
- 💾 用户确认后才保存
- 🚫 不到用户确认，不进入下一步

确定当前工作目录：检查 `_accessibility/` 下最近创建的日期目录。若无，询问用户任务简写并创建 `_accessibility/{当前日期}-{任务简写}/` 目录结构。

## Step 1: 确定测试矩阵

根据审计上下文和用户环境，确定测试组合矩阵：

### 核心测试组合（必测）

| 辅助技术 | 平台 | 浏览器 | 优先级 |
|---------|------|--------|--------|
| VoiceOver | macOS | Safari | P0 |
| NVDA | Windows | Firefox | P0 |
| 键盘导航 | 跨平台 | Chrome | P0 |

### 扩展测试组合（按需）

| 辅助技术 | 平台 | 浏览器 | 优先级 |
|---------|------|--------|--------|
| JAWS | Windows | Chrome | P1 |
| VoiceOver | iOS | Safari | P1 |
| TalkBack | Android | Chrome | P1 |
| 放大镜 200% | 跨平台 | Chrome | P1 |
| 高对比度模式 | Windows | Edge | P2 |

使用 `AskUserQuestion` 工具向用户确认可用的测试环境，确定最终测试矩阵。

**⏸️ 等待用户确认测试矩阵后继续。**

## Step 2: 定义测试任务流

将审计目标拆解为用户任务流（End-to-End Task Flows），每个任务流是用户需要完成的一个完整操作：

```markdown
## 任务流 #{编号}：{任务名称}

**目标：** {用户想要完成什么}
**起点：** {从哪个页面/状态开始}
**终点：** {成功完成的标志}
**步骤：**
1. {操作步骤 1}
2. {操作步骤 2}
3. ...
```

示例：
- 任务流 #1：用户注册 — 从首页到注册成功
- 任务流 #2：搜索商品 — 从搜索框输入到查看结果
- 任务流 #3：完成购买 — 从加入购物车到支付成功

引导用户确认关键任务流列表（3-5 个核心任务流）。

**⏸️ 等待用户确认任务流后继续。**

## Step 3: 屏幕阅读器测试

对每个任务流，按以下维度进行屏幕阅读器测试：

### A. 内容朗读测试

| 检查项 | 操作 | 期望结果 |
|--------|------|---------|
| 页面标题 | 打开页面 | 朗读页面标题 |
| 标题结构 | 标题快捷键导航（H） | 按层次朗读所有标题 |
| 链接列表 | 链接快捷键导航 | 链接文本脱离上下文仍有意义 |
| 图片描述 | Tab/方向键到图片 | 朗读有意义的替代文本 |
| 表格 | 表格导航快捷键 | 朗读行/列头与单元格的关系 |
| 列表 | 列表导航 | 朗读列表项目数和位置 |

### B. 交互操作测试

| 检查项 | 操作 | 期望结果 |
|--------|------|---------|
| 按钮 | Tab 到按钮，Enter 激活 | 朗读按钮名称和角色，操作生效 |
| 链接 | Tab 到链接，Enter 激活 | 朗读链接目的地，跳转成功 |
| 表单 | Tab 进入表单，输入内容 | 朗读标签，输入被接受 |
| 下拉菜单 | 方向键切换选项 | 朗读当前选中项 |
| 模态框 | 触发打开 | 焦点移入，朗读标题，Esc 关闭 |
| 标签页 | 方向键切换 | 朗读当前标签名和内容 |
| 手风琴 | Enter/Space 展开 | 朗读展开/折叠状态 |

### C. 动态内容测试

| 检查项 | 操作 | 期望结果 |
|--------|------|---------|
| Toast/通知 | 触发通知 | 屏幕阅读器自动朗读通知内容 |
| 表单验证 | 提交无效表单 | 朗读错误消息 |
| 加载状态 | 触发异步加载 | 朗读加载中/完成状态 |
| 实时更新 | 数据变化 | 关键更新被朗读 |

**每个测试组合完成后，记录发现的问题，向用户展示。**

## Step 4: 键盘导航测试

不使用鼠标，仅用键盘完成所有任务流：

| 测试维度 | 快捷键 | 检查内容 |
|---------|--------|---------|
| Tab 前进 | Tab | 焦点按逻辑顺序移动 |
| Tab 后退 | Shift+Tab | 焦点可回退 |
| 激活 | Enter/Space | 按钮、链接可激活 |
| 取消/关闭 | Esc | 模态框、下拉可关闭 |
| 方向键 | 箭头键 | 菜单、标签页、单选组可切换 |
| 跳过导航 | Tab（第一次） | 出现跳过导航链接 |
| 焦点可见 | 目视 | 每个焦点位置有清晰的视觉指示 |
| 焦点陷阱 | Tab 循环 | 焦点不被困在某个区域 |

记录格式：

```markdown
### 键盘测试：{任务流名称}

| 步骤 | 操作 | 期望 | 实际 | 结果 |
|------|------|------|------|------|
| 1 | Tab 到搜索框 | 焦点移至搜索框 | {实际情况} | ✅/❌ |
| 2 | 输入关键词 | 输入被接受 | {实际情况} | ✅/❌ |
```

## Step 5: 视觉辅助测试

### 放大测试
- 浏览器缩放至 200%，检查：
  - 内容不被截断或重叠
  - 不出现水平滚动条（响应式重排）
  - 所有文字仍然可读
  - 交互元素仍可操作

### 高对比度模式测试
- 开启系统高对比度模式，检查：
  - 所有文本可读
  - 图标/按钮边界可见
  - 焦点指示器在高对比度下仍然可见
  - 信息不仅靠颜色传达

### 文本间距调整测试
- 设置行高 1.5 倍、段距 2 倍、字距 0.12em、词距 0.16em，检查：
  - 文本不溢出容器
  - 内容不重叠
  - 不丢失信息

## Step 6: 问题整理与关联

将辅助技术测试中发现的问题整理，并与 WCAG 审计结果交叉关联：

```markdown
### AT 问题 #{编号}：{问题简述}

- **AT 工具：** {屏幕阅读器/键盘/放大镜} + {平台} + {浏览器}
- **任务流：** {在哪个任务流中发现}
- **步骤：** {具体操作步骤}
- **期望行为：** {应该发生什么}
- **实际行为：** {实际发生了什么}
- **用户影响：** {对残障用户的具体影响}
- **关联 WCAG 问题：** {对应的 WCAG 审计问题编号，如有}
- **建议修复：** {修复方案}
```

## Step 7: 保存产出

将测试结果保存到 `{工作目录}/assistive-tech/at-test-{日期}.md`，包含：
- 测试矩阵
- 任务流列表
- 屏幕阅读器测试记录
- 键盘导航测试记录
- 视觉辅助测试记录
- 问题清单（与 WCAG 审计交叉关联）

## Step 8: 菜单

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：测试了 [N] 个任务流，覆盖 [M] 种 AT 组合。发现 [K] 个新问题，其中 [L] 个与 WCAG 审计结果可关联。

- **生成合规报告（推荐）** — 整合 WCAG 审计和 AT 测试结果，生成正式合规报告
- **补充测试场景** — 增加新的任务流或 AT 组合
- **回到 WCAG 审计** — 基于 AT 测试发现补充审计内容

**⏸️ 停下来等待用户选择。不要自动执行。**

## 成功/失败指标

### ✅ 成功
- 至少覆盖 1 种屏幕阅读器 + 键盘导航的测试组合
- 测试基于完整任务流，覆盖内容朗读/交互操作/动态内容三维度
- 每个问题记录了 AT 工具、操作步骤和期望/实际行为
- 问题与 WCAG 审计结果做了交叉关联

### ❌ 失败
- 只测试孤立元素而非完整任务流
- 问题缺少 AT 工具信息或操作步骤
- 凭空假设 AT 体验问题 / 没测试键盘导航
- 没等用户确认就进入下一步

<IMPORTANT>
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
每个 AT 问题必须记录：AT 工具 + 平台 + 浏览器的完整组合信息。
任务流测试必须覆盖完整的端到端路径，禁止只测孤立页面元素。
屏幕阅读器测试必须同时覆盖内容朗读和交互操作，缺一不可。
</IMPORTANT>
