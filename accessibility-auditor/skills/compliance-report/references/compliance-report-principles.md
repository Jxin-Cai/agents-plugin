# 合规报告原则

本文档定义了合规报告阶段必须遵循的原则。用这些原则确保报告的专业性、准确性和可用性。

---

## 1. VPAT/ACR 格式规范

### 什么是 VPAT

VPAT（Voluntary Product Accessibility Template）是由 IT Industry Council (ITI) 维护的行业标准模板，用于记录产品对无障碍标准的合规声明。完成填写后的 VPAT 称为 ACR（Accessibility Conformance Report）。

### VPAT 2.5 版本

当前版本 VPAT 2.5 包含四个版本，根据目标市场选择：

| 版本 | 适用场景 | 覆盖标准 |
|------|---------|---------|
| WCAG Edition | 通用 Web 无障碍 | WCAG 2.x Level A/AA |
| 508 Edition | 美国联邦政府采购 | Revised Section 508 + WCAG 2.0 |
| EU Edition | 欧盟市场 | EN 301 549 + WCAG 2.1 |
| INT Edition | 国际综合版 | 以上三者合一 |

### ACR 标准结构

```markdown
# [产品名称] Accessibility Conformance Report
# WCAG Edition

**VPAT Version:** 2.5
**Product Name:** [产品名称]
**Product Version:** [版本号]
**Report Date:** [日期]
**Product Description:** [产品描述]
**Contact Information:** [联系方式]
**Evaluation Methods Used:** [审计方法]

## WCAG 2.1 Report

### Table 1: Success Criteria, Level A

| Criteria | Conformance Level | Remarks and Explanations |
|----------|-------------------|--------------------------|
| 1.1.1 Non-text Content | [状态] | [说明] |
| ...      | ...               | ...                      |

### Table 2: Success Criteria, Level AA

| Criteria | Conformance Level | Remarks and Explanations |
|----------|-------------------|--------------------------|
| 1.2.4 Captions (Live) | [状态] | [说明] |
| ...      | ...               | ...                      |
```

## 2. 合规等级定义

### 标准合规状态术语

按 VPAT 2.5 标准，合规状态使用以下术语：

| 状态 | 英文 | 含义 |
|------|------|------|
| 支持 | Supports | 产品功能完全满足该准则。无已知缺陷 |
| 部分支持 | Partially Supports | 产品部分功能满足该准则，但存在已知问题 |
| 不支持 | Does Not Support | 产品功能未满足该准则 |
| 不适用 | Not Applicable | 该准则不适用于此产品（如产品无视频内容，则视频字幕准则不适用） |
| 未评估 | Not Evaluated | 该准则尚未被审计评估 |

### 使用原则

- **诚实为先**：宁可标"部分支持"也不虚标"支持"
- **证据驱动**：每个状态声明必须有具体的审计发现作为依据
- **说明必填**：Remarks 列必须解释为什么是该状态，尤其是"部分支持"和"不支持"
- **不适用需合理**：标记"不适用"需要说明理由，不能用它回避审计
- **未评估透明**：如果某些准则未被审计覆盖，标记"未评估"而非猜测合规状态

## 3. 报告撰写规则

### 执行摘要撰写

执行摘要面向非技术读者（采购经理、法务、高管），必须：
- 用一句话总结产品的总体合规状态
- 列出最关键的 3-5 个发现
- 提供修复时间线的总体估计
- 避免技术术语或至少附带解释
- 包含审计范围的明确说明（避免误导读者以为覆盖了全部功能）

### 问题描述规范

每个问题的描述必须包含：
- **WCAG 准则编号**：如 1.1.1、2.4.7
- **具体位置**：页面名称 + 元素选择器或文字描述
- **复现条件**：如何触发该问题
- **用户影响**：对残障用户的具体影响（不是笼统的"影响无障碍"）
- **建议修复方案**：具体的技术修复方向

### Remarks 撰写指南

好的 Remarks 示例：
> "首页轮播图中的 3 张产品图片缺少替代文本（img.carousel-item），屏幕阅读器用户无法获取产品信息。其余页面的图片均有准确的 alt 描述。"

差的 Remarks 示例：
> "部分图片缺少 alt 属性。"

差在：没有说明哪些图片、在哪个页面、对用户有什么影响。

## 4. 法律合规标准对照

### 美国

#### Section 508（修订版）
- **适用范围**：联邦政府采购的 ICT 产品
- **技术标准**：等同 WCAG 2.0 Level A 和 AA
- **执行机构**：U.S. Access Board
- **要求**：供应商需提供 VPAT/ACR 证明产品合规性

#### ADA Title III
- **适用范围**：面向公众的商业场所（已延伸至网站和移动应用）
- **技术标准**：法院普遍参照 WCAG 2.1 Level AA
- **执行方式**：私人诉讼 + DOJ 执法
- **关键趋势**：ADA 网站无障碍诉讼持续增长（2023 年超 4,500 起）

### 欧盟

#### EN 301 549
- **适用范围**：欧盟公共采购的 ICT 产品
- **技术标准**：引用 WCAG 2.1 Level AA，并增加了软件和硬件特定要求
- **版本**：v3.2.1（2021）

#### European Accessibility Act (EAA)
- **生效日期**：2025 年 6 月 28 日
- **适用范围**：在欧盟市场销售的电子产品和数字服务（包括电商、银行、电信）
- **关键要求**：不仅是网站，还包括移动应用、自助终端、电子文档等
- **处罚**：各成员国自行设定，可能包括罚款和市场禁入

### 其他地区

| 地区 | 标准 | 适用范围 |
|------|------|---------|
| 加拿大 | AODA | 安大略省组织 |
| 澳大利亚 | DDA | 所有公共网站 |
| 日本 | JIS X 8341-3 | 公共和商业网站 |
| 中国 | GB/T 37668-2019 | 信息无障碍，推荐性标准 |
| 韩国 | KWCAG | 公共和商业网站 |

## 5. 修复路线图编制原则

### 优先级排序

修复优先级综合考虑以下因素：
1. **严重性**：阻断级优先（用户完全无法使用）
2. **影响范围**：影响核心流程的优先
3. **用户量**：影响大量用户的优先
4. **修复成本**：同等严重性下，修复简单的优先（快速胜利）
5. **法律风险**：可能引发诉讼的优先

### 时间规划

| 阶段 | 时间 | 内容 |
|------|------|------|
| 紧急修复 | 1-2 周 | 所有阻断级问题 |
| 重点修复 | 2-4 周 | 所有严重级问题 + 高影响的中等级 |
| 持续改进 | 4-8 周 | 剩余中等和轻微级问题 |
| 长期维护 | 持续 | CI/CD 集成、定期审计、团队培训 |

### 长期建议

- 将 axe/Pa11y 集成到 CI/CD 流水线，每次部署前自动扫描
- 建立无障碍组件库（Accessible Component Library），确保基础组件合规
- 对前端开发团队进行无障碍开发培训
- 每季度进行一次完整的合规审计
- 指定无障碍负责人（Accessibility Champion），负责日常合规维护
