# 高管仪表盘设计原则

## KPI 层级设计

### 北极星指标（1 个）

反映核心价值的单一指标，需满足：反映用户价值、可衡量业务进展、具有先导性。

| 业务类型 | 典型北极星 |
|----------|-----------|
| SaaS | MRR / ARR |
| 电商 | GMV / 月订单数 |
| 社交 | DAU / MAU |
| 游戏 | ARPU x DAU |

### 一级指标（3-5 个）

直接驱动北极星的核心因素。示例（MRR 拆解）：
- 新增 MRR → 扩展 MRR → 流失 MRR → 净留存率（NRR）

### 二级指标（每个一级下 2-3 个）

诊断一级变化原因的细分指标：新增 MRR → 漏斗转化率 / 平均客单价 / 渠道占比。

## 仪表盘设计原则

### 信息密度

- **5 秒规则** — 用户 5 秒内抓住核心信息
- **渐进披露** — 概览 → 趋势 → 明细，逐层深入
- **数据墨水比** — 最大化信息承载，最小化装饰

### 钻取路径（三层）

| 层级 | 内容 | 交互 |
|------|------|------|
| L1 概览 | 核心指标卡片 + 红绿灯状态 | 点击卡片 → L2 |
| L2 趋势 | 时间序列折线图 + 时间范围切换 | 点击数据点 → L3 |
| L3 明细 | 支持筛选/排序的数据表 | 导出 / 回到 L1 |

### 实时性分层

| 指标类型 | 更新频率 | 实现方式 |
|----------|---------|---------|
| 营收/GMV | 准实时（5min） | 流处理 + 缓存 |
| 用户增长 | 每小时 | 定时任务 |
| 留存/LTV | 每日 | 离线批处理 |
| 预测指标 | 每周 | 模型定时运行 |

## SQL 编写规范

- 使用 CTE 提升可读性，禁止嵌套子查询超过 2 层
- 标注目标数据库类型（MySQL / PostgreSQL / BigQuery）
- 参数化日期范围（`@start_date`、`@end_date`）
- 添加中文注释说明业务逻辑
- 除以可能为零的值时使用 `NULLIF(x, 0)` 防除零
- 考虑大数据量下的查询性能（索引命中、分区剪裁）

## 布局规范

1. **顶部概览栏** — 北极星 + 一级指标卡片（含同环比箭头）
2. **趋势区域** — 核心指标时间序列折线图
3. **构成分析** — 按维度（产品/渠道/地区）的占比图
4. **明细表格** — 支持下钻的数据明细
5. **筛选器** — 时间范围、维度筛选，放置于顶部或侧边
