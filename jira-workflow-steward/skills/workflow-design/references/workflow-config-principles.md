# 工作流配置与自动化原则

---

## 1. 字段方案设计

### 必填字段策略

| 时机 | 必填字段 |
|------|---------|
| 创建时 | 标题、类型、优先级 |
| 开始开发 | 经办人、估算工时 |
| 完成时 | 解决结果、实际工时 |

原则：**在需要信息的时刻才要求填写**，不要创建时填 20 个字段。

### 自定义字段控制
- 数量不超过项目实际需要
- 定期清理不再使用的字段
- 用字段配置方案控制不同问题类型的可见字段

---

## 2. 工作流方案与共享

- 同类项目使用相同方案，减少维护成本
- 不同问题类型可绑定不同工作流
- 变更方案影响所有关联项目，变更前充分评估

### 演进策略
- 从简单开始，实践中发现不足再迭代
- 每次回顾会评估工作流合理性
- 每次只改一个变量，观察效果后再改
- 记录每次变更的原因和预期效果

---

## 3. 自动化规则

### 高价值场景
- PR 合并 -> 自动流转到"待测试"
- Issue 超 N 天无更新 -> 自动提醒经办人
- 子任务全完成 -> 自动流转父任务
- 新建 Bug -> 自动分配给模块负责人
- Sprint 结束未完成 -> 自动退回 Backlog

### 设计原则
- 必须可追踪（谁触发、什么时候、做了什么）
- 不替代人的判断（自动关闭 Bug 需谨慎）
- 每条规则要有失败时的处理方式
