# 看板配置原则

---

## 1. 看板类型选择

| 类型 | 适用场景 | 核心特征 | 关键配置 |
|------|---------|---------|---------|
| Scrum Board | 固定迭代、Sprint 驱动 | Sprint 边界、Velocity、燃尽图 | Sprint 容量、DoD |
| Kanban Board | 持续交付、无固定迭代 | WIP 限制、持续流动、周期时间 | WIP 限制、列策略 |
| Scrumban | Sprint 结构 + 流量管理 | Sprint 计划 + WIP + 持续改进 | 适合过渡期团队 |

选择决策：有固定迭代 -> Scrum；无固定迭代且可预测 -> Kanban；其余 -> Scrumban；团队 > 8 人考虑 SAFe 多层看板。

---

## 2. 列（Column）配置

- **数量**：5-7 列为佳，绝不超过 10 列
- **映射**：每列对应工作流中一个或多个状态；一个状态只属于一列
- **流向**：从左到右代表开始到完成
- **命名**：列名自解释，看一眼就知道阶段
- **避免**：隐藏列（状态存在但看板不可见）

| 模式 | 列配置 |
|------|--------|
| 标准开发 | Backlog / Ready / In Dev / In Review / In QA / Done |
| 带缓冲区 | Backlog / Ready / Doing-Done / Review-Done / QA-Done / Released |
| 运维支持 | New / Triaged / Investigating / In Progress / Resolved / Closed |

---

## 3. WIP 限制

**价值**：减少上下文切换、暴露瓶颈、提高完成率、缩短前置时间（Little's Law: LT = WIP / Throughput）

| 设置项 | 规则 |
|--------|------|
| 起始值 | 每列 WIP = 团队成员数 x 1.5（向上取整） |
| 调优 | 观察 2-4 周，堆积列降低 WIP |
| 瓶颈列 | WIP 不设太高，让问题暴露 |
| 缓冲列 | 输出缓冲区可稍高 |

违规处理：超限 -> 先完成在制品再拉新；紧急插入 -> 允许但必须标记并记录；定期复盘违规次数和原因。

---

## 4. 泳道（Swimlane）配置

| 团队场景 | 推荐泳道 | 原因 |
|---------|---------|------|
| 频繁紧急插入 | 按优先级 | 紧急事项一目了然 |
| 关注个人负载 | 按人员 | 直观看到每人并行数 |
| Bug 比例不确定 | 按工作类型 | 监控 Bug 占比趋势 |
| 多项目并行 | 按项目 | 区分不同项目进度 |

紧急泳道规则：始终在最顶部、WIP = 1-2、卡片必须有明确升级人。
