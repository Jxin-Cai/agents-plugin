# 干系人管理原则

基于 PMBOK 第七版干系人绩效域和 Mendelow 权力-利益矩阵方法论。

---

## 1. Mendelow 权力-利益矩阵

| 象限 | 条件 | 策略 | 风险 | 典型角色 |
|------|------|------|------|---------|
| 密切管理 | 高权力+高利益 | 高频双向深度沟通，参与关键决策 | 不满意可能叫停项目 | 发起人、产品负责人 |
| 保持满意 | 高权力+低利益 | 定期简报，关键节点主动汇报 | 突然关注发现问题会强力干预 | 高管、CTO |
| 保持知情 | 低权力+高利益 | 定期信息共享，收集反馈 | 被忽视可能通过非正式渠道制造障碍 | 用户、一线开发 |
| 持续监控 | 低权力+低利益 | 最小信息量，公共渠道 | 权力/利益可能变化 | 其他项目团队 |

**动态评估**：权力-利益矩阵不是静态的，每个里程碑重新评估一次。

---

## 2. 干系人识别五圈层

| 圈层 | 范围 | 典型角色 |
|------|------|---------|
| 1-核心执行 | 直接参与交付的人员 | 项目经理、技术 Lead、开发、测试、设计 |
| 2-直接管理 | 有管理权或审批权 | 发起人、部门负责人、PMO |
| 3-内部协作 | 有接口依赖的团队 | 运维、安全、DBA、架构组、HR、采购 |
| 4-外部协作 | 组织外部参与方 | 供应商、外包、咨询顾问、客户代表 |
| 5-间接影响 | 不直接参与但能影响 | C-level、监管机构、审计方、社区 |

---

## 3. 干系人画像要素

### 必填（密切管理 + 保持满意象限）

- **姓名/角色** / **权力来源**（审批权、资源调配权、技术决策权、组织影响力）
- **利益诉求** / **立场**（支持者 Champion / 中立者 Neutral / 反对者 Blocker）/ **顾虑**

### 进阶

- 影响方式、沟通偏好、决策风格、关系网络、历史经验

### 立场转化策略

| 转化路径 | 策略 |
|---------|------|
| 反对者 -> 中立者 | 理解顾虑、消除威胁感、展示价值 |
| 中立者 -> 支持者 | 增加参与感、展示进展、建立信任 |
| 支持者 -> 拥护者 | 赋予角色、公开认可、成为项目代言人 |

## 4. RACI 矩阵原则

| 角色 | 含义 | 规则 |
|------|------|------|
| R（Responsible） | 执行者——谁做 | 可多个 |
| A（Accountable） | 负责人——谁最终负责 | 每项有且仅有一个 |
| C（Consulted） | 咨询者——需征求意见 | 双向沟通 |
| I（Informed） | 知会者——需告知结果 | 单向通知 |

常见问题：一项多个 A（责任分散）、某人全是 R（过载）、某人无角色（遗漏或不必要）、无 C 的行（缺乏输入）。

---

## 5. 冲突管理

### 常见冲突类型

优先级冲突、资源冲突、范围冲突、技术路线冲突

### 升级路径

项目经理协调 -> 发起人仲裁 -> 管理层决策 -> 治理委员会裁决

### 处理原则

- 聚焦利益（Interest）而非立场（Position）
- 用数据和事实支撑讨论
- 寻找双赢方案
- 记录决策及理由，避免反复争论
