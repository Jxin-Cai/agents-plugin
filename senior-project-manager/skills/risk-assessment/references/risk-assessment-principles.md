# 风险评估原则

基于 PMBOK 第七版不确定性绩效域和 ISO 31000 国际风险管理标准。

---

## 1. PMBOK 风险管理五步闭环

| 步骤 | 关键动作 | 工具/方法 |
|------|---------|----------|
| 识别 | 用 RBS 从技术/外部/组织/项目管理四层级系统识别 | 头脑风暴、SWOT、检查清单 |
| 定性分析 | 用概率-影响矩阵排序，评估紧迫性和可检测性 | P-I Matrix、5 级量表 |
| 定量分析 | 对高优先级风险深入分析 | 蒙特卡洛模拟、决策树、敏感性分析 |
| 应对规划 | 威胁：规避/减轻/转移/接受；机会：开拓/提升/分享/接受 | 每个策略须有责任人、触发条件、应急预案 |
| 监控 | 定期审查风险登记册，跟踪触发条件，识别新风险 | 风险仪表盘、预警指标 |

每个风险必须有清晰的 **原因 -> 风险事件 -> 影响** 链条。应对后须评估残余风险和次生风险。

---

## 2. 概率-影响矩阵标准

### 概率量表

| 等级 | 描述 | 概率范围 |
|------|------|---------|
| 1 | 极低 | < 10% |
| 2 | 低 | 10%-30% |
| 3 | 中 | 30%-50% |
| 4 | 高 | 50%-70% |
| 5 | 极高 | > 70% |

### 影响量表

| 等级 | 进度 | 成本 | 质量 | 范围 |
|------|------|------|------|------|
| 1-可忽略 | < 1 周 | < 5% | 几乎无 | 次要调整 |
| 2-轻微 | 1-2 周 | 5-10% | 次要功能 | 小范围 |
| 3-中等 | 2-4 周 | 10-20% | 主要降级 | 显著变更 |
| 4-严重 | 1-2 月 | 20-40% | 不可接受 | 大范围删减 |
| 5-灾难性 | > 2 月 | > 40% | 项目失败 | 项目取消 |

### 风险评分 = 概率 x 影响

```
绿色: 1-4  |  黄色: 5-9  |  橙色: 10-14  |  红色: 15-25
```

---

## 3. 风险分解结构（RBS）六维扫描

| 维度 | 关注点 |
|------|--------|
| 技术 | 架构复杂度、技术成熟度、第三方依赖、数据安全、集成复杂度 |
| 进度 | 工期估算不确定性、关键路径脆弱性、资源可用性、审批延迟 |
| 成本 | 预算偏差、计划外采购、人力成本变化、返工和学习曲线成本 |
| 干系人 | 需求变更频率、决策延迟、团队流动、沟通障碍 |
| 外部 | 监管政策、市场波动、供应商可靠性、不可抗力 |
| 运营 | 部署复杂度、数据迁移、运维准备度、回滚可行性 |

---

## 4. 应对策略选择决策树

```
风险评分 >= 15（红色）？
├── 是 → 能否改变计划消除风险源？
│   ├── 是 → 规避（Avoid）
│   └── 否 → 能否降低概率或影响？
│       ├── 是 → 减轻（Mitigate）
│       └── 否 → 能否让第三方承担？
│           ├── 是 → 转移（Transfer）
│           └── 否 → 接受（Accept）+ 应急储备
└── 否 → 评分 >= 10？ → 减轻或转移 | 否 → 监控
```

每个应对策略必须包含：责任人、触发条件、行动计划、资源需求、应急预案、残余风险评估。

---

## 5. 风险沟通

| 等级 | 汇报频率 | 升级对象 |
|------|---------|---------|
| 红色 | 每日 | 项目发起人 |
| 橙色 | 每周 | 项目经理 |
| 黄色/绿色 | 每两周 | 登记册记录 |
| 触发条件满足 | 立即 | 所有相关干系人，启动应急预案 |
