# 修复方案生成原则

本文档定义了 Fix Pack Generation 阶段必须遵循的方法论和标准。

---

## 1. 修复类型分类

### FAQ Schema 部署
**适用场景**：推荐型和最佳选择型查询缺失，竞品通过 FAQ 内容被引用。

**实施要点**：
- 在品牌官网部署 FAQPage Schema Markup
- FAQ 内容必须直接回答目标查询（与测试 prompt 高度匹配）
- 每个 FAQ 项的答案控制在 200-300 字，开头直接给出核心答案
- FAQ 页面的 H1 标题匹配目标查询的自然语言表达
- 同时部署在网页可见内容和 JSON-LD 结构化数据中

**验证方法**：使用 Google Rich Results Test 验证 Schema 部署正确性。

### 比较内容创建
**适用场景**：比较型查询缺失，竞品有专门的比较页面。

**实施要点**：
- 创建 "{品牌} vs {竞品}" 的独立比较页面
- 使用对比表格，每个维度有明确的评分或描述
- 内容必须客观公正，承认竞品的优势（AI 模型对过度营销内容敏感）
- 包含使用场景推荐："如果你需要 X，选 A；如果你需要 Y，选 B"
- 定期更新竞品信息，确保数据时效性

**避免**：不要创建明显贬低竞品的内容，AI 模型倾向于引用客观平衡的来源。

### 实体优化
**适用场景**：品牌在 Knowledge Graph 中的实体信号弱，导致 AI 不识别品牌。

**实施要点**：
- 确保 Google Business Profile 完整且经过验证
- 部署 Organization Schema（名称、Logo、URL、社交链接、创始人等）
- 维护 Wikipedia/Wikidata 词条（如果品牌满足关注度标准）
- 在权威百科和行业数据库中建立品牌词条
- 统一品牌名称在所有平台上的拼写和表达

**长期建设**：实体信号提升是长期过程，通常需要 1-3 个月才能在 AI 引用中体现。

### 结构化数据增强
**适用场景**：网站内容质量尚可但缺少结构化数据标记。

**实施要点**：
- **Product Schema**：名称、描述、品牌、评分、价格、可用性
- **Review Schema**：聚合评分、评价数量、来源
- **HowTo Schema**：步骤化教程内容
- **BreadcrumbList Schema**：网站导航结构
- **Article Schema**：发布日期、修改日期、作者
- 使用 JSON-LD 格式（而非 Microdata），AI 模型更易解析

**验证方法**：Schema.org Validator + Google Rich Results Test。

### 深度内容创建
**适用场景**：教程型和推荐型查询缺失，品牌缺少该主题的深度内容。

**实施要点**：
- 创建 2000+ 字的深度指南，覆盖目标查询的完整答案
- 文章开头 200 字内直接回答核心问题（AI 偏好提取开头内容）
- 使用清晰的 H2/H3 层级结构，每个小标题匹配一个子查询
- 包含数据、表格、步骤清单等结构化元素
- 定期更新（每季度至少一次），标注最后更新日期

### 第三方权威度建设
**适用场景**：品牌自有内容被引用但权威度评分低，竞品通过第三方来源获得更多引用。

**实施要点**：
- 在行业评测平台（G2、Capterra、TrustRadius 等）维护完整的品牌档案
- 积极获取用户评价（AI 平台信任有真实评价支撑的品牌）
- 争取行业媒体报道和专家评测
- 建设高质量的反向链接
- 参与行业报告和排名（如 Gartner Magic Quadrant、Forrester Wave）

**注意**：这是最耗时但长期价值最大的修复类型。

## 2. 优先级排序框架

### 修复排序公式

```
修复优先级 = 影响面分 x 速度系数 / 工程量
```

其中：
- **影响面分**：来自 Lost Prompt Analysis 的影响面评分（1-5）
- **速度系数**：修复见效速度（快速=3, 中等=2, 慢速=1）
- **工程量**：实施所需的人力和时间（1-5）

### 实施节奏建议

| 时间窗口 | 修复类型 | 说明 |
|---------|---------|------|
| 第 1 周 | Quick Wins | Schema 部署、现有内容结构优化、FAQ 添加 |
| 第 2 周 | 核心修复 | 比较内容创建、深度指南编写 |
| 第 3-4 周 | 深度优化 | 实体优化、新内容页面创建 |
| 持续进行 | 长期建设 | 第三方权威度、反向链接、Knowledge Graph 实体强化 |

### Quick Wins 识别标准
以下修复通常可以在 1-3 天内完成，且见效较快：
- 在现有页面添加 FAQ Schema
- 优化现有内容的标题结构（H2/H3 匹配目标查询）
- 添加或完善 Product/Organization Schema
- 更新过时的内容并标注更新日期
- 在现有页面添加对比表格

## 3. 复检方法论

### 14 天复检周期
AI 平台的内容索引和模型更新有一定的延迟。基于经验：
- **Perplexity**：实时搜索，修复后 1-3 天可能见效
- **Gemini**：Google 生态内更新较快，3-7 天可能见效
- **ChatGPT**：知识库更新周期较长，联网模式下 7-14 天可能见效
- **Claude**：训练数据更新周期最长，短期可能不见效，但联网搜索模式下可能更快

### 复检流程
1. **准备**：使用与初次审计完全相同的测试 prompt 集合
2. **执行**：在所有目标平台重新查询
3. **记录**：使用相同的数据记录模板
4. **对比**：与修复前的审计数据逐一对比
5. **评估**：计算引用率变化、SOV 变化、新增引用和仍缺失引用

### 复检评估标准

| 评估 | 标准 | 后续行动 |
|------|------|---------|
| 显著改善 | 引用率提升 > 20% | 继续当前策略，进入下一批修复 |
| 有改善 | 引用率提升 10-20% | 微调修复方案，加大同类型优化投入 |
| 轻微改善 | 引用率提升 < 10% | 分析哪些修复未见效，调整策略 |
| 无改善 | 引用率无变化 | 重新分析赢因，可能需要更深层的修复 |
| 恶化 | 引用率下降 | 紧急排查，可能是内容变更导致负面影响 |

### 持续监控建议
- **周频**：监控 P0 查询的引用状态变化
- **双周频**：完整 prompt 集合复检
- **月频**：扩展 prompt 集合，识别新出现的丢失查询
- **季频**：重新评估竞品格局和 AI 平台引用偏好变化

## 4. 各平台内容格式最佳实践

### ChatGPT 优化要点
- 内容开头直接给出核心答案，避免冗长前言
- 使用编号列表和粗体关键词，便于 AI 提取
- FAQ 页面是高价值页面类型
- 确保网站对 ChatGPT 的爬虫（GPTBot）开放
- 在 robots.txt 中不要屏蔽 GPTBot

### Claude 优化要点
- 注重内容的技术准确性和细节完整度
- 提供有数据支撑的论述，避免空泛的营销语言
- 对比分析要客观，承认不同方案的适用场景
- 引用来源要明确，帮助 Claude 验证信息可信度
- 长篇深度内容比短篇概述更有引用价值

### Gemini 优化要点
- Schema Markup 是最关键的优化项（Google 生态）
- 确保 Google Business Profile 完整且经过验证
- 内容时效性非常重要，定期更新并标注日期
- Knowledge Graph 实体信号直接影响引用
- 利用 Google Search Console 监控结构化数据状态

### Perplexity 优化要点
- 确保网站内容可被爬虫正常抓取（避免 JavaScript 渲染问题）
- 在 robots.txt 中不要屏蔽 PerplexityBot
- 内容中包含明确的事实陈述和数据点（Perplexity 偏好可引用的具体数据）
- 使用表格呈现对比数据，便于直接引用
- 来源页面的 URL 结构要清晰（Perplexity 引用时会显示 URL）
