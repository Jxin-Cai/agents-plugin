# 修复方案生成原则

## 1. 修复类型分类

| 修复类型 | 适用场景 | 见效速度 |
|---------|---------|---------|
| FAQ Schema 部署 | 推荐型/最佳选择型缺失，竞品通过 FAQ 被引用 | 快（1-3天） |
| 比较内容创建 | 比较型缺失，竞品有专门比较页面 | 中（1-2周） |
| 实体优化 | Knowledge Graph 实体信号弱 | 慢（1-3月） |
| 结构化数据增强 | 内容质量可以但缺少 Schema 标记 | 快（1-3天） |
| 深度内容创建 | 教程型/推荐型缺失，缺少深度内容 | 中（1-2周） |
| 第三方权威度建设 | 自有内容被引用但权威度低 | 慢（持续） |

### FAQ Schema 部署
- 品牌官网部署 FAQPage Schema Markup（JSON-LD 格式）
- FAQ 答案 200-300 字，开头直接给核心答案
- H1 标题匹配目标查询自然语言；同时部署可见内容和结构化数据
- 验证：Google Rich Results Test

### 比较内容创建
- 创建 "{品牌} vs {竞品}" 独立比较页面，使用对比表格
- 内容客观公正，承认竞品优势（AI 对过度营销敏感）
- 包含场景推荐："如果需要X选A，需要Y选B"；定期更新

### 实体优化
- 确保 Google Business Profile 完整验证
- 部署 Organization Schema（名称、Logo、URL、社交链接）
- 维护 Wikipedia/Wikidata 词条；统一品牌名称拼写

### 结构化数据增强
- Product Schema / Review Schema / HowTo Schema / BreadcrumbList / Article Schema
- 使用 JSON-LD 格式（AI 模型更易解析）
- 验证：Schema.org Validator + Google Rich Results Test

### 深度内容创建
- 2000+ 字深度指南，前 200 字直接回答核心问题
- H2/H3 层级清晰，每个小标题匹配子查询
- 含数据、表格、步骤清单；每季度更新并标注日期

### 第三方权威度建设
- 行业评测平台（G2、Capterra）维护完整档案 + 获取真实评价
- 争取行业媒体报道、专家评测、行业报告（Gartner、Forrester）

## 2. 优先级排序框架

`修复优先级 = 影响面分 x 速度系数 / 工程量`

- **影响面分**：来自 Lost Prompt Analysis（1-5）
- **速度系数**：快速=3, 中等=2, 慢速=1
- **工程量**：人力和时间（1-5）

### 实施节奏

| 时间窗口 | 修复类型 | 说明 |
|---------|---------|------|
| 第 1 周 | Quick Wins | Schema 部署、内容结构优化、FAQ 添加 |
| 第 2 周 | 核心修复 | 比较内容创建、深度指南编写 |
| 第 3-4 周 | 深度优化 | 实体优化、新内容页面创建 |
| 持续进行 | 长期建设 | 第三方权威度、反向链接、Knowledge Graph |

### Quick Wins 识别标准
可在 1-3 天完成且见效较快的修复：
- 现有页面添加 FAQ Schema / Product/Organization Schema
- 优化标题结构（H2/H3 匹配目标查询）
- 更新过时内容并标注更新日期
- 现有页面添加对比表格

## 3. 复检方法论

### 各平台见效周期

| 平台 | 预计见效时间 |
|------|------------|
| Perplexity | 1-3 天（实时搜索） |
| Gemini | 3-7 天（Google 生态更新快） |
| ChatGPT | 7-14 天（联网模式） |
| Claude | 较长（训练数据周期长，联网搜索模式可能更快） |

### 复检流程
1. 使用与初次审计完全相同的 prompt 集合
2. 在所有目标平台重新查询 → 相同记录模板 → 逐一对比
3. 计算引用率变化、SOV 变化、新增引用和仍缺失引用

### 复检评估标准

| 评估 | 标准 | 后续行动 |
|------|------|---------|
| 显著改善 | 引用率 +20% | 继续当前策略，进入下一批修复 |
| 有改善 | +10-20% | 微调方案，加大同类型优化投入 |
| 轻微改善 | <+10% | 分析哪些修复未见效，调整策略 |
| 无改善 | 无变化 | 重新分析赢因，需要更深层修复 |
| 恶化 | 下降 | 紧急排查，可能是内容变更导致负面影响 |

### 持续监控节奏
- **周频**：P0 查询引用状态 | **双周频**：完整 prompt 集合复检
- **月频**：扩展 prompt 集合 | **季频**：重新评估竞品格局
