# 竞争格局分析

用户传入的参数：`$ARGUMENTS`

**核心心态：** 竞争分析不是列清单，而是理解竞争结构。好的竞争分析让人看完后知道"谁是真正的威胁"、"我的护城河在哪"、"差异化机会在哪"。

## Step 1: 识别竞争对手清单

引导用户列出竞争对手，按四个层级分类：

| 层级 | 定义 | 数量建议 |
|------|------|---------|
| 直接竞争者 | 产品功能和目标客户高度重叠 | 3-5 个 |
| 间接竞争者 | 满足同一需求但方式不同 | 2-3 个 |
| 潜在竞争者 | 目前不在赛道但有能力进入 | 1-2 个 |
| 替代方案 | 用户现有的解决方式（含"不做"） | 1-2 个 |

**追问引导**：
- "你的客户如果不用你的产品，会用什么？"
- "有哪些大公司可能会进入这个领域？"
- "有没有用户用 Excel/微信群/手动流程来解决这个问题？"

**⏸️ 等待用户确认竞争对手清单后继续。**

## Step 2: 核心竞争对手画像

对每个直接竞争者，按照 `references/competitive-landscape-principles.md` 第 3 节的维度收集信息：

1. 引导用户提供已知信息
2. 如有需要且用户同意，使用联网搜索补充关键数据
3. 对每条信息标注来源和可靠度

**每完成一个竞争对手的画像：**
- 向用户展示汇总
- 询问是否有补充或修正
- 确认后再进入下一个竞争对手

**⏸️ 每个竞争对手画像完成后等待用户确认。**

## Step 3: 竞争地图绘制

按照 `references/competitive-landscape-principles.md` 第 2 节：

1. 引导用户选择两个最关键的竞争维度
2. 将所有竞争者（含自身）定位到二维地图中
3. 使用文本格式绘制战略分组图

```
          [维度 Y] 高
              │
    ┌─────────┼─────────┐
    │  象限 II │ 象限 I  │
    │  [竞品C] │ [自身]  │
    │         │ [竞品A] │
    ├─────────┼─────────┤ [维度 X]
    │ 象限 III│ 象限 IV │
    │         │ [竞品B] │
    │         │         │
    └─────────┼─────────┘
              │
          [维度 Y] 低
    [维度 X] 低        [维度 X] 高
```

4. 识别竞争空白区域和拥挤区域
5. 分析自身所在位置的战略含义

**⏸️ 等待用户确认后继续。**

## Step 4: SWOT 分析与 TOWS 策略

按照 `references/competitive-landscape-principles.md` 第 1 节：

1. **对自身进行 SWOT 分析**——引导用户逐一梳理优势、劣势、机会、威胁
2. **对核心竞争对手进行简化 SWOT**——聚焦其最突出的优势和最明显的弱点
3. **推导 TOWS 策略矩阵**——从 SWOT 推导四类策略

对每类策略产出 1-2 条具体的行动建议。

**⏸️ 等待用户确认后继续。**

## Step 5: 护城河与差异化机会

按照 `references/competitive-landscape-principles.md` 第 4-5 节：

1. **VRIO 评估**——对自身的核心资源/能力做 VRIO 检验
2. **护城河识别**——评估已有和可建立的护城河类型
3. **差异化机会**——基于价值曲线分析和未满足需求映射，识别差异化方向

输出格式：

```markdown
## 差异化机会

| 方向 | 描述 | 可行性 | 竞争壁垒 |
|------|------|--------|---------|
| 机会 1 | ... | 高/中/低 | ... |
| 机会 2 | ... | 高/中/低 | ... |
```

## 成功/失败指标

### ✅ 成功
- 竞争对手按四个层级系统识别
- 每个直接竞争者有完整画像，信息标注来源和可靠度
- 竞争地图的维度选择经过用户确认
- SWOT 分析覆盖自身和核心竞争对手
- TOWS 策略矩阵产出了具体行动建议
- 护城河和差异化机会有 VRIO 检验支撑
- 推测性结论明确标记为"推测"
- 所有分析逐步向用户展示并获得确认

### ❌ 失败
- 编造竞争对手的营收或市场份额数据
- 只列出直接竞争者，遗漏间接/潜在/替代方案
- SWOT 停留在列表层面，没有推导 TOWS 策略
- 竞争地图维度不合理（如选择了高度相关的两个维度）
- 推测性信息没有标记
- 没有逐步向用户确认就批量输出
- 没有识别差异化机会

<IMPORTANT>
竞争对手信息必须标注来源和可靠度（已验证/未验证/推测），推测性结论不能混入事实。
SWOT 必须推导 TOWS 策略矩阵并产出具体行动建议，不能停留在列表层面。
竞争地图的两个维度必须经过用户确认，不得选择高度相关的维度。
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
</IMPORTANT>
