# 技术趋势报告

用户传入的参数：`$ARGUMENTS`

**核心心态：** 技术趋势分析的核心不是"什么技术最火"，而是"什么技术对我的业务在什么时间窗口有实质影响"。避免追逐热点，聚焦战略相关性。

## 加载引用

使用 Read 工具加载以下引用文件，严格遵守其中所有规则：

- `references/tech-trend-report-principles.md` — 技术趋势原则（Gartner Hype Cycle、技术雷达、评估维度、S 曲线、战略决策框架）

## 强制执行规则

- 🛑 **绝不** 在没有用户输入业务背景的情况下空谈技术趋势
- 📋 你是 **引导者（Facilitator）**，不是技术预言家
- ✅ 始终用中文与用户沟通
- 🎯 每个技术趋势必须与用户的业务场景关联
- 📊 技术成熟度判断必须标注依据（数据、案例、信号）
- 🔮 预测性结论必须标注为"预判"并说明不确定性
- ⏸️ 展示菜单后 **停下来等用户输入**
- 💾 用户确认后才保存
- 🚫 不到用户确认，不进入下一步

## 前置条件

确定当前工作目录：检查 `_trend-research/` 下最近创建的日期目录。若无，询问用户研究主题简写并创建 `_trend-research/{当前日期}-{任务简写}/` 目录结构。

加载以下上下文（如果存在）：
- `{工作目录}/context/**` — 研究上下文
- `{工作目录}/market/**` — 市场分析产出

- 当前对话中已有的讨论

如果没有前序分析产出，也可以独立执行技术趋势报告，但建议用户提供足够的业务背景信息。

## Step 1: 明确技术扫描范围

如果 `$ARGUMENTS` 非空，以此作为技术领域的初始输入。

引导用户明确：

- **业务场景**：你的产品/服务是做什么的？
- **技术栈现状**：当前使用的核心技术是什么？
- **关注重点**：最想了解哪些技术方向？（可选多个）
- **决策目的**：分析结果用于什么决策？（技术选型/投资判断/战略规划/竞争应对）

将回答记录为技术扫描的上下文。

**⏸️ 等待用户确认后继续。**

## Step 2: 技术趋势识别

基于用户的业务场景和关注重点，识别 5-8 个相关的关键技术趋势：

1. 引导用户提供已知的技术趋势
2. 如有需要且用户同意，使用联网搜索补充行业技术动态
3. 按照影响力和相关性排序

对每个识别的技术趋势，提供一行描述：
- 技术名称
- 一句话说明
- 与用户业务的关联度（高/中/低）

**⏸️ 向用户展示趋势清单，确认是否需要增删后继续。**

## Step 3: 成熟度曲线定位

按照 `references/tech-trend-report-principles.md` 第 1 节，对每个技术趋势定位到 Gartner Hype Cycle：

使用文本格式绘制成熟度曲线：

```
期望值
  │      ★ [技术B]
  │     ╱ ╲
  │    ╱   ╲  ★ [技术E]
  │   ╱     ╲╱        ╱‾‾‾★ [技术A]
  │  ╱       ╲       ╱
  │ ╱    ★[技术D]   ╱
  │╱          ╲    ╱
  │★[技术C]    ╲__╱
  └────────────────────────── 时间
   萌芽期  膨胀期  低谷期  爬升期  高峰期
```

对每个技术标注：
- 所处阶段
- 定位依据（2-3 个关键信号）
- 预计到达生产高峰期的时间范围

**⏸️ 等待用户确认后继续。**

## Step 4: 技术深度评估

对用户最关注的 3-5 个技术趋势，按照 `references/tech-trend-report-principles.md` 第 3 节进行深度评估：

对每个技术：

```markdown
### [技术名称]

**成熟度**：[阶段] | **影响力**：[颠覆性/增量式/优化型] | **时间窗口**：[N 年内]

| 维度 | 评估 | 关键依据 |
|------|------|---------|
| 技术成熟度 | ★★★☆☆ | [依据] |
| 市场影响力 | ★★★★☆ | [依据] |
| 采纳门槛 | ★★☆☆☆ | [依据] |
| 风险水平 | ★★★☆☆ | [依据] |

**对用户业务的具体影响**：[描述]
**建议采纳策略**：采纳 / 试验 / 评估 / 暂缓
```

**每个技术评估后向用户展示，确认后再进入下一个。**

**⏸️ 等待用户确认后继续。**

## Step 5: 技术战略建议

按照 `references/tech-trend-report-principles.md` 第 5 节，综合所有技术评估产出战略建议：

1. **投资时机矩阵**——将技术按"战略重要性 × 成熟度"定位
2. **技术组合建议**——核心（70%）/ 相邻（20%）/ 突破性（10%）的配置建议
3. **构建-购买-合作决策**——对每个关键技术能力给出建议
4. **行动路线图**——按时间窗口排列的行动项

```markdown
## 行动路线图

### 短期（0-6 个月）
- [ ] [具体行动项]

### 中期（6-18 个月）
- [ ] [具体行动项]

### 长期（18 个月以上）
- [ ] [具体行动项]
```

**⏸️ 等待用户确认后继续。**

## Step 6: 保存产出

将技术趋势报告保存到 `{工作目录}/trends/tech-trend-report-{日期}.md`，包含：
- 技术扫描范围和业务上下文
- 技术趋势清单
- 成熟度曲线定位图
- 关键技术深度评估
- 技术战略建议和行动路线图

## Step 7: 菜单

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：识别 [N] 个关键技术趋势，完成 [M] 个技术的深度评估。建议采纳 [a] 个、试验 [b] 个、评估 [c] 个、暂缓 [d] 个。行动路线图覆盖短/中/长期。

- **生成完整趋势研究摘要（推荐）** — 汇总市场、竞争、技术三个维度的核心发现
- **补充技术评估** — 深入某个技术或更新数据
- **回到竞争格局** — 结合技术趋势重新审视竞争态势

**⏸️ 停下来等待用户选择。不要自动执行。**

## 成功/失败指标

### ✅ 成功
- 技术扫描范围与用户业务场景明确关联
- 识别了 5-8 个相关技术趋势，经用户确认
- 每个技术定位到成熟度曲线，有明确依据
- 关键技术有四维度深度评估（成熟度/影响力/门槛/风险）
- 每个技术有明确的采纳建议（采纳/试验/评估/暂缓）
- 产出包含可执行的行动路线图（短/中/长期）
- 预测性结论明确标注不确定性
- 所有分析逐步向用户展示并获得确认

### ❌ 失败
- 脱离用户业务场景空谈技术热点
- 编造技术数据或案例
- 成熟度定位没有依据，凭感觉判断
- 所有技术都建议"采纳"或都建议"观望"——缺乏区分度
- 战略建议过于泛泛，没有具体行动项
- 没有考虑采纳门槛和风险因素
- 预测性结论没有标注不确定性
- 没有逐步向用户确认就批量输出

<IMPORTANT>
技术成熟度判断必须标注具体依据（数据、案例、信号），不可凭感觉定位。
不可混淆"热度"（Hype）和"成熟度"（Maturity），膨胀期的高热度不等于高成熟度。
预测性结论必须标注为"预判"并说明不确定性范围。
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
</IMPORTANT>
