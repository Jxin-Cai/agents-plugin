## Step 1: 确定评审范围

明确本次评审的目标和边界：

- **评审对象**：评审哪个系统/模块的架构？
- **评审重点**：用户最关心的质量属性是什么？（从以下选择 Top 3）
  - 性能（Performance）
  - 可用性（Availability）
  - 安全性（Security）
  - 可修改性（Modifiability）
  - 可测试性（Testability）
  - 可伸缩性（Scalability）
- **已知风险**：用户已经意识到的风险或担忧

使用 `AskUserQuestion` 工具让用户选择最关心的质量属性。

**⏸️ 等待用户确认后继续。**

## Step 2: 构建质量属性效用树

基于用户选择的质量属性，构建效用树（Utility Tree）：

```
系统质量
├── 性能
│   ├── [H,H] 搜索请求响应时间 < 200ms（正常负载）
│   └── [M,H] 批量导出处理时间 < 30s（1 万条记录）
├── 可用性
│   ├── [H,H] 系统可用性 >= 99.9%
│   └── [H,M] 核心功能单点故障恢复 < 5 分钟
└── 安全性
    ├── [H,H] 所有 API 请求需认证和授权
    └── [M,M] 敏感数据传输使用 TLS 加密
```

每个场景标注 `[重要性, 风险]`，取值 H（高）/M（中）/L（低）。

优先分析标注为 `[H,H]` 的场景——这些是最关键的。

**⏸️ 向用户展示效用树，等待确认和调整。**

## Step 3: 架构方案分析

对效用树中 `[H,H]` 和 `[H,M]` 的场景，分析当前架构是否能满足：

对每个关键场景：
1. **当前架构如何应对这个场景？** — 描述架构中的哪些决策支撑了这个质量属性
2. **有什么风险？** — 哪些地方可能出问题
3. **敏感点是什么？** — 改变哪个参数会显著影响这个质量属性
4. **与其他质量属性有冲突吗？** — 是否存在权衡（如提高安全性可能降低性能）

向用户逐项展示分析结果。

**⏸️ 等待用户确认后继续。**

## Step 4: 六大支柱检查

用 AWS Well-Architected Framework 六大支柱做补充检查：

| 支柱 | 关键问题 | 当前状态 |
|------|---------|---------|
| **卓越运营** | 如何监控系统健康？如何响应事件？ | ✅/⚠️/❌ |
| **安全性** | 身份认证、数据保护、事件响应如何实现？ | ✅/⚠️/❌ |
| **可靠性** | 故障恢复、弹性伸缩、备份策略如何？ | ✅/⚠️/❌ |
| **性能效率** | 资源选型、监控、权衡如何？ | ✅/⚠️/❌ |
| **成本优化** | 资源利用率、成本感知、弹性策略如何？ | ✅/⚠️/❌ |
| **可持续性** | 资源效率、最小化影响如何？ | ✅/⚠️/❌ |

标记状态为 ⚠️ 或 ❌ 的项，说明具体问题和改进建议。

## Step 5: 输出评审报告

整理评审发现，生成结构化报告：

### 风险清单（Risks）
| 编号 | 风险描述 | 相关质量属性 | 严重程度 | 建议 |
|------|---------|------------|---------|------|
| R1 | {描述} | {属性} | 高/中/低 | {建议} |

### 非风险清单（Non-risks）
- {对当前架构中良好的决策给予肯定}

### 敏感点（Sensitivity Points）
- {修改哪些参数/决策会显著影响质量属性}

### 权衡点（Tradeoff Points）
- {哪些决策同时影响多个质量属性，需要平衡}

## Step 6: 保存产出

将评审报告保存到 `{工作目录}/design/architecture-review-{日期}.md`

## Step 7: 菜单

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：识别风险 [R] 项（高风险 [H] 项），敏感点 [S] 项，权衡点 [T] 项。六大支柱检查 [P] 项通过，[W] 项需关注。

- **生成 ADR（推荐）** — 将关键决策和评审发现转化为 ADR 文档
- **回到系统设计修改** — 根据评审发现调整架构设计
- **深入某个风险点分析** — 对特定风险点做更深入的分析

**⏸️ 停下来等待用户选择。不要自动执行。**

## 质量自检

- 四类发现（风险/非风险/敏感点/权衡点）均有产出
- 效用树中 [H,H] 场景全部完成架构方案分析
- 每个风险项标注了严重程度和具体改进建议
- 六大支柱检查完成，评审报告已保存到 `{工作目录}/design/`

<IMPORTANT>
评审必须产出四类发现：风险、非风险、敏感点、权衡点，缺任何一类视为评审不完整。
每个风险项必须标注严重程度（高/中/低）和具体改进建议，禁止只指出问题不给方案。
质量属性效用树中 [H,H] 场景必须逐一分析架构应对方式，不得跳过。
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
</IMPORTANT>
