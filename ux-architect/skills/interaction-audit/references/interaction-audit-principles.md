# 交互审计原则

本文档定义交互设计审计阶段必须遵循的原则。

---

## 1. Nielsen 十大可用性启发式

| # | 启发式 | 核心要求 | 常见违反 |
|---|--------|---------|---------|
| H1 | 系统状态可见性 | 及时反馈当前状态 | 提交无反馈、长操作无进度、不知当前步骤 |
| H2 | 匹配现实世界 | 用户语言、自然逻辑 | 技术术语、违反自然排序、图标含义不明 |
| H3 | 用户控制与自由 | 撤销/返回/取消 | 不可逆操作无确认、无返回、表单误关丢数据 |
| H4 | 一致性与标准 | 同操作同表现 | 同操作不同名称、相似按钮不同样式 |
| H5 | 错误预防 | 约束/确认/验证 | 允许提交无效数据、危险操作无确认 |
| H6 | 识别而非记忆 | 选项可视化 | 需记住前页信息、无搜索历史 |
| H7 | 灵活性与效率 | 快捷方式/批量操作 | 无快捷操作、批量缺失 |
| H8 | 美学与极简 | 合理信息密度 | 信息过载、视觉层次不清 |
| H9 | 错误恢复 | 清晰消息+修复建议 | 技术错误码、模糊描述 |
| H10 | 帮助与文档 | 上下文帮助/引导 | 无帮助、难找、过时 |

---

## 2. Shneiderman 八条黄金规则

| # | 规则 | 审计关注点 |
|---|------|-----------|
| 1 | 追求一致性 | 操作序列、术语、布局在同类场景中一致 |
| 2 | 常用操作快捷方式 | 高频操作有缩写、快捷键 |
| 3 | 信息性反馈 | 每个操作有适当系统反馈 |
| 4 | 封闭操作序列 | 操作有明确开始、中间和结束 |
| 5 | 简单错误处理 | 防止严重错误，错误时有简单恢复 |
| 6 | 允许撤销 | 单步和多步撤销 |
| 7 | 内部控制点 | 用户感觉自己在控制系统 |
| 8 | 减少记忆负担 | 信息适当组织，减少同时记忆项 |

---

## 3. 认知工程原则

- **Miller 定律**：工作记忆 7±2 项，一次展示选项不超过此范围
- **Hick 定律**：选项越多决策越慢，减少选项加快决策
- **接近律 + 格式塔**：相关信息空间靠近，利用视觉分组减少认知负担
- **心理模型适配**：系统概念模型匹配用户心理模型，隐喻使用恰当

---

## 4. 审计方法论

**启发式评估流程**：独立评估 → 严重程度评级 → 汇总合并 → 按严重程度 x 频率排序

| 严重程度 | 定义 | 处理优先级 |
|---------|------|-----------|
| 0 | 不是可用性问题 | 忽略 |
| 1 | 装饰性问题 | 有空再修 |
| 2 | 轻微可用性问题 | 计划修复 |
| 3 | 严重可用性问题 | 优先修复 |
| 4 | 灾难性问题 | 发布前必须修复 |

**认知走查四问**：目标明确性？ → 操作入口可见？ → 入口与目标可关联？ → 执行后有进展反馈？

---

## 5. 无障碍审计（WCAG 2.1 AA）

| POUR 原则 | 关键检查项 |
|-----------|-----------|
| Perceivable（可感知） | alt 文本、颜色对比度 ≥ 4.5:1、视频字幕 |
| Operable（可操作） | 键盘可达、无键盘陷阱、目标尺寸 ≥ 44px |
| Understandable（可理解） | 语言清晰、一致导航、输入错误有建议 |
| Robust（健壮） | 语义化 HTML、ARIA 正确、兼容辅助技术 |

---

## 6. 报告格式

**问题记录**：问题标题 / 违反启发式(H#) / 严重程度(0-4) / 位置 / 问题描述 / 影响 / 建议修复 / 参考标准

**审计总结**：评估范围 / 发现总数 / 严重程度分布 / 违反最多的启发式 Top 3 / 整体可用性评分
