- 🛑 **绝不** 在没有用户提供产品信息的情况下编造审计结论

- ✅ 始终用中文与用户沟通
- 🎯 每个发现必须关联到具体的启发式原则
- 📊 每个问题必须标注严重程度等级（0-4）
- 🔍 先全面扫描，再深度分析重点问题
- 💬 每完成一个维度的审计向用户展示，等待确认和补充
- ⏸️ 展示菜单后 **停下来等用户输入**
- 💾 用户选择保存时才写入文件

## Step 1: 确定审计范围

引导用户明确审计范围：

- **审计目标**：审计整个产品还是特定功能/页面？
- **产品状态**：已上线产品 / 设计稿 / 原型 / 代码中的 UI？
- **输入材料**：用户能提供什么？（截图、URL、代码路径、设计文件链接）
- **重点关注**：是否有已知的可用性问题或用户投诉？
- **用户群体**：目标用户的技术水平如何？（新手 / 中级 / 专家混合）

如果用户提供了代码路径，使用 Glob 扫描以下文件提取界面结构信息：
- 前端页面组件：`src/pages/**`、`src/views/**`、`src/components/**`
- 路由配置：`src/**/route*`、`src/**/router*`
- 样式文件：`src/**/*.css`、`src/**/*.scss`、`src/**/*.less`

Read 匹配文件，提取页面结构、组件层级和交互元素清单。

**⏸️ 等待用户确认审计范围后继续。**

## Step 2: Nielsen 十大启发式扫描

对审计范围内的界面，逐一对照 Nielsen 十大启发式进行评估：

### 扫描清单

| 启发式 | 评估问题 |
|--------|---------|
| H1 系统状态可见性 | 操作后有反馈吗？加载有进度指示吗？用户知道当前在哪吗？ |
| H2 匹配现实世界 | 术语是用户语言吗？图标含义清晰吗？信息排列自然吗？ |
| H3 用户控制与自由 | 有撤销/取消吗？误操作能恢复吗？有"紧急出口"吗？ |
| H4 一致性与标准 | 同一操作表现一致吗？遵循平台惯例吗？术语统一吗？ |
| H5 错误预防 | 危险操作有确认吗？输入有约束和提示吗？有实时验证吗？ |
| H6 识别而非记忆 | 选项可见吗？有搜索建议吗？用户需要记住什么吗？ |
| H7 灵活性与效率 | 有快捷方式吗？有批量操作吗？高频操作路径够短吗？ |
| H8 美学与极简 | 信息密度合理吗？视觉层次清晰吗？有无关信息吗？ |
| H9 错误恢复 | 错误消息清晰吗？指出了原因吗？提供了修复建议吗？ |
| H10 帮助与文档 | 有上下文帮助吗？有新手引导吗？帮助内容有用吗？ |

对每个启发式，标注：
- ✅ 合格
- ⚠️ 存在问题（标注严重程度 1-2）
- ❌ 严重违反（标注严重程度 3-4）

向用户展示扫描结果概览。

**⏸️ 等待用户确认后继续。**

## Step 3: 认知走查

对前置流程分析中识别的关键任务（或用户指定的核心任务），进行认知走查：

对每个任务的每一步，问四个问题：
1. **目标明确性**：用户是否会尝试去完成正确的操作？
2. **可见性**：用户是否能注意到正确的操作入口？
3. **可理解性**：用户是否能将操作入口与目标关联？
4. **反馈性**：执行操作后，用户是否能看到进展反馈？

记录每个"否"的回答，关联到具体的启发式违反。

**⏸️ 每个任务走查后向用户展示结果，等待确认。**

## Step 4: 无障碍快速检查

对审计范围做 WCAG 2.1 AA 级快速检查：

| 检查项 | 通过标准 |
|--------|---------|
| 颜色对比度 | 正文 ≥ 4.5:1，大文字 ≥ 3:1 |
| 键盘可达 | 所有交互元素可通过键盘操作 |
| 图片替代文本 | 所有有意义的图片有 alt 属性 |
| 表单标签 | 所有表单字段有关联的 label |
| 焦点可见 | Tab 切换时焦点指示清晰可见 |
| 操作目标尺寸 | 可点击区域 ≥ 44x44 CSS 像素 |

如果是代码审计，使用 Grep 扫描前端组件中的无障碍属性：
- 搜索 `aria-` 前缀属性：`Grep "aria-" --glob "*.{tsx,jsx,vue,html}"`
- 搜索 alt 属性：`Grep "alt=" --glob "*.{tsx,jsx,vue,html}"`
- 搜索 role 属性：`Grep "role=" --glob "*.{tsx,jsx,vue,html}"`

统计覆盖率，标注缺失无障碍属性的组件。

## Step 5: 问题汇总与优先排序

将所有发现的问题汇总，按严重程度和频率排序：

```markdown
## 审计发现汇总

### 严重程度分布
- 4级（灾难性）：[N] 个
- 3级（严重）：[N] 个
- 2级（轻微）：[N] 个
- 1级（装饰性）：[N] 个

### 违反最多的启发式 Top 3
1. H[N] - [名称]：[M] 个问题
2. H[N] - [名称]：[M] 个问题
3. H[N] - [名称]：[M] 个问题

### 问题详情（按严重程度排序）
```

对每个问题，输出标准格式：
- 问题标题
- 违反启发式
- 严重程度
- 位置
- 问题描述
- 影响
- 建议修复

向用户逐一确认问题和建议。

**⏸️ 等待用户确认后继续。**

## Step 6: 保存产出

将交互审计产出保存到 `{工作目录}/interaction/audit-{日期}.md`，包含：
- 审计范围说明
- Nielsen 十大启发式扫描结果
- 认知走查记录
- 无障碍检查结果
- 问题汇总与优先排序
- 修复建议（按优先级排序）

## Step 7: 菜单

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：审计 [范围描述]，发现 [N] 个问题。4级 [a] 个，3级 [b] 个，2级 [c] 个，1级 [d] 个。违反最多的启发式：[Top 1 名称]。

- **深入分析重点问题（推荐）** — 对 3-4 级问题逐一深入分析并出具详细修复方案
- **补充审计其他页面** — 扩大审计范围
- **回到用户流程分析** — 如果审计发现了流程层面的问题

**⏸️ 停下来等待用户选择。不要自动执行。**

## 成功/失败指标

### ✅ 成功
- 审计范围由用户确认
- Nielsen 十大启发式逐一对照扫描
- 每个问题关联到具体的启发式原则
- 每个问题标注了严重程度等级（0-4）
- 对关键任务进行了认知走查
- 无障碍做了快速检查
- 问题按严重程度排序
- 每个问题有可执行的修复建议
- 所有产出向用户展示并获得确认
- 菜单展示后等待了用户输入

### ❌ 失败
- 没有确认审计范围就开始评估
- 审计发现不关联启发式原则（纯主观判断）
- 问题没有严重程度分级
- 只找了问题没有给修复建议
- 跳过了认知走查
- 忽略了无障碍维度
- 替用户做设计决策而不是提供原则支撑的建议
- 没有等用户确认就进入下一步

<IMPORTANT>
每个审计发现必须关联具体启发式原则编号（H1-H10），不可纯主观判断。
每个问题必须标注严重程度等级（0-4 级）。
修复建议必须可执行（指出具体改什么、怎么改），不可仅描述问题。
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
</IMPORTANT>
