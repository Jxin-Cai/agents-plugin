# 用户流程分析原则

本文档定义用户流程分析阶段必须遵循的原则。

---

## 1. 流程类型体系

| 类型 | 特点 | 适用场景 |
|------|------|---------|
| 任务流（Task Flow） | 单一路径、无分支 | 理解某操作的基本步骤序列 |
| 用户流（User Flow） | 多路径、有决策分支 | 识别决策点上的不同走向 |
| 线框流（Wireflow） | 结合线框图和流程图 | 向开发设计沟通页面跳转逻辑 |
| 客户旅程地图 | 超越产品边界，含情绪曲线 | 多渠道多触点的全局体验 |

**用户流符号约定**：矩形=页面/屏幕，菱形=决策点，椭圆=起点/终点，箭头=流向。

---

## 2. 流程映射方法论

**入口-目标映射法**：
1. 列出所有入口点（首页/深链/推送/搜索引擎/分享链接）
2. 列出所有目标（任务完成/转化/信息获取）
3. 映射每个入口到每个目标的最短路径
4. 识别共享节点（Hub 页面）和关键决策点

**Happy Path 优先法**：
1. 先映射理想路径（一切顺利时的最短路径）
2. 标注每个决策点 → 延伸替代路径 → 延伸异常路径
3. 确保每条路径都有终点（不允许死胡同）

**任务分析（JTBD）**：核心任务 → 子任务 → 操作步骤，记录每步前置条件和后置状态。

---

## 3. 摩擦点识别框架

| 级别 | 类型 | 定义 | 示例 |
|------|------|------|------|
| 🔴 | 阻断性 | 用户完全无法继续 | 必填信息不清楚、加载失败无提示、死链 |
| 🟡 | 延迟性 | 需要额外时间或操作 | 加载慢、需切换应用获取信息、字段过多 |
| 🟠 | 困惑性 | 不确定下一步 | 标签含义不明、按钮不显眼、缺少进度指示 |
| ⚪ | 烦躁性 | 能完成但体验差 | 重复输入、不必要的确认弹窗、广告打断 |

**每步检查**：系统状态可见？ → 知道下一步？ → 步骤可精简？ → 出错可恢复？ → 等待可接受？

---

## 4. 流程优化原则

- **步骤最小化**：删除无价值步骤、合并可并行步骤、可选步骤延后，目标"比预期少一步"
- **决策简化**：减少选项数（Hick 定律）、智能默认值、渐进式呈现、高频快捷通道
- **断裂点消除**：保持上下文连续性、支持跨渠道状态保持、避免信息/状态丢失
- **错误恢复**：每个可能出错的步骤有恢复路径、明确告知问题和修复方式、支持断点续传

---

## 5. 流程度量指标

| 指标 | 定义 | 优化方向 |
|------|------|---------|
| 任务完成率 | 成功完成的用户比例 | 越高越好 |
| 任务完成时间 | 从开始到完成的平均时间 | 越短越好 |
| 步骤数 | 完成任务的操作步骤 | 越少越好 |
| 错误率 | 触发错误的比例 | 越低越好 |
| 回退率 | 返回上一步的比例（高=困惑） | 越低越好 |
| 放弃率 | 未完成就离开的比例 | 集中步骤是优化重点 |
| 首次成功率 | 不需纠错就完成的比例 | 越高越好 |

---

## 6. 跨角色与跨渠道

- **多角色协作**：泳道图区分角色，关注角色切换点的信息完整传递
- **跨渠道流程**：Web / App / 小程序 / 线下切换点是潜在断裂点，确保关键状态跨渠道同步
