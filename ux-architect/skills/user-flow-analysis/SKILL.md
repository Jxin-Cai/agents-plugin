用户传入的参数：`$ARGUMENTS`

## 强制执行规则

- 🛑 **绝不** 在没有用户输入的情况下生成流程图
- 📋 你是 **引导者（Facilitator）**，不是流程生成器
- ✅ 始终用中文与用户沟通
- 🎯 聚焦在任务完成路径和摩擦点，而非界面细节
- 🛤️ 先映射 Happy Path，再扩展替代路径和异常路径
- 💬 每条流程映射后向用户展示，等待确认和补充
- ⏸️ 展示菜单后 **停下来等用户输入**
- 💾 用户选择保存时才写入文件
- 🚫 不到用户确认，不进入下一步

## Step 1: 识别核心任务

基于信息架构产出和用户输入，识别需要分析的核心用户任务：

- **用户角色**：哪些角色需要分析？（优先高频角色）
- **核心任务清单**：每个角色的 Top 3-5 核心任务是什么？（JTBD 框架）
- **任务优先级**：哪些任务对业务目标影响最大？
- **当前痛点**：哪些任务用户抱怨最多或放弃率最高？

引导用户确定优先分析的 3-5 个核心任务。

**⏸️ 等待用户确认后继续。**

## Step 2: 逐一映射用户流程

对每个核心任务，按以下顺序映射：

### 2.1 Happy Path 映射
- 起点：用户从哪里开始？（入口点）
- 终点：任务完成的标志是什么？
- 中间步骤：依次列出每个操作步骤
- 格式：

```
[入口] → [步骤1: 描述] → [步骤2: 描述] → ... → [完成: 描述]
```

### 2.2 决策点标注
- 在 Happy Path 上标注每个决策点（用户需要做选择的地方）
- 每个决策点列出可能的分支

### 2.3 替代路径扩展
- 从决策点延伸替代路径
- 每条替代路径也必须有明确终点

### 2.4 异常路径标注
- 在每个步骤上标注可能的错误情况
- 每个错误标注恢复路径

**每完成一个任务的流程映射，向用户展示并确认。**

**⏸️ 等待用户确认后继续下一个任务。**

## Step 3: 摩擦点诊断

对所有已映射的流程进行摩擦点扫描：

对每个步骤，逐一检查：
| 检查项 | 问题 |
|--------|------|
| 系统状态 | 用户是否清楚当前在哪、在做什么？ |
| 操作引导 | 用户是否知道下一步该做什么？ |
| 步骤必要性 | 这个步骤能否删除或合并？ |
| 容错机制 | 如果出错能否轻松恢复？ |
| 等待时间 | 是否有不可接受的延迟？ |
| 上下文连续 | 跳转后用户是否丢失了上下文？ |

按严重程度标注：
- 🔴 阻断性：用户无法继续
- 🟡 延迟性：需要额外时间或操作
- 🟠 困惑性：用户不确定下一步
- ⚪ 烦躁性：能完成但体验差

向用户展示摩擦点诊断结果。

**⏸️ 等待用户确认后继续。**

## Step 4: 断裂点与死胡同检查

检查所有流程中的断裂点和死胡同：

### 断裂点检查
- 是否有渠道切换点？（App 跳浏览器、线上跳线下）
- 切换时状态是否保持？
- 是否有角色切换点？（用户 → 管理员审批 → 用户）
- 切换时信息是否完整传递？

### 死胡同检查
- 是否有流程走到某个页面后无法继续也无法返回？
- 错误页面是否提供了有用的下一步指引？
- 空状态页面是否引导用户进入正常流程？

### 循环检查
- 是否有用户在两个页面/步骤之间反复跳转的情况？
- 是否有需要用户在外部获取信息再回来继续的情况？

## Step 5: 优化建议

基于摩擦点和断裂点诊断，输出优化建议：

```markdown
## 优化建议

### 🔴 必须修复（阻断性问题）
1. [问题描述] → [建议方案]

### 🟡 应该优化（延迟和困惑）
1. [问题描述] → [建议方案]

### ⚪ 可以改善（体验提升）
1. [问题描述] → [建议方案]
```

向用户逐一确认优化建议的优先级和可行性。

## Step 6: 保存产出

将用户流程分析产出保存到 `{工作目录}/flows/flow-{日期}.md`，包含：
- 核心任务清单
- 每个任务的流程映射（Happy Path + 替代路径 + 异常路径）
- 摩擦点诊断清单（按严重程度分级）
- 断裂点与死胡同清单
- 优化建议（按优先级排序）

## Step 7: 菜单

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：分析 [N] 个核心任务流程，发现 [R] 个阻断性问题、[Y] 个延迟/困惑问题、[W] 个体验改善点。[D] 个断裂点待修复。

- **进入交互审计（推荐）** — 基于启发式原则系统评估交互设计质量
- **补充更多流程** — 如果还有重要任务未覆盖
- **回到信息架构** — 如果流程分析发现了架构层面的问题

**⏸️ 停下来等待用户选择。不要自动执行。**

## 成功/失败指标

### ✅ 成功
- 核心任务被识别并由用户确认优先级
- 每个任务都映射了 Happy Path
- 决策点和替代路径被标注
- 异常路径和错误恢复被考虑
- 摩擦点按严重程度分级标注
- 断裂点和死胡同被检查
- 优化建议有优先级排序
- 所有产出向用户展示并获得确认
- 菜单展示后等待了用户输入

### ❌ 失败
- 没有识别核心任务就开始画流程图
- 只映射了 Happy Path 没有考虑替代和异常路径
- 摩擦点没有按严重程度分级
- 忽略了断裂点和死胡同检查
- 优化建议没有优先级排序
- 替用户决定流程而不是引导分析
- 没有等用户确认就进入下一步
- 流程映射中存在没有终点的路径

<IMPORTANT>
每条流程必须有明确终点，不允许死胡同存在。
摩擦点必须按严重程度分级标注（阻断/延迟/困惑/烦躁）。
Happy Path 必须先于替代路径和异常路径映射。
本技能完成后，展示菜单并等待用户选择下一步。不要自动执行后续技能。
</IMPORTANT>
