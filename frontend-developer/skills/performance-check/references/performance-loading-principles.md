# 性能原则：加载与 Web Vitals

---

## 1. Core Web Vitals 标准

| 指标 | 测量内容 | 良好 | 需改进 | 差 |
|------|---------|------|--------|---|
| **LCP** | 最大内容元素渲染时间 | <= 2.5s | 2.5-4.0s | > 4.0s |
| **INP** | 交互到下一帧绘制延迟 | <= 200ms | 200-500ms | > 500ms |
| **CLS** | 累积布局偏移 | <= 0.1 | 0.1-0.25 | > 0.25 |

- INP（已取代 FID）测量所有交互中最差一次的完整延迟（输入延迟 + 处理 + 呈现）
- 代码审查关注**代码模式**是否导致指标劣化，非实际测量值

---

## 2. 资源加载优先级

| 优先级 | 资源 | 策略 |
|--------|------|------|
| 最高 | 首屏 HTML、关键 CSS | 内联或最先加载 |
| 高 | 首屏 JS、LCP 图片 | preload |
| 中 | 非关键 CSS、次屏图片 | 异步加载 / lazy |
| 低 | 第三方脚本、分析 | defer / async / 动态注入 |
| 最低 | 预取下一页 | prefetch / preconnect |

---

## 3. JavaScript Bundle 优化

### 代码分割
- **路由级**：每个路由一个 chunk，按需加载
- **组件级**：大组件（模态框、图表、富文本编辑器）动态 import
- **库级**：大型第三方库独立 vendor chunk

### 大小警戒线

| 资源 | 建议（gzip） | 警戒线 |
|------|-------------|--------|
| 首屏 JS | < 150kB | > 200kB |
| 首屏 CSS | < 50kB | > 80kB |
| 单路由 chunk | < 100kB | > 150kB |
| 首屏单张图片 | < 200kB | > 500kB |

### 常见大依赖替换

| 大依赖 | 约大小 | 替代方案 | 约大小 |
|--------|--------|---------|--------|
| moment.js | 300kB | dayjs | 7kB |
| lodash | 70kB | lodash-es（按需） | 按需 |
| Chart.js | 200kB | lightweight-charts | 45kB |

---

## 4. 字体优化

- `font-display: swap`（或 `optional`）避免 FOIT
- 预加载关键字体：`<link rel="preload" as="font" crossorigin>`
- 中文字体子集化（> 5MB → 按需 < 500kB）
- 考虑系统字体栈减少下载

---

## 5. 性能预算

| 指标 | 预算 |
|------|------|
| TTI（3G） | < 3.8s |
| 首屏 JS | < 170kB gzip |
| 首屏 CSS | < 60kB gzip |
| 首屏图片 | < 500kB |
| LCP | < 2.5s (p75) |
| INP | < 200ms (p75) |
| CLS | < 0.1 (p75) |
