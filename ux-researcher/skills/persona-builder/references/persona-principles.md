# 用户画像构建原则

---

## 1. JTBD（Jobs-to-Be-Done）框架

### Job Statement 格式
> 当我 [情境/触发]，我想要 [动机/行动]，这样我就能 [期望结果/价值]

### 三层需求模型

| 层级 | 关键问题 | 关注点 |
|------|---------|--------|
| 功能需求 | "你用这个产品做什么？" | 任务步骤、频率、场景、工具链 |
| 情感需求 | "使用过程中你最在意什么感受？" | 想要：安全/掌控/愉悦；规避：焦虑/困惑/挫败 |
| 社会需求 | "使用产品如何影响别人对你的看法？" | 专业/效率/创新/可靠形象 |

### 雇佣/解雇分析

| 维度 | 关键问题 |
|------|---------|
| 雇佣触发 | 什么事件/痛点让用户开始寻找解决方案？ |
| 雇佣标准 | 用什么标准比较和选择方案？ |
| 习惯引力 | 什么让用户坚持现有方案（即使不满意）？ |
| 切换焦虑 | 对切换到新方案有什么担忧？ |
| 解雇动因 | 什么会导致用户放弃当前方案？ |
| 推力 vs 拉力 | 推力=现状痛点，拉力=新方案吸引力，两者都需足够强 |

## 2. 数据驱动画像 vs 传统画像

| 维度 | 传统画像 | 数据驱动画像 |
|------|---------|-------------|
| 基础 | 假设和直觉 | 研究数据和行为分析 |
| 核心 | 人口统计 + 虚构故事 | 行为模式 + JTBD |
| 命名 | 虚构人名（"小明"） | 行为标签（"效率型专家"） |
| 验证 | 很少验证 | 持续用数据验证和更新 |

### 反虚构协议
- 不编造人口统计细节——除非有数据支撑
- 不用刻板印象——不基于年龄/性别/地域做行为假设
- 不虚构故事——场景描述必须来自真实访谈或观察
- 标注数据来源：每条关键属性标注（访谈/测试/数据分析/假设）
- 标注置信度：高（多源验证）、中（单源数据）、低（假设，待验证）

## 3. 行为变量聚类（Alan Cooper 法）

1. 列出所有与产品使用相关的行为变量维度
2. 在每个维度上标记所有受访者/用户的位置
3. 寻找跨维度聚类——多个维度上位置一致的用户群
4. 聚类即画像的基础

### 聚类质量标准
- **内部一致性**：同一聚类中用户在关键变量上表现相似
- **外部区分度**：不同聚类在关键变量上有明显差异
- **实际意义**：聚类差异能转化为不同的设计决策
- **合理数量**：2-4 个主要画像

---

## 4. 画像验证

| 方法 | 说明 |
|------|------|
| 回溯验证 | 画像能否解释已收集的所有用户数据？ |
| 预测验证 | 画像能否预测新用户的行为模式？ |
| 团队验证 | 展示给客服/销售/运营，是否认出这些用户？ |
| 数据验证 | 行为特征是否与产品使用数据吻合？ |

---

## 5. 画像文档设计

### 信息层次
1. **一眼层**（3 秒）：画像名称、核心 Job Statement、一句话描述
2. **概要层**（30 秒）：JTBD 三层需求、关键行为特征、痛点和目标
3. **详细层**（3 分钟）：使用场景、雇佣/解雇分析、设计暗示

### 反模式
- **万能画像**：一个画像试图覆盖所有用户
- **人口统计堆砌**：不指向任何设计决策的属性罗列
- **愿望画像**：描述"我们希望的用户"而非"真实的用户"
- **一次性画像**：创建后从不更新
