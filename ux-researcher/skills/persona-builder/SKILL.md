# 用户画像构建

基于 JTBD 框架，引导用户把访谈洞察、测试发现和行为数据结构化为数据驱动的用户画像。

用户传入的参数：`$ARGUMENTS`

---

## 加载引用

使用 Read 工具加载以下引用文件，严格遵守其中所有规则：

- `references/persona-principles.md` — 画像原则（JTBD 框架、数据驱动画像、行为变量聚类、画像验证、反虚构协议）

读取画像模板：

- `assets/persona-template.md` — 用户画像输出模板

---

## 强制执行规则

- 🛑 **绝不** 在没有用户输入的情况下编造用户画像
- 📋 你是 **引导者（Facilitator）**，不是内容生成器
- ✅ 始终用中文与用户沟通
- 🎯 画像的每条属性必须有数据来源或用户确认
- 🚫 **绝不** 编造人口统计细节来"丰富"画像
- 🚫 **绝不** 用刻板印象填充画像
- 🔗 每个画像的核心是 JTBD——功能需求、情感需求、社会需求
- ⏸️ 展示菜单后 **停下来等用户输入**
- 💾 用户确认后才保存
- 🚫 不到用户确认，不进入下一步

加载以下上下文（如果存在）：

- Read `{研究目录}/tests/**` — 测试计划和发现
- 当前对话中已有的研究讨论

## Step 1: 盘点数据来源

引导用户盘点可用于构建画像的数据：

- **访谈数据**：访谈指南中的目标用户描述、已有的访谈记录/笔记
- **测试数据**：可用性测试中观察到的行为模式
- **定量数据**：用户分析数据、问卷调查结果（如有）
- **业务数据**：用户细分、使用频率、关键行为指标（如有）
- **团队认知**：产品/设计/客服团队对用户的已有理解

向用户展示数据盘点结果：
- "已有 [N] 类数据来源，覆盖 [行为/态度/定量] 维度"
- "缺少 [X] 维度的数据，建议 [补充方式]"

**⏸️ 等待用户确认后继续。**

## Step 2: 识别行为变量

基于可用数据，识别区分用户群体的关键行为变量：

引导用户讨论以下维度（非所有维度都适用，选择与产品最相关的）：

| 维度类别 | 示例变量 |
|---------|---------|
| 使用频率 | 日活 vs 月活 vs 偶尔使用 |
| 技能水平 | 新手 vs 进阶 vs 专家 |
| 目标导向 | 效率型 vs 探索型 vs 社交型 |
| 决策风格 | 快速决策 vs 深度研究 vs 依赖推荐 |
| 使用场景 | 移动端 vs 桌面端 / 通勤中 vs 办公室 vs 居家 |
| 价值敏感度 | 价格敏感 vs 品质优先 vs 便捷优先 |
| 协作模式 | 独立工作 vs 团队协作 / 发起者 vs 参与者 |

将用户在各行为变量上的分布可视化为连续谱：

```
使用频率：  |-日活---------月活---------偶尔-|
技能水平：  |-新手---------进阶---------专家-|
目标导向：  |-效率---------探索---------社交-|
```

**⏸️ 等待用户确认关键变量后继续。**

## Step 3: 用户聚类

基于行为变量的分布，引导用户识别自然聚类（即用户群体）：

- 在行为变量连续谱上，哪些位置出现了"聚堆"？
- 同一组用户是否在多个变量上表现一致？
- 不同聚类之间的差异是否足够大？
- 推荐 2-4 个主要画像（1 个主要画像 + 1-3 个次要画像）

对每个识别出的用户群体，整理初步标签：
- 群体名称（如"效率型专家用户"、"探索型新手"）
- 核心行为特征（2-3 条）
- 与其他群体的关键差异

**⏸️ 等待用户确认聚类结果后继续。**

## Step 4: JTBD 深度分析

对每个用户群体，使用 JTBD 框架深入分析：

#### 核心任务（Core Job）
- 用一句 Job Statement 描述："当我 [情境]，我想要 [动机]，这样我就能 [期望结果]"
- 这是用户"雇佣"产品的根本原因

#### 功能需求（Functional Jobs）
- 用户需要完成哪些实际任务？
- 这些任务的优先级和频率？

#### 情感需求（Emotional Jobs）
- 用户在使用过程中想要感受什么？（安全、掌控、愉悦、成就？）
- 用户想要避免什么感受？（焦虑、困惑、挫败、尴尬？）

#### 社会需求（Social Jobs）
- 用户希望别人怎么看待他们？
- 使用这个产品如何影响他们的社会形象？

#### 雇佣/解雇动因
- **雇佣触发**：什么事件让用户开始寻找解决方案？
- **雇佣标准**：用户用什么标准评估方案？
- **解雇动因**：什么会导致用户放弃当前方案？
- **迁移障碍**：什么阻碍了用户切换到新方案？

**每个画像的 JTBD 分析展示给用户确认后再继续。**

## Step 5: 构建画像文档

按已加载的 `assets/persona-template.md` 模板，为每个用户群体生成完整画像。

**关键原则**：
- 每条属性标注数据来源（访谈/测试/数据/假设）
- 标注为"假设"的属性需要后续验证
- 不编造具体的年龄、职业等人口统计信息——除非有数据支撑
- 画像名称用行为特征命名（"效率型专家"），不用虚构人名

向用户逐一展示每个画像，逐一确认。

## Step 6: 画像验证检查

对所有画像做验证检查：

| 检查项 | 结果 |
|--------|------|
| 每个画像有独立的核心 Job Statement？ | ✅/❌ |
| 画像之间的差异足够大？不是同一个人的变体？ | ✅/❌ |
| 每条关键属性有数据来源标注？ | ✅/❌ |
| JTBD 的功能/情感/社会三层都覆盖了？ | ✅/❌ |
| 画像能直接指导设计决策？ | ✅/❌ |
| 没有基于刻板印象的假设？ | ✅/❌ |

向用户报告验证结果。

## Step 7: 保存产出

使用 Write 将每个画像分别保存到 `{研究目录}/personas/persona-{画像简写}-{当前日期}.md`，每个文件按 `assets/persona-template.md` 模板结构输出。

保存后，**必须向用户展示文件的绝对路径**（使用 `$(pwd)` 拼接完整路径），以便用户直接点击打开文件。

## Step 8: 菜单

使用 `AskUserQuestion` 工具向用户展示以下选项（不要用文本菜单让用户输入序号）：

产出摘要：已构建 [N] 个用户画像。主要画像：[名称]。次要画像：[名称列表]。数据覆盖：行为 [✅/⚠️]，态度 [✅/⚠️]，定量 [✅/⚠️]。

- **整体回顾研究产出（推荐）** — 审视访谈指南 + 测试计划 + 画像的一致性
- **修改用户画像** — 调整某个画像的属性或 JTBD
- **回到访谈指南** — 补充针对画像的验证问题
- **导出为团队分享格式** — 生成简洁的画像摘要卡片

**⏸️ 停下来等待用户选择。不要自动执行。**

## 成功/失败指标

### ✅ 成功
- 数据来源盘点完整，明确标注了哪些维度有数据、哪些需要假设
- 行为变量基于产品实际场景选择，不是套用通用模板
- 用户聚类有清晰的行为差异支撑
- 每个画像有完整的 JTBD 分析（功能/情感/社会三层）
- 每条属性标注了数据来源
- 画像以行为特征命名，不以虚构人名命名
- 画像验证检查通过
- 产出逐个向用户展示并获得确认
- 画像能直接指向设计决策

### ❌ 失败
- 没有盘点数据来源就开始构建画像
- 编造人口统计细节来"丰富"画像
- 使用刻板印象（"95 后喜欢 XXX"）
- JTBD 分析缺少情感或社会层
- 属性没有数据来源标注
- 用虚构人名命名画像（"小明"、"Emily"）
- 多个画像之间差异不够大
- 没有做验证检查
- 替用户编造用户数据

<IMPORTANT>
画像每条关键属性必须标注数据来源（访谈/测试/数据/假设）。
绝不编造人口统计细节或用刻板印象填充画像。
JTBD 分析必须覆盖功能需求、情感需求、社会需求三层。
每个阶段完成后展示产出并等待用户确认，不自动推进。
本技能完成后，展示菜单并等待用户选择下一步，不自动执行后续技能。
</IMPORTANT>
