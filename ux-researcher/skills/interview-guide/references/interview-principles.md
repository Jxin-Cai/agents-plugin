# 用户访谈原则

本文档定义了用户访谈指南设计阶段必须遵循的原则。

---

## 1. 漏斗式提问结构（Funnel Approach）

访谈问题从宏观到微观，逐步收窄：

### 开放探索层
- 以最宽泛的问题开始："跟我说说你平时怎么 [做某件事]"
- 目的是让参与者进入叙事模式，减少紧张感
- 不预设任何方向，让参与者自然展开

### 聚焦深挖层
- 根据参与者的回答，选择最有价值的线索深入
- 使用"你刚才提到了 X，能多说一些吗？"
- 目的是把模糊的描述转化为具体的细节

### 具体验证层
- 在最窄的层面确认关键发现
- 使用"如果我理解对的话，你的意思是 X？"
- 目的是确保理解准确，避免研究者的主观解读

**检验方法**：如果你的第一个问题就很具体，说明你跳过了漏斗的上层。返回去加一个更宽的入口问题。

---

## 2. 开放式问题设计

### 好问题的特征
- 以"如何"、"为什么"、"跟我说说"、"描述一下"开头
- 邀请参与者讲述故事和经历，而非给出评价
- 不暗示任何"正确答案"

### 问题类型库

| 类型 | 模板 | 适用场景 |
|------|------|---------|
| 行为回忆 | "上一次你 [做某事] 是什么时候？带我走一遍那个过程" | 了解真实行为 |
| 对比探索 | "你之前用的是什么方案？和现在的方案比起来怎么样？" | 理解迁移动因 |
| 困难发现 | "在 [某个场景] 中，最让你头疼的是什么？" | 定位痛点 |
| 期望探索 | "如果有一个魔法棒能改变 [某件事]，你会改变什么？" | 发现未满足需求 |
| 情境重现 | "带我回到那个场景——当时你在哪里？在做什么？" | 还原使用上下文 |
| 关键事件 | "能不能说一次让你印象特别深的 [好/坏] 经历？" | 关键事件法（CIT） |
| JTBD 触发 | "你第一次决定使用 [产品/方案] 的时候，是什么情况触发的？" | 发现雇佣动因 |

### 必须避免的问题

| 错误类型 | 示例 | 修正 |
|---------|------|------|
| 引导性 | "你不觉得这个设计很复杂吗？" | "你对这个设计有什么感受？" |
| 封闭式 | "你喜欢这个功能吗？" | "你平时怎么使用这个功能？" |
| 双筒式 | "你觉得它好用吗？用的时候开心吗？" | 拆成两个独立问题 |
| 假设性 | "如果有 X 功能你会用吗？" | "跟我说说你现在怎么解决 X 问题的？" |
| 术语化 | "你对 UI 的信息架构怎么看？" | "你找某个功能的时候容易吗？" |

## 3. 追问技巧（Probing Techniques）

### 五种追问类型

1. **回声追问（Echo Probe）** — 重复参与者的关键词："你说'很困难'——能说说具体难在哪？"
2. **沉默追问（Silent Probe）** — 保持沉默 5 秒，用眼神和点头鼓励参与者继续
3. **深挖追问（Depth Probe）** — "能多说一些吗？"、"然后呢？"、"你当时是怎么想的？"
4. **澄清追问（Clarification Probe）** — "你说的 X 具体是指什么？"、"能给我举个例子吗？"
5. **对比追问（Contrast Probe）** — "这和之前的体验有什么不同？"、"如果换一种方式呢？"

### 追问时机
- 参与者用了抽象描述："还不错" → 追问具体好在哪里
- 参与者跳过了细节：直接说结果 → 追问过程
- 参与者表达了情绪：叹气、犹豫、兴奋 → 追问当时感受
- 参与者提到了意外行为：变通方案、放弃某个步骤 → 追问原因

## 4. 认知偏误规避

在访谈设计和执行中必须警惕的偏误：

| 偏误 | 表现 | 对策 |
|------|------|------|
| 社会期望偏差 | 参与者说他们"应该做"的而非实际做的 | 问行为而非态度；用"上一次"代替"通常" |
| 确认偏误 | 研究者只关注支持假设的证据 | 主动寻找反例；让另一人独立分析 |
| 锚定效应 | 早期发现过度影响后续解读 | 延迟形成结论；多人独立编码 |
| 回忆偏差 | 参与者的记忆不准确 | 聚焦最近一次经历；请参与者边操作边说 |
| 峰终定律 | 参与者只记得高峰和结尾体验 | 引导回忆完整流程，不只问"印象最深的" |
| 霍桑效应 | 被观察时行为改变 | 暖场充分、语气自然、避免评判感 |

## 5. 知情同意与伦理规范

### 必须包含的知情同意要素
- 研究目的简述（不透露具体假设）
- 参与者权利：随时退出、拒绝回答任何问题
- 数据使用：如何存储、谁能访问、是否匿名
- 录音/录像权限：明确征求同意
- 预计时长
- 是否有报酬/礼品

### 伦理红线
- 不对参与者施加完成任务的压力
- 不在参与者明显不适时继续追问
- 不使用欺骗性的研究说明
- 未成年参与者必须获得监护人同意
- 涉及敏感话题（健康、财务、隐私）时提前预警

---

## 6. 访谈数据质量控制

### 访谈前
- Pilot Test：正式访谈前至少进行 1 次试访谈
- 问题审查：确保没有引导性、封闭式、双筒式问题
- 技术检查：录音设备、网络连接、备用方案

### 访谈中
- 实时标记关键发现和情绪信号
- 记录参与者的原话（Verbatim），不要用自己的话替代
- 观察非语言线索：停顿、语速变化、肢体语言

### 访谈后
- 24 小时内完成访谈备忘录
- 标记需要在后续访谈中验证的发现
- 更新研究假设和问题优先级
