# 可用性测试原则

---

## 1. Think Aloud 协议

### 并发式（CTA）
- 参与者操作时同步说出想法
- 优势：实时获取认知过程；劣势：可能影响任务速度
- 适用：探索性测试、早期原型评估

### 回顾式（RTA）
- 参与者先完成任务，再回看录像解说
- 优势：度量数据更准确；劣势：事后回忆可能不准确
- 适用：需要精确度量的评估测试、A/B 对比

### 主持人行为准则
- 中性提示："你在想什么？"而非"你是不是觉得这里很难？"
- 不干预、不解释界面设计意图
- 计时记录每个任务的开始/结束/关键转折点
- 标记情绪信号：犹豫、困惑、沮丧、惊喜

## 2. 任务设计原则

### 场景化任务
- 好："你朋友下周过生日，你想在这个网站上挑一份 200 元左右的礼物"
- 坏："请使用搜索功能查找商品，并添加到购物车"

### 避免任务偏差

| 偏差类型 | 修正方向 |
|---------|---------|
| 路径暗示 | 只给目标，不指定操作路径 |
| 术语泄露 | 用日常语言替代界面术语 |
| 难度暗示 | 直接给场景，不预判难度 |
| 顺序暗示 | 只给目标，让参与者自己决定路径 |

### 任务递进
1. **热身任务**：简单、建立信心
2. **核心任务**：直接关联测试目标（2-4 个）
3. **挑战任务**：测试容错性和恢复能力（1-2 个）
4. **探索任务**：开放式，观察自由探索行为

推荐 4-6 个核心任务/场次，单场不超过 60 分钟，每任务 3-8 分钟。

## 3. 度量体系

### 效能（Effectiveness）

| 指标 | 计算方式 |
|------|---------|
| 任务完成率 | 成功人数 / 总人数 x 100% |
| 首次完成率 | 不需要帮助即完成 / 总人数 x 100% |
| 错误率 | 总错误数 / 总人数 |

### 效率（Efficiency）

| 指标 | 计算方式 |
|------|---------|
| 任务完成时间 | 中位数（非平均值） |
| 最优路径偏差 | 实际步骤 / 最优步骤 |
| 求助频率 | 总求助次数 / 总人数 |

### 满意度（Satisfaction）

| 量表 | 适用场景 |
|------|---------|
| SUS | 整体可用性评估（10 题，68+ 为尚可） |
| SEQ | 单任务难度评估（7 分制，每任务后收集） |
| NPS | 推荐意愿 |
| UMUX-LITE | 快速评估（2 题） |

---

## 4. 可用性问题分级（Nielsen）

| 等级 | 名称 | 行动 |
|------|------|------|
| 4 | 灾难性 | 必须发布前修复，阻断任务 |
| 3 | 重大 | 高优先级修复 |
| 2 | 轻微 | 中优先级 |
| 1 | 装饰性 | 低优先级 |

### 问题可信度
- 单人出现：谨慎对待，可能是个体差异
- 2-3 人出现：可能是真实问题，需更多验证
- 4+ 人出现：高置信度，应当修复

---

## 5. 参与者与样本量

- Nielsen 5 用户原则：5 人可发现约 85% 可用性问题
- 多用户群时每群至少 3-5 人
- 排除条件：同行从业者、近期参加过类似测试、与团队有利益关系
